# ICND2260 选型测算 (2026-07-10, 与用户逐步推演定稿)

文档 = `D:\claude_workspace\pov3d\models\ICND2260_编程指导_CN_2025_V2.8_深圳映己鸿鹄科技有限公司专用.pdf` (31页, 映己鸿鹄专用版=有FAE渠道)。已有方案对照: [[project_pov3d_led_chip_decision]] (2026-05-12 MBI5264 90颗/101 IO/7.2kHz) 和 2049 现役路线。

## 芯片本质
共阴**行列合一** PWM 引擎芯片 (ICN2153/MBI5759 族), BGA225: 单颗 40列×48行=1920px, **48 行管 NMOS 片内集成** (免 3019/免地址线), 120 恒流通道, 16-bit PWM, GCLK 内部 PLL 自生成 ≤600MHz。数据口: TTL 1/2/3/6通道 (DCLK≤25MHz 双沿=50Mbps/lane) / m-LVDS 1/2/3通道 (≤170MHz 双沿=340Mbps/lane, **multipoint 总线可多负载**)。扫描数可编程 (≤48)。VSYNC=指令 (TTL) 或 I_SYNC 跳变 (mLVDS); 显示数据可按行分段发。

## 🔴 核心限制: 传输位宽固定 16-bit/像素
VHEAD[23:20] 全文只定义 0x3=16位; "显示数据每通道16-bit" 明文。**灰度等级可调只影响引擎端显示, 链路带宽不随色深缩放** → 6-bit 换帧率不通 (PWM 引擎税)。"视觉刷新率=刷新分组×帧频(≤512组)" 是同帧数据复扫, 对 POV 无意义 — POV 要的是新数据帧率。

## 帧率公式 (3通道 mLVDS 每 lane 背一色, 色数/lane数抵消)
- per-lane bits/帧 = 像素数×16bit; fps = 340M / per-lane bits
- 48扫满配 1920px: 30720bit → 理论 11.07k
- **45扫 1800px: 28800bit → 理论 11.81k, 扣 VHEAD+CHECKSUM+RSYNC/Config 开销 ≈ 11.2k 实际**
- TTL 6通道单颗仅 3.2k (15360bit/50Mbps=307µs) → 高帧率必须 mLVDS
- 级联砍半: 2颗/链=5.9k, 高帧率下必须**一链一颗**

## 需求测算 (屏 150×168.75mm = 160×180 @P0.9375)
- 切片数: N ≥ π×D/pitch = **π×160 = 503** → 取 512 (2⁹, 外圈 0.920mm) 或 540 (1.5×360, 0.873mm)
- 🔴 单面屏闪烁 = 转速 (每转两次点亮朝向相反, 单观察者只见一次) → 单面 24Hz 需 24rps → 512×24≈12.3k **超单链能力, 出局**
- ✅ **正反屏**: 每次点亮双向可见 → 每转 2 闪 2 体 → **30体/s = 15rps**; 需求 = 512×15 = **7.68k** (540→8.1k) vs 能力 11.2k = **余量 46%/38%**
- 灰度白送: 130µs帧/45扫×600MHz ≈ 1700 GCLK/行 → **~10.8 bit**

## 排布 + IO 账 (🔴 2026-07-10 当轮修正: 正反必须独立数据)
- 180行/48=3.75 除不尽 → **45扫×4排**; 16颗/面 (4×4), 双面 32 颗
- 🔴 **共享总线镜像同数据方案被屏厚推翻 (用户指出)**: 正反发光面间距 t≈4mm → 两面实际在 θ±δ(r), δ=arctan(t/2r) 随半径变 (外圈~2片, r=20mm~8片), 同数据=全屏 t≈4px 双影且无法统一平移修 → **两面必须各自按 LED 真实 3D 位置采样的数据** (渲染器按"每颗 LED 每快门时刻的真实空间位置"采样, 厚度/镜像/装配偏差全在数据侧吸收, RTL 零成本)
- **方案 A (主)**: 32 链独立 (每面16链, 一链一颗) → 11.2k vs 7.68k 余量46%, 30体/s 全额; PL IO = 96 数据 + 时钟/杂 ≈ **~105 (单端经 m-LVDS 驱动器, 驱动器为必须)**; 差分直驱 ~200 pin 不可行
- **方案 B (降级档)**: 16 链共享级联=2 编址双内容 → 5.9k → 11.5rps = 23体/s, ~56 PL IO
- A 的 105 IO ≈ MBI5264 方案 101, 但 32 颗 vs 90 颗 / 免 12 颗行驱 / 10.8bit vs 8bit / 免 DCLK 超频赌局

## 构造账: LED/驱动不能分板, 用三明治双板 (2026-07-10 补)
- 🔴 LED 板与驱动板分离用连接器 = **天文数字不可行**: 行列合一每颗 165 根矩阵线 (120 阳极+45 阴极行, 行列均不可跨芯片共享), 16颗×2面 = **5280 根**, 且是几十 mA×7.7kHz×45扫 动态电流, 过连接器电感直接毁波形
- ✅ **三明治双板**: 每面 = 完整标准 LED 板 (灯正面 + 16颗2260贴背面 + 过孔互连, 即现有 COB 屏工艺的单面版), 两板背靠背, 芯片藏夹层。每板对外只引 ~100 信号 (16链×3对+时钟/同步) + 电源 = J12 50pin ×2 量级
- 代价: 总厚 ~8-10mm → 外圈 δ≈5片 (独立数据渲染精确吸收, 非新问题); 夹层散热靠桨叶风冷+过孔到灯面铜皮; 双板对称利于动平衡
- 厚度的**真实**光学代价 (独立数据修正后): 仅剩 ①轴心死柱 r<t/2≈5voxel (LED 实扫半径=√(r²+(t/2)²), 落在本就差的近轴区) ②桨叶遮挡略增 ③气动阻力/电机功率。"厚=双影"的直觉在独立数据决策后不成立
- 减薄手段: 两板内侧芯片**错位嵌套** (A板芯片区对B板空区) + 1.0mm 薄板 + 低剖面封装 → ~5-6mm; 可问 FAE 有无薄封装版本
- "无芯片薄刃"不存在: 28800px 矩阵任何路线芯片都必须贴灯背 (2049 路线 108+24 颗更厚), 芯片数最少的恰是行列合一

## 结论 + 遗留
**正反屏(独立数据) + 512片 + 15rps + 方案A 前提下 2260 = 最优候选**: 一链一颗/46%余量/10.8bit灰度/免行驱/开短路检测+校正白送。要冲 >10k fps 仍只能回 2047/2049 族 BCM 自扫路线。
遗留 FAE 三问: ①VSYNC 7.7kHz 工况 (家族按视频帧率设计, 超常规必须样片实测) ②VHEAD[23:20] 有无 8-bit 像素模式 (4-bit 枚举字段只公布一个值, 若有则帧率×2, B 方案也能回满血) ③多点/级联编址在一链两颗下的配置方式 (SEL_I/DEVICE)。其他: 15rps 电机 (现4.5) / 170MHz×32链 转子板 SI 归 [[project_pov3d_rotor_chip_arch]] 新板
