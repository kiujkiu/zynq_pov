实验 ⑤：PLL refclk 能不能吃 400 MHz（🔴 唯一还能推翻引脚定案的未知数）

为什么必须验：上行转发时钟 2026-09-07 定案走 PLL（方案 A）—— DR1 发 400 MHz 半速时钟 → REFCLK_DIV=4 → PFD 100 → VCO 800 → sclk 400 / pclk 200。 但 EG_PHY_PLL 的 refclk 输入脚能不能吃 400 MHz，手册与原语里都查不到出处 （只有 VCO 300~1200、fOUT ≤ 400，没有输入脚范围；FIN 在 eagle_macro.v 里 只是个没被模型用到的注解字符串）。这条不结，PCB 上转发时钟対怎么走就是悬的。

✅ 结论：E104 做得了，而且不用改板 —— 只在 J4 排针上飞一根短线。

为什么不用改板

  • PLL 的专用时钟脚在 E104 上引出来了：BE19(A14/B14) = GPLL0_CLKIN、 BE20(D11/D12) = GPLL0_OUT，都在 J4、都在 bank0。 这是专用 PLL 时钟输入脚，比 GCLKIOL 更直接（后者是否能进 PLL refclk 无需再问）。
  • SDRAM 占的是 bank0 的 GCLKIOB（BE9~BE12），不是 BE19/BE20 —— 这两対没被占。
  • 全程不动 VCCIO1：实验只用 bank0（焊死 3.3V）。⇒ 绕开 「改 VCCIO1 到 2.5V 可能让 JTAG 下不进去」那条 X20 独有的风险。
  • 管脚分配图确认 B14/A14 与 D11/D12 在 J4 上相邻 ⇒ 飞线只有几毫米， 400 MHz 的信号完整性压力很小。

怎么接（一対飞线，不是一根）

板载晶振 = 50 MHz，在球 H3（原理图网名 H3_50MHz_CLK）。50 恰好在 FIN 查找表 {25,50,100} 内，不用放宽任何断言。

🔴 发送侧必须走 bank1 的真差分対、用 LVDS33，不能单端也不能用仿真対：

  • 仿真対（BE*）输出上限只有 166 MHz（DS300 表 3-2-5 只给了 LVDS25E 一行， 166 MHz），单端 LVCMOS33 更低 ⇒ 400 MHz 出不来。
  • LVDS33 真差分输入输出都是 400 MHz / 800 Mbps（DS300 表 3-2-5）⇒ 够用。
  • 接收侧反而没问题：BE19 虽是仿真対，但 DS300 明写 「真/仿真対均可作 LVDS25 标准输入，最大 400 MHz」——"仿真"只在发送侧有意义。
H3 (50 MHz 板载晶振)
  └─> PLL_A:  FIN=50  REFCLK_DIV=1  FBCLK_DIV=8  CLKC0_DIV=2  => VCO 800, C0 = 400 MHz
        └─> ODDR (d1=1,d0=0) ─> bank1 一対真差分, IOSTANDARD = LVDS33
              例: B15/B16 = L2P_1 / L2N_1   (⚠ 是**一対差分**, 不是两个单端脚)
              └── 飞线一対 (短、等长、带一根地回来) ──> A14/B14 = BE19N/BE19P = GPLL0_CLKIN
                    └─> PLL0:  refclk = 400 MHz, REFCLK_DIV=4 => PFD 100
                               FBCLK_DIV=4, CLKC0_DIV=2 => VCO 800 => C0 400 / C1 200

⚠ 别用 D11/D12 当发送脚：BE20 = GPLL0_OUT 是 PLL0 的专用输出， 而本实验正用 PLL0 当接收端，可能冲突。

🔴 实验 ⑤ 与「四対全仿真驱 2260」不能同时接。 BE19/BE20 在接线方案第 3 节里是候选数据対 D2；实验 ⑤ 把 BE19 占去当 PLL 输入 ⇒ 两个实验要分开做，别以为能一次接完。 要同时做的话，D2 退回用 bank2 的 TE8(J4.3/4)。

判据

  1. PLL0.extlock 拉高 —— 这就是「400 MHz 进得了 refclk」的直接答案。
  2. PLL0 的输出频率对得上：C0 应为 400 MHz、C1 应为 200 MHz。 只看 extlock 不够 —— 锁在错误的分频比上 extlock 照样会高，必须独立测频。两种做法：
    • 示波器法：把 C1(200 MHz) 用一个 ÷N 计数器降到 1~10 MHz， 从 bank1 一対 LVDS33 出去量。别直接量 400 MHz，探头和飞线会骗你。
    • 数秒法（不用示波器，更硬）：用 H3 的 50 MHz 做基准数 1 秒（50,000,000 拍）， 同一秒内数 C1 的边沿数，读数应为 200,000,000 ± 少量。 结果用 LED 二进制点出来或走 UART。这个法子不依赖任何量具的带宽。
  3. 失败的话记下失败方式：完全不锁 / 锁了但频率不对 / 锁了但抖动大。 三种对应的退路不同。

② 下载步骤（下 SRAM，掉电丢失）

板上的硬件事实（用户手册 rev1.0 §4.7 + 原理图第 6 页）：JTAG 口位号 J2， 10 针 2.54 mm DC3 带防呆缺口公座，板面丝印写着 JTAG，在 SDRAM 右边、KEY 按键上方。 脚位：1=TCK · 2=GND · 3=TDO · 4=VCC(3.3 V) · 5=TMS · 6/7/8=NC · 9=TDI · 10=GND（四根信号各串 33 Ω）。 FPGA 侧 TCK=C14 · TDO=E14 · TMS=A15 · TDI=C12，是专用脚，不占 J3/J4 任何资源。

没有跳线、没有拨码。 配置模式由 MSEL0/MSEL1(球 T11 / N11) 上的 0402 电阻决定， 出厂默认 MSPI；手册原话「如需改 Slave Serial 下载需要改变启动模式，在 pcb 上替换一颗 0402 电阻即可」。 本实验用 JTAG 下 SRAM，与 MSEL 无关，一个电阻都不用动。

lock 高，但 c1_div ≠ 195.3 kHz 锁在错误的分频比上（extlock 高不代表频率对） 先查 FEEDBK_PATH：CLKC0_EXT ⇒ VCO = PFD × FBCLK_DIV × CLKC0_DIV（反馈取自 C0 分频之后）。 把实测频率 ÷ 195.3 kHz 得到的倍数反推是哪一级配错——比如读到 390.6 kHz（2×）就是把反馈点看成了 C0 分频之前。 这条 09-07 看错过一次。
lock 高、c1_div=195.3 kHz，但 ok 低 频率落在 ±0.1% 外，或者窗口在 PLL 锁上之前就跑完了 先重测：把 J4.43 短一下 GND 再松开（数秒法是一次性的，飞线后接会必然导致 ok=0）。 重测仍低 ⇒ 是精度/抖动问题，不是「能不能吃 400」的问题—— 用 TD IP Generator 按 FIN=100 / VCO=800 重生成环路参数 （GMC_GAIN / ICP_CURRENT / KVCO / LPF_CAPACITOR / LPF_RESISTOR 现在是照抄厂家实例的）。
c0_div 不对，但 c1_div 对 不是 PLL 的问题 —— 是这一版 bit 的已知缺陷 见上面的构建复核：d_c0 那个 400 MHz 计数器 setup 差 0.635 ns。忽略 c0_div，按 c1_div + ok 判。
五个探针脚全都不动，一点输出都没有 多半根本没配置成功 按怀疑度排：① bit 没下进去（TD 有没有真弹成功？重下一次）； ② 板子没上电 / POWER 灯不亮； ③ 量错排——J4 的偶数排是 P、奇数排是 N，探针 lock/ok 在偶数排，c0_div/ref_div 在奇数排； ④ 地没共（万用表的黑表笔必须在 J4.41/42 这类 GND 脚上，不是浮空）。 注意：飞线接反或没接，只会让 lock/c0_div/c1_div/ok 死，ref_div 照样有 48.83 kHz—— 所以「全都不动」一定不是飞线的锅。

失败了怎么办（退路已经准备好）

让 DR1 改发 200 MHz（uplink_tx_frame.v 的 fwd_clk 由 4'b0101 改 4'b0011），桥片侧只需把 UL_FWD_MHZ 改 200 ⇒ REFCLK_DIV 自动变 2，其余参数一个字不动。 这条退路只改一行，代价是转发时钟対上的边沿率减半（对 SI 反而更好）， 但转发时钟不再是标准半速时钟，需要 C 同步改注释。
