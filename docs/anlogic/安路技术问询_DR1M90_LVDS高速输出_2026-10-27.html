一、设计接法

  • 时钟：板载 25 MHz 晶振 → DR1_PHY_PLL。REFCLK_DIV = 1，FBCLK_DIV = SCLK/25，CLKC0 外反馈（FBKCLK = "CLKC0_EXT"），CLKC0_DIV 取"VCO ≤ 2000 MHz 的最大整数"，CLKC0_CPHASE = DIV−1（0°），CLKC0_DUTY50 = "ENABLE"，CLKC0_DUTY_INT：最初写成 DIV/2（奇数分频时错误，现已改为 INT(DIV/2)+1，见第三节）。 PLL 的 clkc[0] 直接作为 ODDRx2 的 sclk；pclk 由 DR1_PHY_LCLK #(.DIV("2"), .LCLK("DIV2TO8")) 对 sclk 二分频得到。
  • 串化：每 lane 一个 DR1_LOGIC_ODDRx2 #(.ASYNCRST("ENABLE"))，q 直连顶层 LVDS25 端口，不经 OBUFDIFF。共 13 条数据 lane，外加 1 条随路时钟（线速/8，同样由 ODDRx2 产生）。
  • I/O：bank 11（bank 33 上也试过），IOSTANDARD = LVDS25，VCCIO = 2.5 V，1.0 / 1.2 Gbps 档开了 bank 级预加重（PRE_EMP=ON，.bit 与不开相差 63 字节，确认生效）；未用 ODELAY；引脚级 VOD 设置无效（见 Q6）。
  • 与官方 IP 的对比：TD 自带的 DR1 High Speed IO IP（ip/depot/HSIOF9F0D0P0_1.0/DR1_High_Speed_IO/RTL/DR1_High_Speed_IO.v，5.9.1 和 2026.1 两个版本相同）也是 assign sclk = clk_in;，pclk 用 DR1_PHY_LCLK（DIV2TO8，DIV 2）产生，和我们的接法同构。
  • 时序：TD 报告 0 违例。pclk 域额外加了 0.25 ns 的 setup 不确定度。

二、实测结果（10-27，面 A，接收端 GW5A）

判据（更正）：桥 sbd 0x60 低 13 位 = 1fff（全锁）；0x61 高 16 位（掉锁次数）不增长；每 lane 误码计数 0x63..0x6F 全为 0（计数约等于 3 × 真实误码数）；0x62（已校验量）在增长。此前用 0x61 当误码计数是错误的。

1.2 Gbps 失败的定位：tp 图样同样失败，说明不是切片或软件；桥按 160 MHz 过约束重编（pclk 余量 0.25% → +0.42 ns）后仍同样失败，桥时序基本排除；判为码型相关码间串扰（长串 0 + 孤立 1 在 0.83 ns UI 下来不及翻转）。链路：DR1 → 核心板 → 板间连接器 → V1 底板 → FPC → 桥转接板 → GW5A。扫眼眼宽：600M 为 0x54–0x5c，1.0G 为 0x30–0x38，1.2G 为 0x24–0x2c。DS1200 表 3-22 LVDS25 输出上限 1250 Mbps，1.2 Gbps 已用到 96%。

VOD：引脚级 VOD = 350M 编出的位流与不加时逐字节相同，TD 静默忽略、无告警；VOD = 400M 则报 USR-8059（只认 200M / 250M / 300M / 350M）。预加重生效。详见 Q6。

核心板面 A 的串阻 R201–R208 已换成 0 Ω，可排除串阻；码间串扰应来自连接器、FPC、转接板走线一侧，预加重是必需措施。自研核心板 LVDS 线不放串阻，且 LVDS 发送 bank 要能开预加重。预加重开关出处：TD arch/dr1_macro.v 的 DR1_PHY_HR_BANKREF、UG1210 表 1-1。

三、根因（已自行解决）

  • 原因：奇数 PLL 输出分频时，CLKC0_DUTY_INT 应按 UG1206 §2.5.4 公式 2-5 取 INT(DIV/2)+1，我们写成了 DIV/2。失败的 700 / 750 / 800 Mbps 三档都是 DIV 5，DUTY_INT 填了 2，应为 3。
  • 验证：全仓代码改正后，800 Mbps 奇数分频（DIV 5、DUTY_INT 3）2 分钟全锁，偶数分频 800 Mbps 同样全锁（误码未按 lane 计数复核）。
  • TD 的表现：TD 对错误配置没有警告，静态时序仍按 50% 占空比推导，报告 0 违例。这一点见 Q1。
  • 1.2 Gbps：根因与占空比无关。开预加重后 PRBS7 近乎干净，但 PRBS31 与真内容仍大量误码，判为码型相关码间串扰，预加重不足以消除（第二节）。
