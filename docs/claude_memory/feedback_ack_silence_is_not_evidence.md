# ACK 静默证明不了任何事 (2026-09-01)

从 2026-08-19 起, "LED2 亮不亮 / `ack_ok_sticky` 置没置位"一直被当成比"屏亮不亮"更硬的判据。
2026-09-01 两条发现把它整个推翻。

## ① 手册明写 ACK 菊花链是**可选**的

编程指导 P6 引脚表 `ACK_I`(N12) 原文:

> 「数据回传输入。**如需回传功能**, 级联情况下需接入下一颗芯片的 ACK_O, 最后一颗 ACK_I 可浮空。」

`ACK_O`(B4) 是纯输出(类型 O, 电平 VDDD/GND, **推挽不是开漏**), 第一颗的 ACK_O 汇总全部回传。
⇒ 灯板是**供应商的客户样板**, 他们自己点亮时用不用回读是他们的事。
**如果 9 颗的 ACK_I↔ACK_O 没串起来、或第一颗的 ACK_O 没引到 J1.22, 这根线永远不会有信号。**

所有既有证据都与"这根线压根没接"相容: ACK 一直高阻、被邻线 I_SYNC 拽着走(错误率 ≈ 帧率的一半);
2026-09-01 重焊接插件后读数一个字没变(**没接的线, 焊得再好也不会变**)。

## ② 读出通路自身有一个未定位的缺陷

2026-09-01 扫 dev 0..8 时冒出"回包", 两次跑落在**完全不同的设备号**上 ⇒ 不可复现。
它同时违反四条可证伪判据, 每条单独就够判死:

1. 回包 **8,300/秒**, 而提问上界只有 `fps/16 = 10/秒` —— 超 830 倍
2. `ack_frame_cnt` 与 `ack_err_cnt` 的增量**每一行都相同** —— 两者由互斥条件驱动(`crc_ok_pulse`
   vs `frame_err`), 不可能同步增长
3. `ack_f_nbits` 每出现一行正好 +1(263→264→265→267→268), **跨 soft_rst 还接着数** ⇒ 是计数器不是数据
4. `ack_ok_sticky` 从 1 变回 0 —— 粘滞位没复位掉不下来

**根因至今未找到。** 在找到之前 ACK 的任何数字都不作判据。

## How to apply

- **判据只剩屏**: 首光阶段一切实验的判据是"屏上有没有光", 不是 ACK 计数。
- 给供应商的问题清单里加一条、排前面: **"这块样板上 ACK 菊花链接了没有? 第一颗的 ACK_O
  有没有引到 J1.22?"** 一句话就能问掉, 而它决定我们过去两周的核心判据成不成立。
- 解调器 `icnd2260_ack_rx.v` 的 `A_IDLE`/`A_START` **都没有超时**(:134-153) ⇒ 线被焊到 GND
  或焊到电源, 都给出 `ack_err=0` + `ack_cnt=0`, 与"芯片推挽驱动着空闲高"**逐位相同**。
  **所以 `ack_err` 塌到 0 不能读作"通了"。**
- 想判断"屏侧到底有没有源驱动 ACK", 唯一干净的办法是万用表: `soft_rst` 在 1/0 两态各量一次
  J1.22 对地直流, **两态读数相同 ⇒ 线上唯一的源是 FPGA 片内上拉**(xdc `PULLUP TRUE`)。
  这个判据与推挽/开漏无关, 不需要任何拓扑假设。
- ⚠ 片内上拉方向是反的: 上拉把"没连"伪造成"健康空闲高"。要验通断应该用 **PULLDOWN**
  (读到高 ⇒ 只可能是屏侧在驱动)。

**Why**: 2026-08-20 已经踩过一次同类(悬空 ACK 放大噪声出 18k 假帧, 差点误判成"找到 7 颗芯片"),
当时的结论是"加上拉+CRC 闸就可信了"。**2026-09-01 证明那个结论下早了。**

相关: [[project_lxb_icnd2260_bringup]] [[feedback_icnd2260_chksum_lfsr_is_reflected]]

## 2026-09-10 追加: **回读是菊花链 ⇒ "第 k 颗没答" 有两个完全不同的解**

手册引脚表原文 (转引自 `zynq_pov/docs/灯板改板_邮票孔FPGA接口_2026-09-09.html`):
> `ACK_I`「数据回传输入。如需回传功能, **级联情况下需接入下一颗芯片的 `ACK_O`**, 最后一颗 ACK_I 可浮空」
> `ACK_O`「数据回传输出。…接入上一颗芯片的 `ACK_I`, **第一颗 ACK_O 输出所有芯片回传数据**」

⇒ 第 k 颗的回包必须**穿过第 k−1 … 第 0 颗**才能到 FPGA。**FPGA 只连着链头那一根线。**

于是"点名第 k 颗, 线上一点动静都没有"至少有两个解:
1. 第 k 颗**根本没收到配置** (正向数据链断在它前面);
2. 第 k 颗**收到了也答了**, 但**回传中继**断在中间某一颗 —— 而那一颗自己的回包**照样能回来**
   (它只需要自己的 `ACK_O`, 不需要转发别人的 `ACK_I`)。

🔴 **这两个解在链头那根线上长得一模一样**, 加多少"零协议假设"的活动检测都分不开 ——
因为**观测点只有一个, 而且在链的最外端**。半死不活的那一颗恰好同时是
"最后一个还活着的" 和 "要替后面所有颗转发的", 这两个身份重合时最容易误判。

**How to apply**:
1. 单观测点 + 中继链 ⇒ **"没听到" 只能推出 "这条链路上某处断了", 推不出 "源头没发生"**。
   写结论时必须把两个解都列出来, 不能只写更顺手的那个。
2. 要分开, 必须**改变拓扑**而不是加仪器: 缩短级联 (`CASCADE=k`) 逐个试、或把可疑那颗跳过/换位。
3. 反过来: 若能看到**编号大于断点**的回包, 那才是"中继是通的"的正证据 —— 所以要读的是
   **回包自己声称的编号** (帧里的 DEV 字段), 而不是"我们当时在点名谁"的本地计数器。
   这两个位图必须分开出脚, 一旦不重合, 先信帧里的那个。

## 🔴 2026-09-10 自我更正: 上面那句"必须改变拓扑而不是加仪器"**太强了**

原文 How to apply 第 2 条写的是「要分开, 必须**改变拓扑**而不是加仪器」。
**这句话只对"在链头再加一个观测点"成立**, 对"**改我们发出去的内容**"不成立。

漏掉的那个观测点是: 🎯 **被观测系统本身的输出**。这个案子里就是**发光的屏** ——
它天然在**下游**(恰好是插不上探针的那一侧), 而且带宽比任何调试脚都高。
实际发生的事: 用户在看屏, 我们在看 JTAG, **他看到了我们读不出来的东西**
(「第三块不是完全不对, 隐约能看出彩色条, 像是后续数据都被开在第三块反复显示」)。

而我们自己的图案里**没有任何片号** —— 每一颗收到的图案长得一模一样 ⇒
"第 3 块上有彩色条"根本不能说明那是**谁的**数据。**这是自己造的盲区。**
改法: 把片号揉进颜色 (每片整片一个纯色) ⇒ 屏自己把"第 3 块在显示第几片"说出来。

**How to apply (补)**:
4. 列"可用观测点"时**别只数自己接的那些线**。被观测系统本身的输出往往带宽最高、
   而且天然在下游。⇒ 与其想办法在下游插探针, 不如**在上游改激励, 让下游的输出把信息带出来**。
5. 自研的测试图案要**自带位置签名**(片号/行号/帧号)。没有签名的图案在"数据错位/重复/丢失"
   这类问题上**等于没有信息** —— 它只能告诉你"有没有数据", 不能告诉你"这是谁的数据"。

## 🔴 2026-09-10 又一条自我更正: **"现象逐像素变"推不出"是模拟余量问题"**

推理原文: 测试图案在一片内**每个像素的数据完全相同** ⇒ 任何**静态**损坏 (bit slip / 字边界错位 /
lane 交换) 都只能产生"整块均匀但颜色不对" ⇒ 观测到**逐像素**噪点就说明损坏**逐像素地变**
⇒ 「所以是采样余量 / 时序边缘 / SI」。

**前半段对, 后半段错。** 上板实测: **4 倍降速 (200 → 50 Mbps) 屏上零变化。**

漏掉的第三种机理: **显存被高速反复覆写, 而显示扫描与写入在打拍子** ——
损坏源是**纯数字的静态逻辑错误**(比如某颗芯片不转发、把下游数据全写进自己的显存),
但因为**扫描相位与写序列相互游走**, 每个像素被扫到时命中的是不同的写入 ⇒
**观测到的结果照样逐像素变**。

⇒ **How to apply**: 看到"逐像素/逐拍随机"的现象, 只能推出「**损坏源随时间变**」,
推不出「**损坏源是模拟余量**」。**写入侧的时序竞争 / 缓冲区回绕**也能让一个纯数字错误
看起来像模拟噪声。要分开, 用**降速**(余量类会变, 逻辑类不变) —— 一刀就切开, 而且很便宜。

## 🔴 2026-09-10 第三条: **选判据之前先问"我的测量手段会不会把这个物理量抹掉"**

判据是"第 3 块里出现**几种颜色**", 观测手段是**手机拍照**。
屏 ~1150 fps, 手机曝光 10~30 ms ⇒ **一张照片积分了几十帧**。
黄 `(1,1,0)` 与蓝 `(0,0,1)` 快速交替, 积分出来**就是白**, 而且**每个像素一样白**。
⇒ 这个判据**在原理上就答不了**, 与照片拍得好不好无关。

识破它的方法很干净: 把画面里**已知的纯色块当机内色标**, 比**色度标准差** ——
杂色块的散布 (0.044/0.053) 居然**比纯色块 (0.105/0.105) 还小一半**,
而"两种饱和色混在一起"只可能让散布**变大**。⇒ 看到的"彩色点"是 JPEG/去马赛克伪影。

**How to apply**:
1. 观测链上**每一级**都要问"它保不保这个量": 这次是 `屏(高帧率) → 相机(长曝光) → JPEG(有损+去马赛克)`,
   **三级都在削颜色**, 而**平均亮度三级都保真** ⇒ 把判据从颜色换成亮度, 问题立刻可判。
2. 判据要选**观测链最结实的那个维度**, 不是最直觉的那个维度。
3. 画面里**放一个已知的机内标准**(这里是两块已确认的纯色), 否则连"照片可不可信"都没法判。

## 🔴 2026-09-10 第四条 (**更正上面那条第三条**): 是**过曝**, 不是时间平均

上面第三条把"照片读不出颜色"归给「屏 1150 fps + 相机 30 ms 曝光 ⇒ 积分了几十帧」。
**被用户一句话证伪**: 屏上画面「**几乎是完全静止的**」。静止画面不存在时间平均问题。
重新量同一张照片, 真正的原因是**传感器饱和**: 块3 R 通道 50% 像素饱和、三通道全饱和 5.8%。

🔴 **把一个可修的问题说成了不可修的**: 过曝**降曝光重拍就行**, 时间平均**无法事后挽回**。
差点因此把整条颜色判据废掉。

✅ 那条"色度标准差比纯色块还小 ⇒ 不存在颜色分群"的**结论仍然成立**, 只是理由换成
**饱和把比值压缩到 1 附近**。而且**只取未饱和像素重算**之后结论更硬:
色度标准差 0.011, 全部挤在白点附近 ⇒ **是均匀的白, 不是杂色**。

**How to apply (改写第三条)**:
1. 拿照片做定量判据前, **先统计饱和像素比例**; 饱和像素的通道比值是**假的**, 必须剔掉再算。
2. 区分"**测量被破坏**"(可修: 换曝光/换镜头/换手段) 与 "**信息本身不存在于该维度**"(不可修)。
   **把前者误判成后者会让人放弃一条本来能用的判据。**
3. 先问被测对象的**动态特性**(这次: 画面是静止还是在动) —— 一句话就能决定
   "时间平均"这个机制存不存在。**别在没问之前就假定它存在。**

## 🔴 附带的一条方法论: **全白(全 1)图案只能抓 stuck-low, 抓不到 stuck-high**

一条**永远为 1** 的 lane, 在"所有位本来就该是 1"的图案里**看起来完美无缺**。
⇒ 全白档能抓"缺通道"(断线/stuck-low), 对"多出一个通道"(stuck-high/串扰泄漏)**完全瞎**。

**要抓 stuck-high, 判据必须是「让那条线本该沉默」**:
> 在一颗**已知健康**的芯片上把那一位压成 0, 看它是不是自己冒出来。

📌 这跟 [[§ 在健康芯片上诱发故障]] 是同一条: **"本该沉默的东西出声"比"本该出声的东西沉默"更难伪造**,
   因为后者有一万种平凡解释(没接、没配、没使能), 前者只有少数几种。
⚠ 我一度因为"这一版 R 位是 0, 所以又没测 R"而想撤掉那个实验 —— **搞反了**:
   **R 位是 0 恰恰是它有牙的原因。**

## 🔴🔴 2026-09-11: **JTAG 下载 ≠ 被测设备复位** —— 而且差了五个数量级

实测(零变量, 两次独立复现): 重下**同一版 bit**(同文件同 CRC)、跳线一根没动、不做人工复位
⇒ 被测设备的应答位图从 511(全部) 掉到 **0**; 人工复位后**立刻**恢复全部。

根因在**我们自己的上电复位计数器**里, 一行就能看出来:
```verilog
reg [7:0] por_cnt;  ...  else if (!por_cnt[7]) por_cnt <= por_cnt+1;  // 128 拍 ≈ 1.28 µs
```
FPGA 配置期那根电源使能脚是**高阻**(靠外部下拉), 而配置一完成, **1.28 µs** 内就被拉高了
⇒ **FPGA 从来没有"主动驱动它低"过**, 被测设备侧的电容一路撑着, **根本没断过电**。

🔴 而顶层注释里写的是「要按住足够久让电容放完 (**估** ≥100 ms)」——
**那个"估"字就是"没人验过"**, 而且它估的是**手按复位脚的时长**,
**没人去核过"配置完成 → 使能脚拉高"这一段有多长**。两件事被混为一谈了。

**How to apply**:
1. **"重新下载"不等于"被测系统回到初始状态"**。做对照实验前先问: 这一版和上一版之间,
   **被测设备到底有没有被复位过**? 没有的话, "换了参数没变化"这个零结果**可能只是它还停在旧状态**。
2. 把复位**做进 bit 里**: 配置完成后**主动驱动**电源使能/复位脚低若干百毫秒再放行,
   让"下载"自带一次真复位 —— 否则每个实验都要等人到台架前按一下, 这个循环延迟会吃掉全部工作。
3. 注释里凡是带"**估**"字的数, 都是**没验过**的; 它还很可能**估的不是你以为的那个量**。
4. ⚠ 由此受影响的**全部历史零结果**标「**可能无效 / 需重做**」, 不要标「无效」——
   其中有些可能正好赶上过复位。一笔勾销会丢掉真结论。

## 🔴🔴 2026-09-14 追加: **只置位不清零的计数器, 读数里一定混着"你等了多久"**

九颗链的"有几颗在答"是靠一个 sticky 位图读的:
```verilog
if (!rst_n) fdev_seen <= 0;                       // 只有复位清零
else if (crc_ok) fdev_seen[dev] <= 1'b1;          // 只置位, 没有清零分支
```
⇒ 某颗**只要曾经答对过一次**, 位就永远是 1。于是:

| 我们以为读到的 | 实际读到的 |
|---|---|
| "现在有几颗好的" | **"到目前为止有几颗至少答对过一次"** |
| 三天后 8 颗 = 修好了 8 颗 | 三天内有 8 颗**至少答过一次**(可能每颗只答了一次) |

🔴 后果一: **"指标随运行时长上升"由构造保证** —— 只要每颗有任何 >0 的应答概率,
等得够久位一定会置起来。**观察到上升, 推不出"在恢复"。**
🔴 后果二: 35 个"下载后约 100 秒"的读数横跨 1~9 —— 这个**高方差是量具的固有属性**,
它们是在**一条单调累积曲线上的固定早期时刻**取的样, 读到几取决于应答率 + 运气。
不需要任何物理假说就能解释掉那个离散。

⇒ 📌 **协议**: 这类读数**必须同时记下"距上次复位过了多少秒"**。不写时刻的累积量读数没有意义。
("约 100 秒"里那个"约"字本身就在往方差里加东西。)
⇒ 📌 **量具**: 要答"**现在**有几个在答", 需要**带窗口(定期清零)**的版本。两个都要留 ——
累积版答"曾经", 窗口版答"现在", 它们是**两个不同的问题**。

## 🎯 反过来, 同一个性质也能白送一批数据

因为它只会涨, **每一位的 0→1 跳变时刻 = 那一颗的"首次答对延迟"**。
⇒ 一条长日志能给出**每颗一个数**(9 个), 而不是一条"总数 vs 时间"的曲线,
而这 9 个数才分得开机理: 首答延迟**随链序单调递增**(沿链累积) vs **各颗独立随机**(片间离散)。
⚠ 前提是**日志记位图, 不记 popcount** —— 记成总数的话这 9 个数事后补不回来。

📌 一般形状: **遇到一个"只增不减"的观测量, 先问两件事**:
① 它混进了"我等了多久"吗(⇒ 必须记录时刻); ② 它的**首次跳变时刻**是不是比它的**当前值**信息量更大。

## 🔴🔴 工作顺序: **先问"量具能不能产生这个形状", 再问"这说明了什么"**

一夜之间同一个模式出现**三次**, 每次都是"先解读读数"的人被"先查量具"的人拦住:
1. 位图的**有序前缀** ← 回读是**菊花链**, 坏芯片不转发 ⇒ 前缀是拓扑强制的, 与病因无关。
2. 「同几颗反复坏」这条**判据本身不可观测** ← 第一个坏的会挡住它后面所有人的 ACK。
3. 读数是 **sticky 累积量** ← 只置位不清零 ⇒ "随时间上升"由构造保证, 高方差是量具的属性。
4. (隔天又一次) 「首答延迟**随链序单调递增** ⇒ 沿链累积」—— 同样由菊花链强制,
   `t_k` 置位要求 0..k−1 全在转发 ⇒ `t_0≤t_1≤…≤t_8` 是拓扑给的。**提出这条判据的正是第 1、2 条里拦人的那个**
   ⇒ 📌 **"知道这条规律"和"下次用得上"是两回事**; 写在文档里不等于在下一个判据上会想起来。

> 🔴 **拿到一个"有信息"的读数时, 第一反应应该是**
> **「这个量具能不能自己产生这个形状?」而不是「这说明了什么?」**

**为什么这个顺序值钱**: "这说明了什么"是**开放式**的 —— 想多久都能想出一个解释, 而且解释得越好越危险;
"量具能不能自己产生这个形状"是**封闭式**的 —— 查一下代码/拓扑就有答案, **而且经常是"能"**。
⇒ 先做封闭的那个: 便宜、有确定答案、一旦答"能"就省掉全部后续推理。

📌 可执行版, 按顺序问三句:
1. **这个量是怎么产生的?** 去读**产生它的那段代码/拓扑**, 不是读它的名字。
2. **它有没有混进"我等了多久"/"我从哪个点看的"?** 累积量混时间, 单点观测混拓扑。
3. **换一个假说, 这个形状会变吗?** 不变 ⇒ 分辨力是 0, 别拿它当判据。

## 🎯 被拓扑强制的"顺序"里, 还能救出什么: 看**增量**

链式观测让 `t_0≤t_1≤…` 成为必然, 但**增量 `Δ_k = t_k − t_{k−1}` 没有被强制** ——
它是"前面都通了之后还要再等多久", 反映第 k 个环节自己。
- `Δ_k` 随 k **系统性增大** ⇒ 沿链累积(每跳都更差一点)
- **某一个 `Δ_j` 特别大, 其余都小** ⇒ 单点瓶颈, 第 j 个把后面所有人挡在身后
- 都小且相近 ⇒ 没有逐环节结构, 由某个全局因素主导

⚠ 限定: `Δ_k` 是**条件**等待时间, 两个都慢时后一个的 `Δ` 会被前一个吃掉一部分
⇒ **只能做定性排序, 别拿去拟合速率。**

📌 一般形状: **顺序被拓扑吃掉时, 去看差分。** 一阶量废了不等于数据废了。

## 🔴🔴 同一天五次: **量具静默返回一个"看着合理"的值**

① 输出口没接线 ⇒ 空 bidir 读出**稳定的**随机值(稳定 ⇒ 像真数据, 工具不报错)
② 饱和计数器的**时间常数跟着工作点变** ⇒ 同一个 255 在不同档下不是同一件事
③ 位图**只置位不清零** ⇒ 读数里混着"我等了多久", 长得和"现在有几个好的"一样
④ 取值工具没起来 ⇒ **全读 0**, 而全 0 是合法值 ⇒ 与"真的一个都没有"分不开
⑤ 注释里的"还剩 N 根空闲脚"是旧快照, 剩下的其实全是**配置脚**

**共同点**: 失败时**没有任何异常信号** —— 不报错、不出 X、不越界, 返回值**落在合法值域内**,
而且**经常正好落在"符合预期"那一侧**(0=没问题 / 稳定值=有信号 / 255=饱和)。
🔴 ⇒ **"检查有没有报错"抓不到它, 只有"这个值到底怎么来的"抓得到。**

### ✅ 解法是把自证做进读数, 不是做进流程

`nbad=0` 有两义("没掉线" vs "计时器没跑") ⇒ 加一位 **`wtog`, 每窗口翻转一次**。
**它不靠人记得去验 —— 它就在读数里, 和主量一起被读回来。**
第二个实例: 一个**必然会涨满**的对偶计数器(`rdok`)给"从 0 开始的计数器"(`rdbad`)当自证。

> 🔴 **纪律: 每加一个探针, 同时回答「它坏了的时候读数长什么样?」**
> **如果答案是"和正常一样", 就必须再加一位自证。**

### 📌 清单 (按探针形状配自证位)

| 探针形状 | 坏掉时的假象 | 配什么 |
|---|---|---|
| 从 0 开始的计数器 | 卡在 0 = "完美" | 心跳翻转位, 或一个必然涨满的对偶计数器 |
| 饱和计数器 | 255 = "好得很" | 记下**涨满要多久**; 跨档比较前先问这个时间常数变没变 |
| 只置位的位图 | 混进"我等了多久" | 必须同时记采样时刻; 要"现在"就另做定期清零版 |
| 纯组合输出 | 口没接线 ⇒ 稳定随机值 | 构建判据扫网表: 必须 `opad`, `bpad` 数 = 0 |
| 靠外部工具取值 | 工具没起来 ⇒ 全 0 | 同一次读里放一个**已知非零的常量位**, 读到 0 ⇒ 整次作废 |
| 链式/单点观测 | 拓扑强加的形状被当成结果 | 先问"换个假说这形状会变吗", 不变 ⇒ 分辨力 0 |

📌 最后一条最便宜也最常被漏: **一个恒 1 的哑位**, 就能把"工具没起来"和"真的全 0"分开。
