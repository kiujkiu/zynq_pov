# ACK 静默证明不了任何事 (2026-09-01)

从 2026-08-19 起, "LED2 亮不亮 / `ack_ok_sticky` 置没置位"一直被当成比"屏亮不亮"更硬的判据。
2026-09-01 两条发现把它整个推翻。

## ① 手册明写 ACK 菊花链是**可选**的

编程指导 P6 引脚表 `ACK_I`(N12) 原文:

> 「数据回传输入。**如需回传功能**, 级联情况下需接入下一颗芯片的 ACK_O, 最后一颗 ACK_I 可浮空。」

`ACK_O`(B4) 是纯输出(类型 O, 电平 VDDD/GND, **推挽不是开漏**), 第一颗的 ACK_O 汇总全部回传。
⇒ 灯板是**供应商的客户样板**, 他们自己点亮时用不用回读是他们的事。
**如果 9 颗的 ACK_I↔ACK_O 没串起来、或第一颗的 ACK_O 没引到 J1.22, 这根线永远不会有信号。**

所有既有证据都与"这根线压根没接"相容: ACK 一直高阻、被邻线 I_SYNC 拽着走(错误率 ≈ 帧率的一半);
2026-09-01 重焊接插件后读数一个字没变(**没接的线, 焊得再好也不会变**)。

## ② 读出通路自身有一个未定位的缺陷

2026-09-01 扫 dev 0..8 时冒出"回包", 两次跑落在**完全不同的设备号**上 ⇒ 不可复现。
它同时违反四条可证伪判据, 每条单独就够判死:

1. 回包 **8,300/秒**, 而提问上界只有 `fps/16 = 10/秒` —— 超 830 倍
2. `ack_frame_cnt` 与 `ack_err_cnt` 的增量**每一行都相同** —— 两者由互斥条件驱动(`crc_ok_pulse`
   vs `frame_err`), 不可能同步增长
3. `ack_f_nbits` 每出现一行正好 +1(263→264→265→267→268), **跨 soft_rst 还接着数** ⇒ 是计数器不是数据
4. `ack_ok_sticky` 从 1 变回 0 —— 粘滞位没复位掉不下来

**根因至今未找到。** 在找到之前 ACK 的任何数字都不作判据。

## How to apply

- **判据只剩屏**: 首光阶段一切实验的判据是"屏上有没有光", 不是 ACK 计数。
- 给供应商的问题清单里加一条、排前面: **"这块样板上 ACK 菊花链接了没有? 第一颗的 ACK_O
  有没有引到 J1.22?"** 一句话就能问掉, 而它决定我们过去两周的核心判据成不成立。
- 解调器 `icnd2260_ack_rx.v` 的 `A_IDLE`/`A_START` **都没有超时**(:134-153) ⇒ 线被焊到 GND
  或焊到电源, 都给出 `ack_err=0` + `ack_cnt=0`, 与"芯片推挽驱动着空闲高"**逐位相同**。
  **所以 `ack_err` 塌到 0 不能读作"通了"。**
- 想判断"屏侧到底有没有源驱动 ACK", 唯一干净的办法是万用表: `soft_rst` 在 1/0 两态各量一次
  J1.22 对地直流, **两态读数相同 ⇒ 线上唯一的源是 FPGA 片内上拉**(xdc `PULLUP TRUE`)。
  这个判据与推挽/开漏无关, 不需要任何拓扑假设。
- ⚠ 片内上拉方向是反的: 上拉把"没连"伪造成"健康空闲高"。要验通断应该用 **PULLDOWN**
  (读到高 ⇒ 只可能是屏侧在驱动)。

**Why**: 2026-08-20 已经踩过一次同类(悬空 ACK 放大噪声出 18k 假帧, 差点误判成"找到 7 颗芯片"),
当时的结论是"加上拉+CRC 闸就可信了"。**2026-09-01 证明那个结论下早了。**
