# 同一步里改了量具又改了被测物, 结论就废了 (2026-08-07)

## 事情经过

lz4 解码核在 DR1 上表征出 Fmax 100.4 MHz（余量 0.4%），关键路径起于 `m_ready`。
我判断是[[feedback_always_ready_tb_hides_handshake_bugs]]里那个反压修复把 `m_ready`
拉进了 ERAM 地址路径，于是要求加输出 skid FIFO 把它踢出去，验收线定 Fmax ≥ 111 MHz。

回来的结果：**SWNS +0.780 ns ⇒ 108.5 MHz**，关键路径起点确实从 `m_ready` 变成了 `s_data_q2`。
看起来方向对、只是差一点没到线。

**但 `s_data_q2` 这个名字不是我写的** —— 我的表征壳里只有 `s_data_q`。
壳被从**输入输出各一级**改成了**各两级**打拍。

## 对照实验（把 2×2 补齐）

| | 单级壳 | 双级壳 |
|---|---|---|
| **旧核**（无 skid） | **+0.043 ns → 100.4 MHz** | 未测（那版核没进过 git，已无法重建）|
| **新核**（有 skid） | **+0.009 ns → 100.1 MHz** | **+0.780 ns → 108.5 MHz** |

⇒ **量具固定（单级）时，skid FIFO 让 Fmax 从 100.4 变成 100.1 —— 没有改善，还略降。**
那 8 MHz 全部来自换量具。

## 为什么双级壳"看起来"更好 —— 它确实是更好的量具

改壳的理由本身是成立的（对方在注释里写了）：单级壳下
**pad → 第一级 FF 的走线就有 2.169 ns，占整条关键路径 9.412 ns 的 23%**，
报出来的不是核的内部 Fmax 而是"pad 离核有多远"。加第二级后，第二级触发器可以被
自由摆到核旁边，路径才真的是 FF→组合→FF。

**所以两个数都不是"真值"**：单级偏悲观（含 pad 走线），双级偏乐观（核的邻居是空气）。
真值要等集成进完整设计后才有。

## 教训

**一次只动一个变量。** 改了设计就别同时改量具；要换量具，先用新量具把旧设计重测一遍，
建立新基线，再改设计。否则"改善了多少"这个问题在结构上就没有答案。

这次是靠"这个信号名不是我写的"察觉的 —— 值得推广的习惯是：
**拿到超预期的结果时，先确认量具没变。**

## 顺带: skid FIFO 该不该留 —— 该留, 但理由不是时序

- 功能上正确（`s_ready` 变回纯寄存器且是对的，四档回归 16/16 全过）
- 33% 反压下吞吐 0.930 → **0.938 B/clk**（约 +1%，聊胜于无）
- 代价：lut6 421→487，slice 464→558，reg 256→337，eram 不变

## 真正的关键路径 & 由此得到的更好解法

新核的关键路径是 `s_data → offset → ERAM 读地址`（7 级：LUT5×2 LUT3×2 LUT6 LUT4 ERAM）。
LZ4 的 offset 来自输入流、直接参与算读地址，**这是字节串行架构固有的**，skid FIFO 碰不到。

⇒ **不要再和这条路径较劲。换个方向：降频 + 加引擎。**
DR1V90 的 PL 大得离谱而这个核极小（单引擎 eram 10.0% / slice 1.06%）：

| 方案 | 时钟 | 吞吐 | eram | 时序余量 |
|---|---|---|---|---|
| 2 引擎（原计划，抄 Zynq） | 100 MHz | 190 MB/s | 20% | **~0%** 🔴 |
| **3 引擎** | **75 MHz** | **214 MB/s** | 30% | **33%** ✅ |

门槛是 143 MB/s。3 引擎 @75 MHz 不但吞吐更高，时序还从"压线"变成"宽裕"。
`PVS_FLAG_MSTREAM` 本来就支持 N 路流 ⇒ **协议零改动**。
压缩流只占 1/33 带宽，写侧 214 MB/s 走 64-bit HP 也远没到顶。

**这是 Zynq 和 DR1 约束不同带来的结论**：Zynq 那边 fabric 紧、HP 口多，
自然想到"少引擎跑高频"；DR1 fabric 富余、HP 口少，正确答案是"多引擎跑舒服的频率"。
照抄 Zynq 的架构决策是错的。
