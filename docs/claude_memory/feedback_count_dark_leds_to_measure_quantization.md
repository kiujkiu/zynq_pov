# 色深测量: 数暗端全黑的 LED 颗数 (2026-09-02)

## 先说失败的几种(都试过)

| 图案 | 为什么不行 |
|---|---|
| 8 级 gamma 台阶 | 最小间距 850 码 >> 12 位的量化台阶 16 码 ⇒ **一级都不会并, 测不出** |
| 1800 级细斜坡(高位, 步长32) | 覆盖 88% 满量程, 但感知 ∝ v^(1/2.2) ⇒ **90% 的面积看着一样亮**, 暗端被挤进最上面几行 |
| 1800 级细斜坡(低位, 步长1) | 只占满量程 2.7% ⇒ 太暗; 拉大 LED 电流后 ⇒ **相机高端饱和(150~243/255)** |

🔴 **根因**: 要分辨的是码值差 16(12位) 或 4(14位) = 满量程的 0.02%~0.006%,
而手机 JPEG 只有 8 位 + 手持透视 + 环境光 + LED 点阵摩尔纹。**差一个数量级, 换算法救不了。**

## 唯一可行的读法: 数暗端有几颗全黑

```
量化台阶 Q  ⇒  码值 0..Q-1 全部量化成 0  ⇒  **斜坡起点的头 Q 颗 LED 完全不亮**

16 位 Q=1  → 1 颗       12 位 Q=16 → **16 颗**
14 位 Q=4  → 4 颗       11 位 Q=32 → 32 颗
```

🔴 **"亮 / 不亮"是二值判断 —— 不怕饱和、不怕曝光、不怕透视、不怕裁剪、不怕噪声。**
今天所有困扰照片判读的问题, 一个都影响不到它。

配套: 图案用"每个 LED 一个码值"的斜坡(1800 像素 = 1800 级, 见
`tools/gen_single_ramp.py --pattern rfull --lsb 1`), 并把 `0x2d` poke 成 `223F`
(红色电流拉满 5.3 倍)让头几级也看得见 —— **码值和量化都不变, 只是同样的码发更多光。**

## 可推广的

**当量具的精度不够时, 把"测量"改造成"计数"。**
连续量(强度)受一切系统误差影响; 而离散事件(亮/不亮)几乎不受。
同类: 帧率测量也是这样才做通的(数亮起的相位条数, 而不是测亮度)。
