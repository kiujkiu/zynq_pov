# 穷举之前, 先把"器件约束"和"我的选择"分开标注 (2026-09-04)

## 发生了什么

给 ICND2260 排屏板布局, 我列了张"颗数 × 扫数"的表, 三个候选算得逐格精确,
但**整张表的前提是错的**: 我默认 "40 px 通道轴沿 192 方向摆"。

那不是芯片约束, 是**布局自由度** —— 40×S 的矩形在面板上横着摆竖着摆都行。
锁死方向后, 192÷40 = 4.8 ⇒ 横向恒 5 颗, 纵向 216÷扫数 恒不整除,
于是我算出 "22.5 颗"(不可实现) 和 "25 颗, 末排只用 24 扫"(不对称)。

换个方向摆立刻通了: 6×40 = 240 覆盖 216, 192÷4 = 48 **整除**,
⇒ **4×6 = 24 颗, 全局最少**, 而且 48 扫恰好用满 48 个内置行管。
用户一句"我理解应该是 4*6 的结构吧"点破的。

## Why

穷举法只在**穷举空间对**的时候有效。空间少一个维度, 算得再精确也是精确地错。
而"哪些是给定"往往不写在手册里 —— 手册只说 "120 通道 / ≤96 扫",
**没说这两个轴在面板上怎么对应**, 那是留给设计者的。我把留白读成了约束。

## How to apply

- **穷举前逐项标注**: 每个参数写清 `器件约束(手册第几页)` 还是 `我的选择`。
  写不出出处的, 多半就是自由度。
- 🔴 **丑解是信号, 不是结论**: 算出 22.5 颗、末排不齐、必须浪费一大块 ——
  出现这种解时**先回头查是不是漏了自由度**, 而不是在丑解里挑一个最不丑的。
  与 [[feedback_verdict_design_before_blaming_dut]] 同源: 结果反常时先怀疑自己的设定。
- 这条与 "判据不能包含答案" 是一对: 那条讲**别把结论塞进判据**,
  这条讲**别把选择塞进前提**。
