# 🔴 排除表不能吃掉被测量 (2026-09-14, E104 × ICND2260 一链一颗回读核对)

**事实**: `SKIP_N=7` 排除了 7 个"回读≠写入"的地址 (每个**每全表周期各 1 次**)。
之后 4.3 h (95 个周期) 里又冒出 **1 次** `0x44` 失配 (写 `0x028F` 读 `0x1082`, 5 位不同)。
我提议把它也加进排除表 —— **错的**, 被协调者拦下。

**为什么错**:
1. 速率差两个数量级 (每周期 vs ~1/100 周期) ⇒ **不是同一个过程**。
   "稀有一点的同类成员"和"百倍稀有的另一种现象"是两回事。
2. 排除的正当性来自**系统性、每周期必现、与写入值无函数关系** —— 一次性事件**三条一条都判不出来**。
3. 🔴 那 1 次就是测试要交付的那句「231 个寄存器核对 1,600 遍**无一次不符**」里的"一次不符"。
   排除它 = **删掉唯一正样本再宣布测试全过** ⇒ 自己**主动造**一个"量具静默返回合理值"
   (同类清单见 [[feedback_ack_silence_is_not_evidence]] 末节)。

**How to apply**:
- 往排除表 / 白名单 / 忽略列表加成员之前, 先比它的**速率**和**系统性**是否与现有成员同量级;
  不同 ⇒ 它是信号, 留给计数器 (`rdbad`) 和首次抓取 (`badaddr/baddata`), **不进表**。
- 🔴 "收齐 / 集合稳定 / 没有新的了" 必须写成「**在 X 时长内**…」并给检出下限:
  以 95% 把握抓到平均间隔 τ 的事件需观测 ≈**3τ**。这次拿 25 分钟 (9 周期) 宣布收齐, 而 τ≈100 周期, 差 30 倍。
- 交付语把观测时长写进判据本身, 例: 「在 5.2 h 观测内高频失配集合为 7 个且稳定; 另观测到 1 次低频失配 (0x44), 仅 1 例, 未定性」。

## 同日: 破坏性步骤执行前, 重核它的前提还在不在

计划是「用户重启电脑 ⇒ 回来重下同一版 bit、重新计时 3 天」, 前提是"重启会中断测试"。
先做非破坏读数: `rdbad`/`badaddr` 与重启前一致 ⇒ **板子从没复位** (PC 重启不等于板子掉电);
顺带读到了此前**从没读出过**的 `baddata=0x1082`。重下 bit 会白白毁掉 5.2 h 累积时长和这个读数
⇒ **不重下, 沿用原 T0 继续记**。

📌 这是 [[feedback_single_reading_is_noise_repeat_five_times]]「罕见状态先榨干, 非破坏的做完才轮到破坏的」的又一次应用。
📌 **只在复位时清零的累积量 (计数器 / 首次锁存) 本身就是"有没有复位过"的免费证据** —— 先读它, 再决定要不要重来。

详细读数与判据: `dr1v90/eg4_2260_e104/README.md` §6.52。
