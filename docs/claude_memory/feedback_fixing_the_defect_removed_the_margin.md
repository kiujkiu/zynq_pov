# 修好了一个真缺陷, 系统反而变差 (2026-09-02, ICND2260 九颗级联)

## 事实

09-01 晚上拿到过 **9 颗全亮、稳定 60 秒**。09-02 修好供电后重测, 变成 **2~6/10**。
我和用户都把它当"退步"在查, 查了半天时序和相位。**但那两次根本不是同一个配置**:

| | 09-01 拿到 9/9 | 09-02 的 2~6/10 |
|---|---|---|
| **VDDR** | **1.9 V(规格下限 2.8 V)** | 2.96 V |
| 刷新分组 | 32(VIO poke) | 74(重烧回出厂表) |
| 帧率 | 398 fps | 118 fps |

🔴 **三个变量里, "修好供电"是唯一朝更糟方向变的那一个。**
1.9 V 时红色恒流源没有压降余量、**拉不满电流**; 修到 2.96 V 后, 9 颗同步扫同一行的
红色峰值 `40 通道 × 1.96 mA × 9 ≈ 700 mA`(平均仅 16 mA)**真的流起来了**。
而 mini-LVDS 共模输入窗 `V_IC = 1.1~1.3 V` 只有 **200 mV 宽**, 第 1 跳实测 **1.294 V,
距上限只剩 6 mV** ⇒ 几十 mV 的地弹就能把某一跳推出窗口。

⇒ **那个"缺陷"一直在当限流器用, 它是 9/9 的必要条件之一。**

## 可推广的

1. 🔴 **"修好 X 之后 Y 变差"不是悖论, 是常态**: 一个缺陷可能同时在压制另一个缺陷。
   遇到这种情况, **先假设它是因果的**, 不要先怀疑"是不是别的地方碰坏了"。
2. 🔴 **拿两次实验结果作对比之前, 必须先把变量差异逐条列出来。**
   这次 A/B 之间同时差了三个变量, 而我直接把 2/10 和 9/9 当成同一配置的退步在解释,
   在错误前提上推了很久。**列表本身只要两分钟, 却能省掉几小时。**
3. 本项目第四次踩"测量条件本身不稳", 前三次见 [[feedback_vddr_sags_to_1v9_invalidates_fps_limits]]
   (VIO 读回撕裂 / poke 残留 / 塌陷随帧率变)。**四次都表现为"同样设置结果不同"。**
