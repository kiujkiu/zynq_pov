# 修好了一个真缺陷, 系统反而变差 (2026-09-02, ICND2260 九颗级联)

## 事实

09-01 晚上拿到过 **9 颗全亮、稳定 60 秒**。09-02 修好供电后重测, 变成 **2~6/10**。
我和用户都把它当"退步"在查, 查了半天时序和相位。**但那两次根本不是同一个配置**:

| | 09-01 拿到 9/9 | 09-02 的 2~6/10 |
|---|---|---|
| **VDDR** | **1.9 V(规格下限 2.8 V)** | 2.96 V |
| 刷新分组 | 32(VIO poke) | 74(重烧回出厂表) |
| 帧率 | 398 fps | 118 fps |

🔴 **三个变量里, "修好供电"是唯一朝更糟方向变的那一个。**
1.9 V 时红色恒流源没有压降余量、**拉不满电流**; 修到 2.96 V 后, 9 颗同步扫同一行的
红色峰值 `40 通道 × 1.96 mA × 9 ≈ 700 mA`(平均仅 16 mA)**真的流起来了**。
而 mini-LVDS 共模输入窗 `V_IC = 1.1~1.3 V` 只有 **200 mV 宽**, 第 1 跳实测 **1.294 V,
距上限只剩 6 mV** ⇒ 几十 mV 的地弹就能把某一跳推出窗口。

⇒ **那个"缺陷"一直在当限流器用, 它是 9/9 的必要条件之一。**

## 可推广的

1. 🔴 **"修好 X 之后 Y 变差"不是悖论, 是常态**: 一个缺陷可能同时在压制另一个缺陷。
   遇到这种情况, **先假设它是因果的**, 不要先怀疑"是不是别的地方碰坏了"。
2. 🔴 **拿两次实验结果作对比之前, 必须先把变量差异逐条列出来。**
   这次 A/B 之间同时差了三个变量, 而我直接把 2/10 和 9/9 当成同一配置的退步在解释,
   在错误前提上推了很久。**列表本身只要两分钟, 却能省掉几小时。**
3. 本项目第四次踩"测量条件本身不稳", 前三次见 [[feedback_vddr_sags_to_1v9_invalidates_fps_limits]]
   (VIO 读回撕裂 / poke 残留 / 塌陷随帧率变)。**四次都表现为"同样设置结果不同"。**

## 🔴🔴 2026-09-11: 两周后, 我们又从头走了一遍 —— **本文件就是答案, 没人回来读**

E104 上重新出现**逐字相同**的症状(链上前几颗亮、后面黑、每次上电随机几颗)。两个 agent 花了
一整夜、十几版 bit, 依次怀疑过: 帧率 → 下载不等于复位 → `PWR_ON_MS` → `PWR_OFF_MS` →
片间 POR 门限 → 每跳成功率。**没有一个是本文件里已经量出来的那个。**

本文件第 24 行写着: **共模输入窗 `V_IC = 1.1~1.3 V` 只有 200 mV 宽, 九颗同扫一行的红色峰值
≈700 mA 的地弹就能把某一跳推出窗口**; 而唯一那次 **9/9 是靠 VDDR 掉到 1.9 V 当限流器**拿到的。
它一条不落地解释了那一夜的**每一个**现象:
随机几颗(地弹跟瞬时电流走) / 从 0 开始的有序前缀(**地回流沿链累积, 越靠链尾偏移越大**) /
帧率越低越好(占空比↓⇒电流↓) / 重发救不回来(配置包走同一条出窗的链路) /
换相位·极性·速率全无变化(改的是信号, 坏的是**共模基准**, 而差分判据对共模是盲的)。

📌 **两周、十几版 bit 的代价, 换来的是重新走到自己两周前已经写下的结论。**

## 🔴 由它引出的一条新方法论: **两个假说对同一个旋钮预言同向时, 那个旋钮判不了案**

降帧率**同时**降低 ①每颗的扫描负担 ②LED 平均电流 ⇒ "扫描速率溢出"与"地弹/共模"
对帧率的预言**方向相同** ⇒ **帧率梯子无论做得多漂亮、样本多足, 都分不开这两个假说。**
⇒ 必须找**只动其中一个**的旋钮: 这里是**图案灰度**(只动电流, 不动任何时序)。

🎯 而且它给出一个**方向相反**的预言: **把屏调暗, 应该有更多颗亮。**
没有任何竞争假说会做出这个预言 ⇒ **无论结果如何都有信息量**。
📌 可推广: **优先做那个"预言方向反直觉"的实验** —— 它天然不会和别的机制混淆,
而"把东西调好会变好"这种预言, 几乎每个假说都做得出来, 验了也分不出谁对。
(本项目的历史正是反过来的: 两周都在**把东西修好**, 而唯一一次成功来自**把电流弄小**。)

## ⚠ 做"降电流"实验时的一个陷阱: **灰度降的是占空比, 不是峰值**

这类芯片的灰度是**恒流源上的 PWM 占空比**, 峰值电流由**电流增益/每色标定寄存器**定。
⇒ 调灰度 ≠ 调峰值。而**本文件记的那次 9/9, 靠的恰恰是 VDDR 掉到 1.9 V 把峰值饿死。**

后果在**判读**上, 不在预言上:
- ✅ 预言方向不变 —— 地弹只在导通窗里出现, 占空比↓ ⇒ 关键跳变撞进导通窗的概率↓ ⇒ 仍然"调暗更好"。
- 🔴 但**"调灰度没效果" ≠ "电流不是根因"**, 只能得出"**不是占空比这条路**"。
  要否掉电流假说, 必须再单独动一次**峰值**。

不用新硬件的峰值旋钮: **同时点亮的颜色数** (一行 1 色 vs 3 色 = 白, 峰值差 3×,
而占空比与时序一个字不变) —— 零风险, 优先用这个; 电流增益寄存器直接但有风险
(标定值与本板 LED 压降绑定, "降 G 会不会连带影响标定值"仓库里明写"不知道")。

📌 可推广: **一个旋钮号称"调 X", 先问它调的是 X 的哪一个分量。**
"平均值"和"峰值"在电源/EMI 类故障里是**两个不同的因**, 阴性结果只能否掉你真动过的那一个。
