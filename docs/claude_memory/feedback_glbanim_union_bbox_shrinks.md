description: 整段动画共用 bbox 防抖但压小单帧; 逐帧归一 + 循环滑动平均兼顾"吃满体积"与"不抖"

`povstream.py` 的 `glbanim` 用**整段动画并集 bbox** 归一化 (防帧间缩放抖动),
代价是单帧被压小。同一 Robot 模型实测:

```
静态渲 (gen_anime_slices, 单帧 bbox) → 高 140
动画渲 (glbanim, 并集 bbox)          → 高  86     ← 缩 39%
```

## 解法: --fit-frames (2026-07-29 新增)

- 每帧按自己的 `[fit-pct, 100-fit-pct]` 分位 bbox 算缩放 → 吃满体积
- 对 144 帧的 **scale 与 center 序列做循环滑动平均**平滑 (动画首尾相接,
  用 wrap 卷积而非普通卷积) → 不抖
- 参数: `--fit-smooth 9` (窗口, 0/1=不平滑) / `--fit-pct 1.0` (分位裁剪剔离群点)

实测: 高 89 → **143** (追平静态版 140); scale 序列仅在 69.5..71.8 波动 (**3.4%**),
证明平滑有效, 不会帧间忽大忽小。

## 标定流程 (每个模型单独定)

渲 1 帧 → 量**整段包络** → 定参 → 渲全套。
⚠ **量包络必须用整段动画**: 单帧测 Robot 的 X 顶到 0..159 像是裁切,
整段包络其实 4..155 根本没裁 —— 个别帧手臂张开而已。

`--robust-fit` ([2,98] 分位并集) 单独就能放大 2.2× 但 Robot 上会裁切, 慎用。
`--y-offset` 是同期新加的 (原来只有 `--x-offset`); Robot 定值 `--scale 1.3 --y-offset 19`。

## 代价

内容变大 → 亮点变多、零值区变少 → **zlib 压缩率下降**, 帧率 9.4 → 6.9 fps,
链路占用 26% → 44%。物理规律, 不是 bug。要兼顾帧率可用 `--freeze-phase`
(冻结时域抖动, 静止区帧间字节不变, 兑现 delta 编码红利)。
