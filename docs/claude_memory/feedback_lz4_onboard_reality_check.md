2026-08-05 把 lz4 + 均衡三流合并上板实测。**三个并行 agent 的外推数字大半没兑现** ——
这也正是必须上板的理由。上位: [[feedback_codec_lz4_beats_zlib_4x]](离线测量) /
[[feedback_wifi_throughput_bottleneck_isolated]](链路)。

## 实测矩阵 (同一次会话, 967RPM fake-spin = 16.1 rps, 720/540 片偏心双面)

| 配置 | 板端 dec | cpy | 两核均衡 | 板端 rx |
|---|---|---|---|---|
| zlib 720片 (基线) | **~120 ms** | ~25 | — | 7-9/s |
| lz4-HC9 720片 按面 | **33-46 ms** | 22-34 | ✅ | 7-9/s |
| lz4-HC9 fold540 按面 | 27-42 ms | 17-40 | ❌ core0 17 / core1 41 | 7-13/s |
| **lz4-HC9 fold540 均衡三流** | **24-32 ms** | **16-24** | ✅ 22.6/22.6 | **10.0-11.4/s** |

✅ **解码 120 → 28 ms (4.3×) 兑现。** 均衡三流确实消掉 1:2 不均衡(预算 agent 判断正确)。

## 🔴 外推错在两处

**① 并行加速几乎没有: 1.06×, 不是 1.9×**
单核 lz4 解 8.85 MB = 41.2 ms(ctypes 实测); 双核每核解一半本该 20.6 ms,
**实测每核 35 ms**。lz4 计算少、更吃内存带宽, 两核抢得比 zlib(1.34×)更凶。
⇒ 预算 agent 的 **16.3 ms / 解码余量 2.04×** 没兑现, 实际 ~28 ms。
⚠ **编解码越快, 并行加速比越低** —— 这条对以后选型有普适意义。

**② 端到端只涨 1.4×, 不是 4×**: 7.41 → 10-11.4 fps。省下的 90 ms 被
`cpy 20 ms + wait 31 ms` 吃掉大半。

## 现在的真实帧预算 (16.1 rps, 一圈 62 ms)
```
dec 28 + cpy 20 = 48 ms  < 62 ms  ✅ 压进一圈了
但 wait 平均 31 ms (帧在随机相位完成, 平均等半圈)
⇒ 48 + 31 = 79 ms → ~12 fps, 实测 10-11.4
```
🔴 **翻页天花板 = 转速 = 16.1 fps** (一圈只能翻一次)。现在离物理上限只剩 1.4×。
要 30 fps 内容必须 1800 RPM —— 见 [[project_pov3d_final_target]] 的"内容帧率≠体帧率"。

## 🔴 读 pov_rxd.log 的判据 (我这轮连续错三次)

**空闲动画和网络推流都在同一个 log 里, 且都会让 rx 增长**, 极易张冠李戴。
我据此得出过"memcpy 涨到 40-58ms 成为瓶颈"的**错误结论并上报** ——
实际推流时 cpy 只有 16-24 ms, 那 40-58 是空闲动画的。

**可靠判据**:
```bash
grep -a 'DIAG' pov_rxd.log | grep -av 'dec 0.0/0.0ms'    # 空闲动画路径不更新 dec 累加器
```
- `dec 0.0/0.0ms (core0 0.0 core1 0.0)` ⇒ **空闲动画**, 不是推流
- `drop=` 恒定不变 ⇒ 也是空闲动画
- ⚠ **板子时钟与开发机不同步** (板 06:31 / WSL 14:30), 别按墙钟时间对窗口;
  用 `FRAME seq=` 的连续段界定, 或直接用上面的 dec 判据。

## 其他实测细节
- `FRAME` 行会标 `2str/par` / `3str/par`, 是确认均衡三流真的生效的最快办法
  (我第一次跑 fold540 忘了加 `--stream-split balanced`, 日志里 `2str` 一眼看出)
- 帧区映射确认走 **WC via /dev/povmem** 快路径 (不是 SO 回退)。
  ⇒ **不能直接解压进 bank**: WC 内存读极慢, 而 lz4/zlib 都是 LZ77 回溯要读输出缓冲。
- lz4-HC12 编码 722 ms/帧, **实测把发送端变成瓶颈** (板子 dec+cpy 只用 58ms 却只收到
  5-6 fps)。用 HC9(99ms/帧) 才测得准; HC12 只适合离线预压缩。
- 线上大小: fold540+lz4-HC9 = 278,880 B, 压缩比 23.8×

## ⚠ 端到端数字噪声很大, 本轮每配置只跑一次
WiFi 每 20-40 s 有 1-3 次 **300-840 ms 停顿**(环境性, 见诊断结论), 同一配置
povstream 总平均能差 7.49 vs 10.14。**要可信的端到端数字必须重复多次取分布**,
板端 DIAG 的 rx/s 比 povstream 的总平均可靠。
