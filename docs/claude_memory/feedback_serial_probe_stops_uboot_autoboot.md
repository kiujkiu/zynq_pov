2026-08-28 在 pov2 上踩到，**排查方向被带偏了很久**。

## 症状

板子"起不来"：网络不通、mDNS 解析不到、心跳灯不闪、屏不亮。
串口读到的却是：

```
Zynq>
Zynq>
```

**那是 u-boot 的提示符，不是 Linux。** 板子好好的，只是停在 u-boot 里没往下走。

## 原因是我自己

探串口时习惯先发 `Ctrl-C` + 回车把控制台叫醒：

```powershell
$p.Write([char]3)          # ← 就是它
$p.Write("`r`n`r`n")
```

**如果这一下正好落在 u-boot 的 autoboot 倒计时里，就会打断自动启动。**
而我恰恰习惯在"断电重上电"之后**立刻**探串口 —— 时机每次都撞在倒计时上。

## 🔴 为什么危险

停在 `Zynq>` 的外部表现，和"BOOT.BIN 坏了 / 供电不足 / 板子没起来"**完全一致**：

- 网络不通 ✓  心跳灯不闪 ✓  屏不亮 ✓  ping 不到 ✓

2026-08-28 我据此一度判定"`BOOT.bin.lz4x3` 启动不了"，让用户拔卡改文件。
**至少这一次的"起不来"是我自己造成的。**（另有一次串口是**完全静默**、连 `Zynq>` 都没有，
那次是 DLP 加密的 BOOT.BIN，不是这个原因 —— 两者要分清。）

## How to apply

1. **上电后探串口不要发 `Ctrl-C`**，只发回车。要打断 autoboot 才发 Ctrl-C。
2. 读到 `Zynq>` **不是故障** —— 敲 `boot` 回车就继续启动（实测一路跑到 `pov2 login:`）。
3. 判断"板子起没起来"之前先看串口给的是**哪一级**提示符：
   `Zynq>` = u-boot（活着，只是被停住）／`xxx login:` = Linux 起来了／**完全无输出**才是真没起来。
