| 1 | 渲染"实测 355 µs 差 4.8×" | 旧的非 batch IP 在 300 点场景 | **旧 top 的账**(记忆里早写了"别再引用") |

| 8 | 🔴 **面板取片 110.8 MB/s** | 那是 **1-bit/360槽/780RPM** 的旧账; 现役约 **160 MB/s** | **旧口径当现役分母** |

## 🔴 第 8 条单独说 —— 它是所有带宽论证的分母

反推证实旧数出处: `360 槽 × 2 面 × 11664 B ÷ 76.9 ms = 109.2 MB/s`, 逐位对上。
按**现役**口径重算(3-bit 三位平面 + 双面 + **142 槽/面** + **969 RPM**):
```
142 × 2 × 3 × 11664 B = 9.94 MB/圈  ÷ 61.9 ms ≈ 160 MB/s
```
而这条通路的**硬顶是上游 32 位 @50 MHz = 200 MB/s**(仿真实测 176-185) ——
与 HP 口是不是 64 位无关: 桥把一个 64 位拍拆成两个 32 位拍还给上游,
所以它**每 2 拍才收一个 64 位拍**, 自己就把 HP0 的 R 通道压掉一半
(`rtl/axi4_to_axi3_hp.v:118-120`)。

⇒ **余量不是 `pov_dual_top.v:713` 注释写的 1.7×, 是约 1.15×。**
⇒ 而"三引擎 142.5 写 + 面板 110.8 读 = 253 MB/s"这个到处引用的总需求,
   正确应是 **~300 MB/s**。

## 可推广的

🔴 **每一条都不是算错, 是「口径搬家」** —— 数字本身在它自己的场景里都是对的,
错在被搬到了另一个场景当分母/分子。

**How to apply**: 引用任何一个数之前, 先问三件事:
1. **它是哪个版本/哪个 top/哪块板的?**(第 1/2/4/6/7 条)
2. **它是峰值还是持续? 是芯片规格还是板子实际?**(第 3/4 条)
3. **它的口径参数是什么?**(槽数/色深/转速/面数 —— 第 8 条)

⚠ 尤其: **代码注释里的余量数字(如"余量 1.7×")最容易过期** ——
分子分母都可能在别处被改过, 而注释不会跟着改。
