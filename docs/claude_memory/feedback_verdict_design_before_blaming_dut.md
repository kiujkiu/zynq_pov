# 连着三次 FAIL 全是判据错, 不是被测物错 (2026-08-07, Step 3 取片验证)

没接屏的时候要验"DDR 取片通路取到的字节对不对", 我在 PL 里挂了个观测点,
然后连着拿到三次 FAIL。**三次都是我的判据设计错**, 取片通路自始至终是好的。

## 三次分别错在哪

**① 先读 CNT 再读 XOR —— 两次读之间通路还在跑**
取片是自由跑的, 读完计数再读校验和, 中间又取走了几百个字
⇒ XOR 里含着 CNT 没算进去的内容, 必然对不上。
修: **先停引擎再读, 而且要复查停稳**(再读一次 CNT 确认不变)。

**② `dual_en=1` —— 两个引擎各取一次同样的片**
字数正好翻倍, 而且同一片被 XOR 两次**正好抵消**。
修: 验证时关掉 `dual_en`, 让账目只有一条通路。

**③ 🔴 XOR 这个判据在原理上就不成立**
两条性质合起来杀死了它:
- 一片 40 ms 而读一片只要几十微秒 ⇒ **同一片被重复读几百次**, 顺序也不是 0,1,2,3 各一次
- `slice_idx` 一变**整对丢弃** ⇒ 返回的是若干个**片前缀**拼起来的, 不是完整片

⇒ "读了多少字"和"读了哪些内容"**都无法由 CNT 反推**。
我却一直在试图从计数算出期望值 —— 方向从一开始就错了。

## 换成什么

**判据必须与"读了多少次/被打断多少次"完全无关。**

DDR 里填 `word[i] = i`(每片内容相同), PL 侧只看**返回序列是否连续**:
```
data == 0        -> 新的一片开始, OK
data == prev + 1 -> 继续, OK
其它             -> err++
```
掉字 / 重字 / 乱序 / 坏数据全都抓得到, 而与读取模式无关。
实测 **`FETCH_ERR = 0 / 148,561 字`**。

⚠ 还有个边界: 清零时取片多半正停在片中间, 清零后看到的第一个字是任意值
⇒ 必然多记一次错(实测就是不多不少 1 次)。加一位 `primed` 让首字只给
`prev` 打底、不计错 —— 修完正好归零, 这本身就验证了这个解释。

## 可推广的

**拿到 FAIL 先怀疑判据, 尤其当被测物是"自由跑 + 可被打断"的时候。**
判据的设计要求是: **在被测物所有合法的行为下都应当成立**。
如果判据依赖"读了多少次""按什么顺序读"这类**被测物有权自由选择**的事,
那它不是判据, 是巧合。
