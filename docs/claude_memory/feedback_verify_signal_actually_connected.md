2026-07-29 在"面板刷新率"这一条线上**连错三次**, 根因完全相同:
**没确认信号到底接没接, 就拿它的值/存在性去推理。**

## 三次错误

**① `0x28 frame_period` 读到 7033 拍 → 算出 7109 Hz**
但 `panel_engine_2047.v:97` 是 `.frame_period_o ()` —— **悬空未引出**, 第 13 行注释明写
"本版未引出 — 遗留"。读到的是噪声。我不仅当成实测值, 还用它去"修正"设计文档的理论值
(文档 10530 拍/4.75kHz), **把噪声当证据推翻了正确的文档**。
用户一句"我理解应该只有 3.6k"才让我回头核 —— 物理上 54 行 × 192 bit ≥ 10368 拍,
7033 比理论下限还小, **本该一眼看出不可能**。

**② 说 "overlap 已经开着" (status bit6=1)**
`grep -c overlap icnd2047_panel_core.v` = **0**。那位是 v5(ICND2049) 沿用的遗留寄存器,
写得进、能回读、**不接任何逻辑**。

**③ 说 "oe_window 已到顶, 亮度没余量"**
实际 oe 是在**拿刷新率换亮度**: oe≤111 免费(藏在移位时间里), 超过就插 LWAIT。
说"到顶"等于没意识到这是个权衡。

## How to apply

**看到寄存器/信号要拿来推理时, 先花一秒查它接没接:**
```bash
grep -n "signal_name" <top>.v <wrapper>.v     # 看是否 .port () 悬空
grep -c "signal_name" <core>.v                # 核里出现 0 次 = 根本没这功能
```
**数量级自检**: 得到的数如果比理论下限还小/比上限还大, 先怀疑测量而不是理论。

**新增 RTL 功能时顺手留状态回读位**, 成本近零, 收益是每次换 bit 都能自证 —
见 [[feedback_cold_boot_required_for_bit]] 里"写新位再回读"的判据。

**遗留位要清理或标注**: `overlap_en` / `dclk_fast` 这些 v5 沿用但 2047 核不用的位,
不清理下次还会有人(包括我)看到 bit=1 就以为功能开着。
