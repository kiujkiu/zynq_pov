工程 `dr1v90/eg4_bridge/`(分支 `feature/uplink-tx-probe`, **未提交**)。
接口冻结在 `SPEC.md` + `rtl/bridge_defs.vh`。四个并行工作包一天建起:
分发块 / 顶层·时钟·IO·tx阵列 / DR1 侧发送器·双端对拍 / TD 工程·引脚·SDC·构建。

```
DR1V90 ──13対 LVDS 800M + 1対400M转发时钟──> EG4A20 ──24链×3対 mini-LVDS 300M──> 24×ICND2260
```

## 🔴 四条本轮自己定的协议/架构决定 (手册上没有, 别当成抄来的)

1. **13 対 = 12 数据 lane + 1 校验 lane**。beat 从 26 像素变 **24 = 8 个完整 3 像素组**,
   3 beat = 1 字槽 ⇒ **分发路由退化成纯布线零 mux**, 白捡一条 CRC-8 lane。
   ⚠ 不变量: 要与"24 链 × 3 lane"对齐, 26 字节里最多用 24 ⇒ **换任何摆法都是 9.45 Gbps**
   (13 lane 跨 beat / 12+1 / 平面优先 26=24+2 三种算出来一模一样) ⇒ 余量只能从"少发像素"来。
2. **216 = 6 × 36, 填充均摊到每颗 4 个通道**(不是堆在最后一颗)。堆着会让含填充的字槽只剩
   20 条链要数据(60 字节), 破坏 24 字节对齐。均摊 ⇒ 整槽不发, 丢整数个 beat。
   链路每帧每颗发 **1728** 字槽, 桥片每行末尾**本地补 4 个黑字槽**给芯片(芯片要收满 1920)。
   🔴 **落到 PCB: 每颗 2260 有 4 个通道不接 LED, 每颗一样。**
3. **时基主控归 DR1**: 屏的每一帧由上行带内 `frame_start` 触发, `icnd2260_seq` **不许自走**。
   两端频差被帧间空隙吸收(屏一帧 104.8 µs vs DR1 帧周期 110.6 µs, 余 5.5%), 不进链 FIFO。
4. **DR1 必须按链路满速突发一帧(1728 槽/105.3 µs)再空闲**, 不能均匀发。
   代数原因: 均匀发时 `R = 1728/110.6 = 15.62` 使 `S_min ≡ S_max`(110.6 × 15.62 ≡ 1728)
   ⇒ **预存量只有唯一解、零容差, 是退化解**。突发才有窗口。
   ⚠ 帧间空闲**必须发训练码型不能停发**(源同步链路停发没边沿)。

## 预存量 START_SLOTS 与 FIFO 深度 (两次算错的地方)

```
R_link = 1728 槽 / 105.3 µs = 16.41 槽/µs        T_tx = 1920×8/dclk
S_min = 1728 − R_link × T_tx        S_max = (T_dr1 − T_tx) × R_link
```
🔴 **上界要按链路填充速率算, 不是按屏侧消费速率**(用消费速率会算出 154, 偏大 15%)。

| dclk | T_tx | 窗口 | 默认 |
|---|---|---|---|
| **150.000**(主) | 102.40 µs | **[48, 134]** | **90** |
| 166.667(备选) | 92.16 µs | [216, 302] | 切档必须同时改 |

`BR_FIFO_SLOTS = 384`(原写 64 是错的, 漏了"tx 排空比链路填充快 13 µs"这个主项;
实测深度 64 每帧丢 10% 像素、384 零欠载)。**加深度不花钱** —— 33 块 bram9k 是**宽度驱动**
(`3 × ceil(192/18)`), 一块 x18 管 512 深。

## 🔴 三条踩到并修掉的真 bug

- **改 EG4 PLL 的分频账前, 先看清 `FEEDBK_PATH` 的反馈点在 C0 分频前还是后** (2026-09-07 踩过):
  `FEEDBK_PATH="CLKC0_EXT"` ⇒ 反馈取自 **C0 分频之后** ⇒ `VCO = PFD × FBCLK_DIV × CLKC0_DIV`,
  不是 `VCO = PFD × FBCLK_DIV`。看错会把 `FBCLK_DIV` 算大一倍, VCO 直接越出 300~1200
  (实测 100×8×2=1600), 而 **TD 不一定拦** —— 它照样布通出 bit, 只是把 pclk 推到 2 倍频,
  症状是 `pclk → pclk` 突然冒出上千个违例端点。判据: 看 `final_timing.rpt` 的 Clock Summary,
  pclk/sclk 的频率对不对得上设计值。

1. **真视频能触发假 SYNC**: 收端只看"13 lane 同时 0x35"不校验紧跟的 0xCA。穷举证明
   `d[0..11]=0x35 且 d[12..23]=0x05` 时 CRC 恰好 = 0x35 ⇒ 平坦灰度可复现, 最多 63 beat 错位。
   对照实测: 旧判据丢 197/1509 beat, 加两字判据后丢 0。
   结构性论证: 净荷较晚字周期 lane12 = `chk_late ≤ 0x0F ≠ 0xCA` ⇒ 不是降低概率是彻底消除。
2. **给视频通路加流水会把配置包一起延掉**: `tx_array` 沿用了 `icnd2260_lvds_tx_opt` 的隐式约定
   "配置字取 `pl_data[15:0]`", 而配置来自没被延的 seq、视频来自被延的 dispatch ⇒ 第一版报
   **5,373 处数据不同**。拆成独立 `cfg_data` 端口后修好, 副作用是好的:
   **SPEC 那个"注入点 2:1"变成 0 LUT**。⚠ 这条隐式约定值得回写进 opt_tx 注释。
3. **`DCLK_MHZ` 曾静默失效**: 顶层与 `bridge_clk` 有同名参数, 只改后者的默认值会被顶层实参覆盖
   ⇒ 日志说工作点已改、报告里 dclk 没变。判据"核对 dclk 实际频率"救了整批数据。

## 🔴 两条负结果 (别再试)

1. **在末端复制读侧状态拆扇出**: `oreg` 切 4 子块各带一份状态 + `dont_touch` ⇒ 扇出 104→105
   **一点没降**, SWNS −0.113→−0.351, 白花 173 LUT4。根因: `dont_touch` 加在**寄存器**上
   挡不住 TD 把 4 份等价的 **CE 组合锥**合并回一份。
2. **过约束有上限**: 150 档 SDC 按 166.67 写能把 SWNS 从 −0.253 提到 −0.113(有效);
   但 166 档按 185 写反而掉到 −0.859。

## 有效的三招 (通用, 与器件无关)

- **把只在某个使能拍变化的比较提前一拍寄存掉**(`blank_cur/blank_nxt`), 白送下一拍的值 ⇒
  组合锥里不再有比较器。这一招把 −0.050 变成 **+0.100**。
- **共享控制器 + 逐 lane 数据通路**(tx_array `CE_PIPE`): 15 根选通每 8 链复制一份 + 数据同延一拍,
  逐拍等价, +412 FF 换 −960 LUT。24 链下选通扇出 ~1,152 就是靠它修掉的。
- **把地址计算从使能信号上摘下来**(`q_fetch` 只看寄存器) ⇒ 砍掉 `slot_next → addrb` 4 级 LUT5。

- ✅✅ **PLL refclk 吃得下 400 MHz —— 2026-09-08 E104 上板实测, 结案** (原为"唯一还能推翻引脚定案的未知数")
  上行走 PLL(方案 A): DR1 转发 **400 MHz** 半速时钟 → `REFCLK_DIV=4` → PFD 100
  → `FBCLK_DIV=4` × `CLKC0_DIV=2` → VCO 800 → sclk 400 / pclk 200(`CLKC1_CPHASE=DIV` 得 180°)。
  **⇒ 方案 A 定案, `UL_FWD_MHZ=400` 确认, PCB 上转发时钟対按 400 MHz 走。**

  **怎么验的**(工程 `dr1v90/eg4_pll400/`, 器件 EG4X20BG256 / E104, 不用改板, 一対飞线):
  板载 50 MHz(H3) → PLL_A(×8×2 ⇒ VCO 800) → C0 400 MHz → ODDR → bank1 真差分 `LVDS33`
  `B15/B16`(J4.50/49) ──飞线──> `B14/A14`(J4.54/53) = `BE19` = `GPLL0_CLKIN`
  → PLL_0 用**与桥片同一组分频比**再锁一次。

  | 探针 | 球/J4 | 期望 | **实测 2026-09-08** |
  |---|---|---|---|
  | `probe_ref_div` 基准 | E16 / J4.45 | 48.83 kHz | **47 kHz** ⚠ 见下 |
  | `probe_lock` | C15 / J4.48 | 高 | **高** ✅ |
  | `probe_c1_div` ★主判据 | E15 / J4.46 | **195.3 kHz** | **195.3 kHz** ✅ 分毫不差 |
  | `probe_ok` 数秒法 | F15 / J4.44 | 高 | **高** ✅ |

  ### ⚠ 基准脚读到 47 kHz(低 3.7%) —— 为什么它不影响结论

  🔴 **先说清 `probe_ok` 证明了什么、没证明什么**(这一步容易想当然):
  整条链 `clk50 → PLL_A(×8×2, C0=÷2) → 飞线 → PLL_B(÷4 → ×4×2, C1=÷4)` 的分频比是**固定**的
  ⇒ **`f_C1 ≡ 4 × f_clk50` 恒成立, 与 clk50 的绝对频率无关**。
  所以数秒法那个计数**必然**是 200,000,000, **不管晶振是 50 MHz 还是 48 MHz**。
  ⇒ **`probe_ok` 证明的是"分频链配对了"(PLL 锁在正确的倍数上, 没锁错谐波),
     它本身并不能证明 `pllin` 真的是 400 MHz。** 要坐实 400 这个数字, 靠下面三段:

  1. **晶振容差 —— 决定性的一段**
     ```
     47 kHz 反推 ⇒ clk50 = 48.1 MHz ⇒ 偏差 −3.7% = −37,000 ppm
     晶振规格   ⇒ ±50 ppm 量级(哪怕最差的振荡器也就 ±100 ppm)
     ⇒ 需要偏出规格的 740 倍
     ```
     **晶振不可能偏 3.7%。** ⇒ clk50 必是 50.000 MHz ⇒ `ref_div` 必是 48.83 kHz
     ⇒ **47 kHz 只能是量具在低频端的读数误差。**
     (这不是"仪器不该只偏一个脚"那种概率论证 —— 是**另一种解释在物理上不成立**。)
  2. **两探针由构造锁死 4:1** —— `probe_c1_div / probe_ref_div ≡ 4.000`, 与晶振无关。
     实测比值 `195.3 / 47 = 4.155`, 偏 3.9% ⇒ **两个读数至少有一个是错的**;
     而其中一个(195.3)**恰好等于设计值** ⇒ 错的是另一个。
  3. 三段合起来: clk50 = 50.000 MHz ⇒ `pllin = 8 × 50 = 400.0 MHz` 真的进了 refclk 脚,
     `lock` 高 + 数秒法过 ⇒ **PLL 在 400 MHz refclk 上锁住且分频正确**。

  ### 🔴🔴 本次**没有**验的两件 —— 上板前必须补, 别被上面的 ✅ 盖住

  1. **PLL 环路参数仍是照抄厂家 EG4D20 实例**(`GMC_GAIN/ICP_CURRENT/KVCO/LPF_*`)。
     要用 TD IP Generator 按 **`FIN=100`(PFD 频率, 不是输入脚的 400)** 重生成。
     本次只证明"锁得上且分频对", **锁得稳不稳没测**。
  1b. 🔴 **5R 网络的幅值预测跨 365~481 mV, 三处文档互不一致, 只有上板实测能定。**
     `365`(按 VOH/VOL 最坏角) / `432`(接线方案表) / `455`(3R@3.3V × Rpd 的 0.895 衰减) /
     `481`(完整并联, 载 = 140∥860∥100) —— **散布近 1.3 倍**。
     🔴 而「幅值 < 500 mV 才能用片内端接」那道门槛就在旁边: 按 481 算只剩 **19 mV**。
     ⇒ 上电后必须**实测** `|VID|`(判据 100~600 mV), **实测 > 500 mV 则片内端接不可用**。
     **根源**: 厂家的 `150/140` 档位是按 **`LVDS25_E` 的 VCCIO = 2.5 V** 设计的
     (2.5V+3R ⇒ 385 mV, 正落在 LVDS 标称 350 附近); 而 E104 的 bank0 **焊死 3.3V**
     ⇒ 幅值先天大 **1.25×**(= 481/385)。**最终桥片板自己设 2.5V + 3R 就没这个问题**(385 mV, 离门槛 115 mV)。
     ⚠ **不是 1.32×(电压比 3.3/2.5)** —— 负载也变了: `Rpd` 串联的 860 Ω 跨接把差分负载
     从 `140∥100 = 58.33` 拉到 `140∥860∥100 = 54.63`, 抵掉一部分电压增益。

  🔴 **单独记一条通用规则: `Rpd` 同时在共模和差分两条路径上, 两条账都要进。**
     · `RP` 共模下两端等电位 ⇒ 不载流, **只进差分账**
     · `Rct`(变体) 差分下中点是虚地 ⇒ 不载流, **只进共模账**
     · **`Rpd` 两条都进** —— 共模看 `430∥430 = 215 Ω`, 差分看**串联 860 Ω 跨接**
     这条 2026-09-08 一天内被漏掉**两次**, 方向相反:
       ① 选变体半值时把差分目标当成 `RP = 140`(漏了 860 并联) ⇒ 差点选 68 而不是 62
       ② 算 3.3V/2.5V 幅值比时只看电压 ⇒ 写成 1.32× 而不是 1.25×
     ⇒ **共模路径与差分路径必须分别算, 同一只电阻可能同时出现在两条里、权重还不一样。**
     ⚠ 与下面那条抖动是同一类: **纸面预测与实测之间还没有校准过**。

  2. **抖动完全没测。** 本次是**板上自产自收的几毫米飞线**, 与真链路(DR1 板 → 连接器 →
     桥片)不是一回事: 真链路要吃板级 skew、対间偏斜、连接器不连续、发送端抖动。
     ⇒ **"E104 上锁得住"不等于"整机链路上锁得住"**, 抖动预算要单独算并复测。

  ⇒ 退路作废但留档: 若将来要降速, C 把 `uplink_tx_frame.v` 的 `fwd_clk` 由 `4'b0101` 改
    `4'b0011`(= 200 MHz), 桥片侧只需 `UL_FWD_MHZ=200` ⇒ `REFCLK_DIV` 自动变 2, 其余不动。

## 🔴 并行开工的一条教训 (下次照做)

**TD 构建是单机独占瓶颈, 不是可以随便并发的东西。** 本轮四个包并行时:
- 工作包 D 同时跑 4~5 路种子/频率扫描把机器占满 ⇒ 别的包每次 `./build.sh real` 要 **20~40 分钟**;
- 于是要实测数的包排了 6 次构建 + 7 次全量 TB, 光等就烧掉 **~670k tokens / 3h39m**(其中真正的
  RTL 工作是小头);
- 更浪费的是**轮询太碎**: `build.sh` 的 `tee` 有缓冲、日志到最后才落盘, agent 反复
  `sleep + grep` 去看, 一次没看到就再来一次。

⇒ 下次: **同一时刻只让一个包跑 TD**(其余包先做 RTL/TB/文档), 构建**只挂一个阻塞等待器等通知**,
不要 sleep+grep 轮询; 需要多点数据时由**一个包统一排队跑完再分发结果**, 而不是各包各跑各的。
⇒ 另: `build.sh` 值得加一个"构建完成"的标记文件(或 `stdbuf -oL`), 让等待有确定的判据。
