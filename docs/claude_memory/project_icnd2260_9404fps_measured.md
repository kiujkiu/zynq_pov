# 单颗 2260 实测 9,404 fps, 芯片一帧不丢 (2026-09-02)

## 结果

```
快门      曝光    第一颗亮区占比   折合相位   推算显示帧率
1/2000   500 µs      58.8%       4.70/8      **9,404 fps**   ← 发送 9,310, 差 1.0%
1/4000   250 µs      38.3%       3.06/8      12,244
1/8000   125 µs      24.7%       1.98/8      15,802
```
⚠ 三档比值是 1.54 而非 2 ⇒ **手机高速档没真正做到标称快门**(1/8000 实际约 1/4700),
**以 1/2000 为准**。另: 脚本自动分割出的色块宽度三张为 596/425/404 px, 第一张偏大,
那个 58.8% 有系统误差可能, 但三张同向同量级, 结论不依赖单张。

## 达成这个数的配置

```
bit    build_dbg_cas1_f143_np/icnd2260_lvds_dbg_div7_cas1_f143_np   WNS = -0.471(=基线, 零真实退化)
构建   tools\build_bit_dbg.tcl -tclargs 7 lvds casc1 f143 noprobe
时钟   DCLK 142.86 MHz (CLK_DIV=7, VCO_MULT_X8=160)
寄存器 0x00 = 0F3C  (16 刷新分组, N=8)      0x06 = AA44 (出厂, P/M=0.5)
       ⇒ GCLK = 142.86 × 0.5 × 8 = 571 MHz (上限 600, 未超)
       ⇒ 显示能力 = 571e6/(45×16×52) = 15,257 fps
链路   帧内容 15,270 拍 ⇒ 上限 142.86e6/15,270 = 9,356 fps  ← 真正的瓶颈
图案   dbg_pat_mode=7, NSTRIPE=8 (每条 5 列)
```

🔴 **`0x06` 在高 DCLK 下必须保持出厂 AA44**: 若照搬 62.5MHz 时的 AA48(P/M=1.0),
GCLK 会到 1,143 MHz, 超上限 1.9 倍。

## 量法(唯一可行的, 见 [[feedback_time_average_cannot_measure_display_rate]])

帧相位条纹 + 短曝光拍照 + **从像素算亮区占比**(不要目测、不要数细线):
灰度化 → 取有光的行带 → 列平均亮度 → 阈值 → 统计第一颗色块内亮列占比。
`显示帧率 = 占比 × 相位数 ÷ 曝光时间`。

**量具已上板验证**: 4 fps 下一圈正好 2.0 秒(8相位÷4fps)、每次亮 5 列(40÷8), 两个数精确命中。
⚠ 亮带**每帧跳一格**, 跳格速度 = 发送帧率(不是帧率÷相位数)。

## 🔴 修正 (2026-09-02 17:53): 155.36 MHz **是通的**, 之前那条"全黑"作废

早先记的「155.36 MHz 屏全黑 ⇒ 链路上限在 142.9~155.4 之间」**是错的**, 错在没排除两个自造干扰:

| | 那次失败的配置 | 修正后 |
|---|---|---|
| 读探针 | **开着** —— 每 3.3ms 停 56µs DCLK, 每秒 300 次 ⇒ 全链 PLL 反复失锁 | `noprobe` 关掉 |
| `0x06` | `AA44` ⇒ GCLK = 155.36×0.5×8 = **621 MHz, 超 600 上限 3.5%** | **`AA43`**(P=3) ⇒ GCLK 466 MHz ✅ |

【实测】改正后 155.36 MHz **画面正常**, `SENT = 10,344 fps`。数字自洽:
`noprobe` 去掉探针后帧内容 15,270 → **14,755 拍**, `155.357e6/(14,755+265) = 10,343` ✓

⇒ **首次跨过 10,000 fps。** 155.36 MHz 下链路上限 = `155.357e6/14,755` = **10,529 fps**。
⇒ 手册 DCLK 上限 170 MHz ⇒ 理论 **11,522 fps**。

**教训: 拿"失败"当结论之前, 先排掉自己造成的干扰。** 那次失败同时叠了两个我自己引入的问题,
而我据此推出了一个错误的上限区间, 并基于它做了后续决策。

## 🔴 再刷新 (2026-09-02 18:02): **11,000 fps @ 166.67 MHz, 画面正常**

```
bit    build_dbg_cas1_f167_np/icnd2260_lvds_dbg_div6_cas1_f167_np
构建   tools\build_bit_dbg.tcl -tclargs 6 lvds casc1 f167 noprobe
DCLK   166.67 MHz  (CLK_DIV=6, **VCO_MULT_X8=160 = 原生 1000 MHz**)
0x00=0F3C  0x01=0020  0x06=AA43 ⇒ GCLK = 166.67×0.375×8 = 500 MHz (上限 600 ✅)
显示能力 500e6/(45×16×52) = 13,354 fps    链路上限 166.67e6/14,755 = 11,296 fps
SENT = 11,000 fps 【实测】, 屏正常
```

**⚠ 意外发现: 166.67 MHz 的时序比 155.36 更干净**
```
166.67 (CLK_DIV=6, VCO 1000 原生)  WNS = -0.470  ← 正好基线, **零真实退化**
155.36 (CLK_DIV=7, VCO 1087.5)     WNS = -0.695  ← 0.22 ns 真实违规
```
⇒ **为了凑非整数频率去拉 VCO, 反而付了时序代价。优先用原生 VCO 1000 的整数分频档。**
