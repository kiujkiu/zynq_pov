# ACK 一帧都没收到过 (2026-09-09 复盘)

**ACK 是"芯片到底活没活"唯一的自动判据, 而它从未工作过。** 验证板要一次把 12 路都做起来,
等于第一次让这个功能真正工作。

## 三次场合, 三种失败模式

| 场合 | 观测 | 原因 |
|---|---|---|
| 08-19 鹿小班首测 | `ack_frame_cnt = 0` **且** `ack_err_cnt = 0` | 两个都是 0 **有判别力**: 协议/CRC 错会是 frame_cnt 涨但 crc_ok 不亮, 噪声会是 err_cnt 涨 ⇒ **指向物理层**。20 M 也不通 ⇒ 与速率无关 |
| 08-20 排查中 | 垃圾帧 **18,245 帧/秒**, 而每秒只问 83 次 | ① ACK 引脚**没上拉**(手册规定空闲为高, 悬空 CMOS 放大耦合噪声) ② 读寄存器的 **DEVICE 写死成 0xF**(手册 `4'b1010` 是"读**指定**设备, 不支持广播", 第 1 颗 = 0) ⇒ 一直在点名第 16 颗。**两个 TB 都没抓到, 因为它们复制了同一个误解** |
| 08-20 修完重扫 | 有效回包**全 0**; 残留错误率 **≈669/s 且与设备号无关** | 669 对得上 `I_SYNC` 的 662 Hz, 而 **ACK(J1.22) 与 SYNC(J1.23) 在连接器上相邻** ⇒ ACK 悬空被邻线拽动, **屏侧没有任何东西在驱动它** |
| 单芯片 fps 扫描 | 10/10 次 `ack_cnt = 0` | "这块屏没接线" |
| 08-20 FS03 | 假计数 **5 万次/秒** | DCLK 串扰(单变量对照: DCLK 恒 0 时 0/s), 病根 J1.21/22 紧邻无地 |

🎯 **反过来基本排除了"协议不认"**: 芯片只要活着且 ACK 通到 FPGA, 推挽输出会把线钉在空闲高,
邻线那点耦合拽不动。⇒ 嫌疑收窄到 **ACK 物理通路没建立**(线没通 / 245 方向或供电 / VDDD 没上来 /
**RSTN 被摁住** —— 当时头号嫌疑是"Altium 转接板 J1 上根本没有 RSTN")。

## 🎯 08-20 那条方法论教训

那组"找到 7 颗级联芯片"(dev 4/5/6/7/13/14/15 都有应答、data0 有值)的垃圾数据**长得极像真结果**,
差点据此去协议层排查一整天。**戳穿它的是速率 —— 回包不可能比提问还多。**
⇒ **任何"应答数 > 提问数"的观测, 先怀疑量具不是被测物。**

## 🔴 接收器无门控 —— 现在就能修

`icnd2260_ack_rx` 端口只有 `clk / rst_n / ack_pin / crc_refl`, **没有 enable** ⇒ 任何时候线上的
毛刺都会被当成 start 解析。这正是上面那些假计数的放大器。

而 ACK **只在读寄存器时有活动**(手册注 2: "对于读操作 CMD=0b1010, 则没有数据域, 读取返回的数据
通过 ACK 传输"; `Display Data`/`VSYNC`/`Write Register`/`Correction Data` 都不产生 ACK)。
⇒ 顶层加一行即可(空闲是高, 门控值取 1), **不用动模块内部**:

```verilog
assign ack_gated = ack_rd_window ? ack_d[sel] : 1'b1;
```

窗口从"发出读命令"拉起, 到"收到帧或超时"落下。把串扰问题从"只能靠布线解决"降级成"布线 + 门控双保险"。

## 改板恰好解掉三条根因

① **物理通路** —— 以前 LED 板是供应商客户样板、拿不到原理图、ACK 在屏侧根本没接; 现在灯板自己改,
ACK 从每颗 `B4` → mux → 邮票孔 → FPGA 全程自己画。
② **RSTN** —— 接口里有 `panel_rstn` 引到 FPGA, 灯板侧另加 10 kΩ 下拉。
③ **邻线耦合** —— 邮票孔每対夹地、单端区插地; ACK 走线要求远离时钟対。

⚠ 仍要确认: **DEVICE 编号那个 bug 修掉没有**(第 1 颗 = 0, 不是 0xF), 且 **TB 要跟着改** ——
原来两个 TB 只查了写指令的 DEVICE。

## ACK 协议速查 (手册 P12 + `icnd2260_ack_rx_serial.v`)

脉宽调制: 空闲高 → start 低 >1 µs → 每位先高 w1 后低 w2, **w1 > w2 判 1**, 每位 1 µs < w1+w2 < 5 µs
→ 帧尾高 >10 µs。帧 = `ACK[3:0] | DEVICE[3:0] | OFFSET[7:0] | LENGTH[7:0] | DATA… | CHKSUM[15:0]`,
**CRC-16, CHKSUM 从 LSB 先回传**, 帧长 <56 位判太短。速率 200 kbps~1 Mbps, 一帧 56~280 µs。
🔴 判决基于**脉宽** ⇒ 串扰毛刺会被直接误判成位边界, ACK 走线必须远离时钟対、全程有地伴随。
