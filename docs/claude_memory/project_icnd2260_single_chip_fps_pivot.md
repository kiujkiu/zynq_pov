# 转向: 只测单颗, 不再折腾级联 (2026-09-02 下午)

## 用户的决定

> 「目标是测 40x45 单个 2260 帧率上限, 先不折腾这个级联了, 在第一个屏幕测帧率,
>   不考虑级联的事了, 做 8x8 分割的棋盘格, 做带色深的」

## 为什么这个方向对

- **链路不再是瓶颈**: 单颗每帧 1800 字 x 16 bit = 28800 bit。
  链路上限 = `2 x DCLK / (CASCADE x 1800 x 16)`
  ⇒ 62.5MHz 单颗 = **4340 fps**(9 颗时只有 482), 100MHz 单颗 = 6944 fps, 170MHz(手册上限) = 11806 fps
- ⇒ **剩下唯一的约束是芯片自己的显示帧率**, 而它 = `扫描数 x 刷新分组数 x Line_len / Q`,
  **与级联颗数无关**。实测 62.5MHz + 32 分组 = 398 fps。
- ⇒ 要涨帧率只能**降刷新分组数 / 抬 GCLK**, 而**降分组数直接掉色深**。
  🔴 **带色深的棋盘格就是用来量这个代价的** —— 否则帧率涨了却不知道换走了什么。

## 几何

40x45 除不尽 8x8。**5x5 的格子排 8 列 x 9 行 = 72 格正好铺满**(40/8=5, 45/9=5)。
72 级灰阶。若要严格 8x8 则底部留 5 行做参考条。

## 为什么用"第一颗"

【实测】**失效永远不在第 1 跳** —— 它直接吃 FPGA 出口眼图(全链最差控的一只眼)却从不坏,
坏的总是芯片自己再生转发的第 2~9 跳。见 [[reference_icnd2260_startup_writes_table_66_times]]。
⇒ 第一颗是当前唯一 100% 可靠的被测物, 拿它测帧率不会被级联的概率性失效污染。

## 级联问题的收摊状态(供以后回来接)

| 观测 | 结果 |
|---|---|
| div48 (20.8MHz) | ✅ 9/9 可靠。但内部刷新只有 ~60Hz, **肉眼可见闪烁, 连正常显示都不合格** |
| div16 (62.5MHz) | 概率性, 2~6/10, 永远是链头连续一段 |
| 全黑加压 vs 彩色加压 | **彩色(满电流)反而更稳** ⚠ 但全黑同时=全零数据无跳变, 不干净 |
| 半电流 vs 满电流 (0x2d/3d/4d IREF) | L 组 10 轮跑完(多数成功、也有失败), **H 组只跑了 3 轮就暂停, 无结论** |
| ACK | 这块屏没接线, 10/10 次 ack_cnt=0, **没有自动成功判据** |

补做的话: `hw_ab_iref.tcl ... 10 build_dbg_ph28.125 HL`(倒序, 顺便排除顺序混淆)。
