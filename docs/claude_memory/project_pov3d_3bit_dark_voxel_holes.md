2026-08-24 用户提出「颜色低于某阈值就完全没有空间点显示了」的猜想，定量证实成立。

量化链路 (`tools/gen_anime_slices.py:to_3bit`):
```
x = 7·v^gamma          想要的码值(带小数)
code = floor(x + d)    d = Bayer4 ∈(0,1), 均值 0.5
⇒ P(code=0) = P(d < 1-x) ≈ 1-x    当 x<1
⇒ 洞率 = 1 - 7·v^gamma,  无洞临界 v = (1/7)^(1/gamma)
```

| gamma | 临界亮度 | v=20% 洞率 | v=30% |
|---|---|---|---|
| **2.2 (现役)** | **41.3%** | **79.7%** | 50.5% |
| 1.8 | 33.9% | 61.4% | 19.8% |
| 1.4 | 24.9% | 26.5% | 0% |

⚠ 抖动是**无偏**的（`E[code]=x`），所以平均亮度对 —— 但那是靠「大部分体素灭、
少数点亮」实现的。面因此变成稀疏点阵，正是用户说的「一个披风本来是个面，
很多点就不存在了」。

## 推荐解法: 覆盖区重映射到 [1,7]，用 max 通道定标

```
covered:  x_max = 1 + 6·Lmax    其余通道 x_c = x_max·(L_c/Lmax)   ← 保色相
vacuum:   x = 0                                                    ← 真空仍全黑
```
洞率 0%，真空仍黑，暗部渐变保留（硬垫底 `max(1,code)` 会把暗部压成一片死灰）。
代价：最暗的物体固定在 1/7 = 14% 亮度。

🔴 **不要按通道设下限** —— 深蓝 `(0,0,0.4)` 垫成 `(1,1,3.4)` 会让整个暗部褪色发灰。
**存在性是几何属性不是颜色属性**。

## 实现前提 (已查证)

`gas.render_slice` 是**最近邻**取样 (`np.rint`)、子角度间用 `max` 混合 ⇒
**当前管线没有抗锯齿，覆盖是干净的二值**，`img.max(axis=2) > 0` 就是覆盖 mask，
不用改渲染器。

⚠ 但这也意味着**下限和抗锯齿会打架**：一旦加了抗锯齿，判据就得从 `>0` 改成
`coverage > 0.5`，否则半覆盖的边缘体素被抬到 14% 会让物体**变胖一圈**。
先后顺序上，现在加下限是安全的。
