# DDR 的两堵墙, 和一步解两墙的那一手 (2026-09-02 整理)

## 🔴🔴 2026-09-02 晚 五路复核: 本文下面的账**有两个数是错的**, 且结论从"稳过"降为"擦线"

| 项 | 本文原值 | 复核后 | 为什么错 |
|---|---|---|---|
| ① 体素读(直供) | 1.13 GB/s | **1.50 GB/s** | 1.13 是 fold-a 口径(面A 存半圈镜像复用, 25 MB); **直供拓扑没有那个存储**(7020 全部 BRAM 630 KB), 每个显示片都重渲 ⇒ 1206 片/圈 × 82,944 B × 15 = 1.50 |
| "只剩 ① 占有效 53%" | 53% | **占峰值 70% / 占"有效"101~117%** | 53% = 1.13/2.133 **分母是峰值不是有效**, 分子还套了用不上的 fold-a |
| "内容 5 Hz 省 DDR" | 3.77→2.26 | **对直供零影响**(只省 3~7%) | 直供是即时渲染, 读频率 = 片频率 = 9,045/s/面, 与内容更新无关 |
| fold-a 面A 302 片 | — | **不可实现** | 603 是奇数, FOLD_A RTL 要偶数 |
| csynth 69.1 µs | 预期值 | **下界** | 假设 IP 读口 1.2 GB/s 持续(一个 HP 口 100%); 两 IP 同时 = 2.4 > 2.133 峰值, 物理不可能 |
| 片上双缓冲 | 83 KB | **331 KB** | 83 KB 是一面一片; 双面×2 bank = 331,776 B = 2.65 Mb, 72~96 个 RAMB36 |
| 三流合计 | 3.77 | 3.752 | 1.5005 四舍五入 |
| 容量 | 143~174 MB | 131.9~141.9 MB | 十进制 MB 对二进制 MiB; "174 上界"全仓库无出处 |
| 缺一片视觉代价 | −50% | **−25%** | 每体素每圈被扫 4 次(面A θ/θ+180°, 面B 两次) |

### 判定: **有条件 GO**
```
面板端  ✅ 今天实测 11,000 fps, 每片 88.5 µs < 110.6
片上端  ✅ **已做出来**: zynq_pov/icnd2260/ppbuf/ (slice_ppbuf.v 乒乓+相位锁+跨域, slice_feed.v,
           pat_writer 顶替渲染 IP), iverilog 5 段判据 PASS, 布线出 bit, 2 RAMB36 —— **未上板**
DDR 端  ❓ 由**一个实测数**决定: DDR 对"432 B 散布突发读×2 路"的读效率 η
           需 η ≥ 0.70(裸) / ≥ 0.84(留 20%); 记忆里"有效 1.28~1.49"= 峰值×0.6~0.7 **是假设, 全库零实测**
```
🔴 **决定生死的实测**: FS03 上跑 `hls_proj/pov_slice_v2` **两个实例并发**, ap_done 计 603 片墙钟
→ µs/片, 判据 ≤110 µs 且两路同时。不用新 bit。

### 三条零 BOM 变体(任一成立即"稳过", 可叠加)
| 变体 | ① 降到 | 峰值% | 代价 |
|---|---|---|---|
| **V1 两面共面穿心(垂距 0)** | 0.75 | **35%** | 机械决策, **一把卡尺**; 现役 v3.1 偏心 13.4 mm; 判决早列为第 4 项 |
| V2 相邻片列复用 | 0.83 均/1.09 最坏 | 39/51 | 改渲染 IP 内核几百 FF; 内容切换时强制全读 |
| V3 8-bit 调色板体素 | 0.75 | 35 | 色深 256 级 |

**no-go 边界**: η < 0.70 且 V1/V2/V3 全否 ⇒ 16-bit DDR 板上不成立。
**但仍比原拓扑好**: 原三流 3.75 在任何 η 下都超峰值 1.76×; 直供压到 1.50, 从"不可能"变成"要实测"。

### 必须同时成立的条件
C1 DDR η 实测达标 | C2 渲染 IP 读请求要提前 2 列发(现在只提前 8 拍, 空载即擦线) |
C3 序列器每 64 帧整表刷新拆成滚动 ≤16 寄存器/帧 | C4 体素必须 RGB565(3 B/px 则任何 η 都死) |
C5 面板拼板(192/40、216/45 都 = 4.8 非整数)要用户拍板

**可推广**: 一份账里"分母用峰值还是有效"和"分子的口径(fold/不 fold)"这两处一错, 结论就从
"稳过"翻成"擦线" —— **任何 GB/s 数字都要标清分子口径和分母口径。**

## 墙③ 带宽: 切片在 DDR 里走了个来回

| 流 | 方向 | GB/s | 来源 |
|---|---|---|---|
| ① 体素读 | 渲染 IP ← DDR | 1.13 | 判决表 |
| ② 切片写 | 渲染 IP → DDR | ~1.13 | 3.77 − 1.505 − 1.13 |
| ③ 面板取片 | 面板 ← DDR | **1.505** | 自验: 9,045 fps × 41,472 px × 2B × 2面 = 1.50 ✓ |
| **合计** | | **3.77** | |

板子: 峰值 **2.13**(7020 与 DR1 打平, 都是单颗 16-bit), 有效 **1.28~1.49**。
🔴 **光③一条纯读流就占有效带宽的 101~118%。**

## 墙⑥ 容量: 大头是切片缓冲

```
切片缓冲  603 片 × 2 面 × 41,472 px × 2 B = **100 MB**
体素网格  192×216×192 × 2 B = 15.9 MB, 双缓冲 31.9 MB
其它      ~10 MB
合计      **~143 MB**   vs   DR1 CMA 实测 **96 MB**  ⇒ 差 1.5×
```

## 🎯 一步解两墙: 切片不落 DDR

**渲染 IP 直供面板, PL 片上双缓冲 83 KB。**
```
带宽:  砍掉 ② + ③ = 省 **2.63 GB/s**, 只剩 ① 1.13
       ⇒ 占有效带宽 **53%**  ✅ 连现役 16-bit 板都过
容量:  100 MB 切片缓冲消失, 只剩体素 32 MB
       ⇒ 96 MB CMA 绰绰有余  ✅
```
**零 BOM 成本, 不换器件。**

### 代价
- 变成**硬死线架构**: 渲染必须与转子相位硬锁, 失去 DDR 这个弹性缓冲
- 渲染慢一帧 = 屏上直接缺一片, 没有补救
- 每片预算 1/9,045 = **110 µs**; 渲染 IP csynth 报 69.1 µs/片 —— **但从未上板**
  (且 [[feedback_hls_cycle_estimate_optimistic]]: HLS 估计曾乐观 14×)
- ⚠ **这个拓扑不在任何设计文件里, 零设计零验证。**

"面板这一端"已经是确定的, 不确定性只剩渲染那一端。

## 两条独立的减压手段(可叠加)

1. **内容帧率 ≠ 体帧率**: 转子仍 15 rev/s(30Hz 体帧率), 内容只 5 Hz 更新
   ⇒ 体素读 3.77 → 2.26 GB/s
2. **传体素表而非压缩切片**: 链路 108 Mbps@15fps / 36@5fps ⇒ 过
   ⚠ 但对现役 1-bit 屏反而更贵(262 KB vs 450~900 KB/帧), 只在 2260 目标上划算
