两块屏**正反背靠背、中间有 13.8mm 间距**，屏面不再穿过旋转圆心。对称安装（各偏 d/2 = 6.9mm）。

## 结论一：RAM 不用两块，RTL 一行没动

两屏关于轴对称 ⇒ **屏B@θ ≡ 屏A@(θ+180)** 严格成立（推导：屏B 在 θ 占的是「法向 θ、偏移 −d/2」
的平面 = 「法向 θ+180、偏移 +d/2」= 屏A 在 θ+180 占的平面）。所以：
- `PHASE_B=180` 机制原样有效
- DDR 仍只需**一份 360 片**，`02_dual_panel_arch.md`「数据零翻倍」结论成立
- 213.7 µs/片 带宽预算不受影响（半圈内 A+B 仍覆盖全部 360 平面，13 rps → 26 fps）

⚠ 但**冗余度变了**：穿心时 slice i 与 i+180 互为镜像（信息量其实只有 180 片，360 是冗余存法）；
有间距后 **360 片各不相同**。存储量没变，但「一半是冗余」的余量没有了。

## 结论二：切片采样必须改（已实现）

`tools/gen_anime_slices.py` 加 `--gap-mm`（默认 13.8），`render_slice()` 核心：
```python
# 旧 穿心子午面:  wx = D*cosθ            ; wz = D*sinθ
# 新 偏移平面:    wx = D*cosθ - off*sinθ ; wz = D*sinθ + off*cosθ
#   u=D 沿 û=(cosθ,sinθ) 保持旧约定不变, 垂距 off 走法向 n̂=(-sinθ,cosθ)
#   off = (gap_mm/2)/0.9375  → 13.8mm 时 = 7.36 px
```
等价极坐标 `R=√(u²+off²)`，`方位 = θ + atan2(off, u)` —— **一列像素不再共面**，
近轴处方位偏移极大（u=0 直接偏 90°，u=2px 偏 15°），旧的「u>0 半边=θ_i / u<0 半边=θ_i+180」错得离谱。

⚠ `--gap-mm 0` 必须逐字节退化回旧行为（u 沿 û 而非 t̂，否则整体转 90° 会破坏 angle_tracker 标定）。
验证方法：关抖动后 `slice_i` 与 `mirror(slice_i+180)` 应 **180/180 对逐像素相同**；gap>0 时应 0/180。

## 数字账 (gap=13.8mm, P0.9375 屏, 160×180)

| 项 | 值 |
|---|---|
| 每屏到轴垂距 | 6.90mm = 7.36 px |
| **中心盲区直径** | 13.8mm = **14.7 px** |
| 盲区占直径 / 占截面积 | 9.2% / **仅 0.85%** |
| 有效外径 | 74.85mm（穿心 74.53，只涨 0.32） |
| 整屏跨方位角 | **169.4°**（穿心正好 180°） |

盲区是几何固有、软件补不回来，但轴心是模型**内部**、外表面看不见，对角色模型基本无损
（除非有细长物体正好穿过中轴）。想减小只能缩小间距。

## 🔴 手性: --mirror-u 默认 ON (2026-07-27 上板实测)

屏 X 轴物理方向与代码假设的 û(θ) **相反**, 每片须对屏中心轴做轴对称。
`gen_anime_slices.py` 已把 `--mirror-u` 设为默认 ON (逃生门 `--no-mirror-u`)。

**为什么以前没发现**: 穿心几何下 `mirror(slice i) == slice i+180`, 手性错误**等价于相位转 180°**,
而相位本来就靠光电标定, 随便转多少度都能被吸收掉 → 手性错了根本看不出来。
有间距后 `mirror(slice_j)` 不再等于集合里任何一片 → 第一次变成肉眼可见的镜像。

⚠ 若转起来发现手性仍不对, 修法**不是**再翻 u, 而是翻转 θ 方向 (`θ → −θ`)。
这两者在有间距几何下**不等价**(偏移量会落到轴的另一侧), 需实测区分。

## ✅ 定案 (2026-07-28 电机转起来后实测)

**最终配置: host `--mirror-u` = ON (全局), RTL `mirror_b` = 0。两屏内容都是镜像。**

绕过的弯路: 中途误判成"屏B 需相对屏A 镜像", 为此在 RTL 加了 `mirror_b`(见下)。
实测两屏都亮、都要镜像 ⇒ 只需 host 那一次全局翻转, `mirror_b` 保持 0。

`mirror_b` 逻辑留在 RTL 里 (默认 0, 零影响), 机械结构变了随时能开。
⚠ 判断镜像**必须电机转起来**: 静止时屏A=slice i、屏B=slice i+180 本就是两个不同平面,
在两个不同截面之间比较得不出结论 —— 今天在这上面反复了很多次。

## RTL mirror_b (2026-07-28 新增, 备用)

寄存器 `0x10[4]=mirror_b`, 状态回读 `0x00[13]`, **复位默认 0**。
置于 **fb 写入侧** (只改屏 B 的 `fb_wlane`/`fb_waddr`), 屏 A 完全不动。
DDR 突发读仍线性 → **零额外带宽、零额外 BRAM 口、不用第二份切片数据**。

置换 (观察者 X→159-X 在打包域, 三条宽 53/53/54 **不对称**, 不是干净的行反转):
```
(lane基6, r) → (lane基0, 52-r)   r=0..52     左条↔右条
(lane基0, r) → (lane基6, 52-r)   r=0..52
(lane基3, r) → (lane基3, 51-r)   r=0..51     中条自映射, 常数 51 不是 52
(lane基3, 52) → (lane基0, 53)                ← 例外
(lane基0, 53) → (lane基3, 52)                ← 例外
```
按直觉写成"lane组对调 + row 取 53-r"会让中条整体偏 1 列并丢 2 个边界像素。
上板前用软件模型跑遍 9×54=486 格, 确认完备双射/无冲突/对合 才编译。

⚠ 若将来真要"屏B 相对屏A 镜像"且 host 侧不动: `mirror(slice_j)` 不在切片集合内
(翻 û 必然同时翻 n̂), 软件方案必须翻倍 DDR + 加 `slice_base_B` 寄存器; 用 `mirror_b` 则零代价。

## 待观察风险

同一体素在半圈内被 `u>0` 和 `u<0` 两次命中，两次机械角度相差接近 180°。
同一 3D 模型采样值一致所以没问题，但**视角相关着色会重影** —— 若启用了
[[feedback_hls_zbuffer_for_depth]] 那套 depth-fade / z-buffer，两次会给出不同值。转起来看到重影先查这个。

## 亮度到顶了吗 (2026-07-28)

**OE 占空已到顶**: `oe_window` 写 192, 引擎内部**箝位 [2,187]** (187 保证 LE 落在 OE 回高之后,
`icnd2047_panel_core.v` 硬约束, TB 有用例 `oe_window=200 clamped -> 187`)。
一行 195 拍 → **187/195 = 95.9% 占空**, 再写大没有意义。

**但单 LED 真实占空只有 1.78%**: 54 行顺序扫描, 每 LED 只亮 1/54 → `187/10530 拍`。
这是扫描架构固有代价。

**唯一剩余余量 = 驱动 IC 电流增益寄存器** (ICND2049/2047 内部, 靠 LE 长度编码指令配置),
现在跑的是**上电默认值, 从没配过**。⚠ 但 `pov_dual_top.v` 的手动命令通路
(0x00/0x04 + 0x0C subcmd01 per-chain 预载) **还没接进顶层**(文档标"遗留 v6 集成项"),
要配增益得先补这条通路。且调高前须实测电流 — 接口板 TPS54560 总闸 5A。

软件侧还可降 `--thresh`(默认 128) 让更多像素点亮, 代价是细节变糊。

## 🔴 2026-07-31 v3.1 偏心屏: 上面的对称等价**作废**

机械侧 (`D:\claude_workspace\macha\pov3d\v3.1\`) 把屏模组整体 +6.7mm,
让一面正好落在轴平面上 —— 动机是消掉中心 Φ13.4 盲柱。结果两 LED 面变成:

| 面 | 到轴垂距 | 盲柱 | 跨方位 |
|---|---|---|---|
| **A (贴轴)** | **0 mm** = 0 px | **无** | 180.0° |
| **B** | **13.4 mm** = 14.29 px | Φ26.8mm (占截面 3.13%) | 159.6° |

**两面不再关于轴对称 ⇒ 「屏B@θ ≡ 屏A@(θ+180)」不成立**
(A@(θ+180) 垂距仍是 0, 永远给不出 B 要的 13.4 平面)。
⇒ **`PHASE_B=180` + 单份 360 片喂两面 的全部依据没了**。已用 `check_meridian_mirror()`
数值验证: 垂距 0 时 6/6 对镜像恒等; 垂距 7.36(v3 对称) 与 14.29(v3.1 B 面) 均 0/6。

### 反向红利: A 面穿心 ⇒ 数据可减半

垂距 0 时 `slice_i ≡ mirror(slice_{i+180})` 严格成立 → **360 片里只有 180 片独立**。
且**体积帧率不变**: 穿心面每半圈扫过全部 180 个子午面 = 覆盖整个体积,
与老双面偏移装 (半圈内 A+B 覆盖 360 偏移平面) 等价, 都还是 **2 × 转速**。

| | 老 v3 对称双面 | v3.1 只驱 A 面 | v3.1 双面各一份 |
|---|---|---|---|
| 独立切片数 | 360 | **180** | 180 + 360 = 540 |
| 每帧 raw | 4.42 MB | **2.21 MB** | 6.64 MB |
| 压缩后 (33.7×) | 131 KB | **~65 KB** | ~197 KB |
| 30fps 线速 | 31.5 Mbps | **~16 Mbps** ✅ 低于 28 链路 | ~47 Mbps |
| 体积帧率 | 2×rps | **2×rps (不变)** | 2×rps |
| 亮度 | 基准 | **÷2** (每点每半圈只被扫 1 次) | 基准 |
| RTL 改动 | — | idx≥180 → 取 idx−180 + 镜像 | 加 `slice_base_B` + 双份 DDR |

⇒ **只驱 A 面 = 链路/DDR/CPU 全部减半且帧率不损**, 代价只有亮度减半;
这对 [[reference_anlogic_dr1_fs03_eval]] 的 DR1V90 30fps 账是决定性利好
(单核解压压力也减半, 30fps 需求从 132.7 MB/s 降到 66.4 MB/s)。
⚠ 但亮度本来就已经到顶 (单 LED 占空 1.78%), 减半是硬伤 — 需实测判断可接受性。

### ⚠ 平台澄清: 现在跑的仍是 **Zynq 7020 米联派 FS03**, 安路只是选型评估

上表的收益要按**现板**算 (A9 双核, 实测 传输 40ms + 解压 64ms 串行 = 9.89 fps):

| | 现在 (双面 360 片) | 只驱 A 面 (180 片) |
|---|---|---|
| 压缩后/帧 | 131 KB | ~65 KB |
| 传输 @28Mbps | 40 ms | **20 ms** |
| A9 单核解压 | 64 ms | **32 ms** |
| 串行周期 → 帧率 | 104 ms → **9.6 fps** | 52 ms → **19.2 fps** |
| +window=2 重叠后 | 64 ms → 15.6 fps | 32 ms → 31 fps (**被机械 2×11.1=22.2 卡住**) |

⇒ **在现板上, A-only 直接把帧率翻倍到 ~19 fps, 基本贴住 11.1 rps 的机械上限**,
不需要任何 PL 解压 IP、不需要换芯片、不需要改推流协议。代价只有亮度减半。
⚠ 注意: A-only **不改变每转 360 次的发射节奏** (面板刷新预算 213.7µs/片 不受影响),
只改 DDR 里存多少片 + 链路上传多少字节。
