两块屏**正反背靠背、中间有 13.8mm 间距**，屏面不再穿过旋转圆心。对称安装（各偏 d/2 = 6.9mm）。

## 结论一：RAM 不用两块，RTL 一行没动

两屏关于轴对称 ⇒ **屏B@θ ≡ 屏A@(θ+180)** 严格成立（推导：屏B 在 θ 占的是「法向 θ、偏移 −d/2」
的平面 = 「法向 θ+180、偏移 +d/2」= 屏A 在 θ+180 占的平面）。所以：
- `PHASE_B=180` 机制原样有效
- DDR 仍只需**一份 360 片**，`02_dual_panel_arch.md`「数据零翻倍」结论成立
- 213.7 µs/片 带宽预算不受影响（半圈内 A+B 仍覆盖全部 360 平面，13 rps → 26 fps）

⚠ 但**冗余度变了**：穿心时 slice i 与 i+180 互为镜像（信息量其实只有 180 片，360 是冗余存法）；
有间距后 **360 片各不相同**。存储量没变，但「一半是冗余」的余量没有了。

## 结论二：切片采样必须改（已实现）

`tools/gen_anime_slices.py` 加 `--gap-mm`（默认 13.8），`render_slice()` 核心：
```python
# 旧 穿心子午面:  wx = D*cosθ            ; wz = D*sinθ
# 新 偏移平面:    wx = D*cosθ - off*sinθ ; wz = D*sinθ + off*cosθ
#   u=D 沿 û=(cosθ,sinθ) 保持旧约定不变, 垂距 off 走法向 n̂=(-sinθ,cosθ)
#   off = (gap_mm/2)/0.9375  → 13.8mm 时 = 7.36 px
```
等价极坐标 `R=√(u²+off²)`，`方位 = θ + atan2(off, u)` —— **一列像素不再共面**，
近轴处方位偏移极大（u=0 直接偏 90°，u=2px 偏 15°），旧的「u>0 半边=θ_i / u<0 半边=θ_i+180」错得离谱。

⚠ `--gap-mm 0` 必须逐字节退化回旧行为（u 沿 û 而非 t̂，否则整体转 90° 会破坏 angle_tracker 标定）。
验证方法：关抖动后 `slice_i` 与 `mirror(slice_i+180)` 应 **180/180 对逐像素相同**；gap>0 时应 0/180。

## 数字账 (gap=13.8mm, P0.9375 屏, 160×180)

| 项 | 值 |
|---|---|
| 每屏到轴垂距 | 6.90mm = 7.36 px |
| **中心盲区直径** | 13.8mm = **14.7 px** |
| 盲区占直径 / 占截面积 | 9.2% / **仅 0.85%** |
| 有效外径 | 74.85mm（穿心 74.53，只涨 0.32） |
| 整屏跨方位角 | **169.4°**（穿心正好 180°） |

盲区是几何固有、软件补不回来，但轴心是模型**内部**、外表面看不见，对角色模型基本无损
（除非有细长物体正好穿过中轴）。想减小只能缩小间距。

## 🔴 手性: --mirror-u 默认 ON (2026-07-27 上板实测)

屏 X 轴物理方向与代码假设的 û(θ) **相反**, 每片须对屏中心轴做轴对称。
`gen_anime_slices.py` 已把 `--mirror-u` 设为默认 ON (逃生门 `--no-mirror-u`)。

**为什么以前没发现**: 穿心几何下 `mirror(slice i) == slice i+180`, 手性错误**等价于相位转 180°**,
而相位本来就靠光电标定, 随便转多少度都能被吸收掉 → 手性错了根本看不出来。
有间距后 `mirror(slice_j)` 不再等于集合里任何一片 → 第一次变成肉眼可见的镜像。

⚠ 若转起来发现手性仍不对, 修法**不是**再翻 u, 而是翻转 θ 方向 (`θ → −θ`)。
这两者在有间距几何下**不等价**(偏移量会落到轴的另一侧), 需实测区分。

## ⚠ 未决: 全局镜像 vs 屏B 相对屏A 镜像

- **全局镜像 (已做)**: 每片都翻 → 两屏内容都变, 但**相互关系不变**, 并排看观感与翻转前相同。修的是整体手性。
- **屏B 相对屏A 镜像 (未做)**: 屏A 读 `slice i`, 屏B 读 `mirror(slice i+180)`。
  ⚠ 这种**做不到一块 RAM** — `mirror(slice_j)` 不在切片集合内(翻 û 必然同时翻 n̂)。
  需 host 生成两份 (4.4→8.8 MB) + RTL 加 `slice_base_B` 寄存器 (现在 pair FSM 用同一 `base_lat` 喂 A/B)。
  **若确认需要这种, 本文开头"RAM 不用两块"的结论要修正。**

判据必须**转起来**看 — 静止时两屏本就是 0°/180° 两个不同截面, 分辨不出该不该互为镜像。

## 待观察风险

同一体素在半圈内被 `u>0` 和 `u<0` 两次命中，两次机械角度相差接近 180°。
同一 3D 模型采样值一致所以没问题，但**视角相关着色会重影** —— 若启用了
[[feedback_hls_zbuffer_for_depth]] 那套 depth-fade / z-buffer，两次会给出不同值。转起来看到重影先查这个。

## 亮度到顶了吗 (2026-07-28)

**OE 占空已到顶**: `oe_window` 写 192, 引擎内部**箝位 [2,187]** (187 保证 LE 落在 OE 回高之后,
`icnd2047_panel_core.v` 硬约束, TB 有用例 `oe_window=200 clamped -> 187`)。
一行 195 拍 → **187/195 = 95.9% 占空**, 再写大没有意义。

**但单 LED 真实占空只有 1.78%**: 54 行顺序扫描, 每 LED 只亮 1/54 → `187/10530 拍`。
这是扫描架构固有代价。

**唯一剩余余量 = 驱动 IC 电流增益寄存器** (ICND2049/2047 内部, 靠 LE 长度编码指令配置),
现在跑的是**上电默认值, 从没配过**。⚠ 但 `pov_dual_top.v` 的手动命令通路
(0x00/0x04 + 0x0C subcmd01 per-chain 预载) **还没接进顶层**(文档标"遗留 v6 集成项"),
要配增益得先补这条通路。且调高前须实测电流 — 接口板 TPS54560 总闸 5A。

软件侧还可降 `--thresh`(默认 128) 让更多像素点亮, 代价是细节变糊。
