2026-07-29 用 `sim/tb_oe_sweep.v` 仿真扫 `oe_window`, 拿到真实数据 (板上 0x28 悬空读不到):

| oe_window | 行周期(拍) | 整屏 | **面板刷新率** | 16.22rps 每片可扫 |
|---|---|---|---|---|
| 8/24/48/96 | 195.0 | 210.6 µs | **4748 Hz** | 0.81 ⚠ |
| 128 | 212.0 | 229.0 µs | 4368 Hz | 0.75 ⚠ |
| 160 | 244.0 | 263.5 µs | 3795 Hz | 0.65 ⚠ |
| **187 (当前)** | 271.0 | 292.7 µs | **3417 Hz** | **0.59** ⚠ |

行周期 = 1取指 + 1装载 + 192移位 + LWAIT + 1显示。**LWAIT = max(0, oe − 111)**
(仿真三点吻合); oe=200 与 187 结果相同, 证实箝位 [2,187]。

## 🔴 结论一: overlap 是架构固有, oe≤111 免费

`oe ≤ 111` 时行周期恒 195 拍 —— **OE 显示窗完全藏在下一行的 192 拍移位里**,
一拍不多花。这就是 overlap (靠 ICND2047 内置双缓存)。超过 111 才插 LWAIT 等待拍。
⇒ **111 是免费亮度上限**; 当前跑 187 = 用 **39% 刷新率**换那 68 沿额外亮度。

## 🔴 结论二: 当前转速下无论 oe 取多少都扫不满

```
每片预算 (16.22 rps) = 171.3 µs
最快扫描 (oe≤96)     = 210.6 µs   → 最好也只有 0.81 遍
当前 (oe=187)                     → 0.59 遍, 41% 的行根本没显示
```
要扫满一遍, 转速须降到: **oe≤96 → 13.19 rps 以下** / oe=187 → 9.49 rps 以下。

设计文档按 13 rps / 213.7 µs 定预算, **正卡在 oe≤96 那条线上 —— 文档是对的, 是实际转速跑超了**。
体积帧率 = 2×转速, 13.19 rps 已对应 26.4 fps (达标) ⇒ **再加转速无收益, 反而丢行**。

## ✅ 2026-08-03 定案: oe_window 187 → **111**, 已固化

**111 才是免费亮度上限, 不是 96** —— `LWAIT = max(0, oe-111)`, 所以 `oe≤111` 行周期
恒 195 拍。之前打算用的 96 白扔了 15 个沿的亮度, 刷新率一点没多拿。

| | oe=187 (旧) | **oe=111 (现)** |
|---|---|---|
| 行周期 | 271 拍 (含 76 拍 LWAIT) | **195 拍** |
| 整屏扫描 | 292.7 µs | **210.6 µs** |
| **2D 刷新率** | 3417 Hz | **4748 Hz (+39%)** |
| 967RPM 每片扫描 | 0.58 遍 (42% 行不显示) | **0.81 遍** (19% 不显示) |
| LED 电流 | 基准 | **约 −29%** (给 5V 轨让余量) |

**寄存器写法** (`0x0C` subcmd=`2'b10` + `cfg_we`(bit27), `oe_window` 在 **[15:8]**):
```
pw(0x0C, 0x000001FF)   # sdi_mask
pw(0x0C, 0xB8366F01)   # [15:8]=0x6F=111, [24:16]=54 行, bit29 dclk_fast, bit28 overlap
pw(0x0C, 0xC1000003)   # auto_en + use_fb
```
旧值 `0xB836C001` ([15:8]=0xC0=192, 引擎内部箝位到 187)。已写进 `pov_boot.sh`。

### 4748 Hz 是当前架构天花板
卡在每行 **192 拍移位 = 1728 列 ÷ 9 lane @50MHz aclk**。再上只有两条路:
提 aclk (受 ICND2049 FCLK 25MHz 上限约束, 要重核分频) 或 加 lane 数
(9→18 → 9500 Hz, 但要多 9 个 PL IO + 改屏侧接线)。**都不是软件能解决的。**
