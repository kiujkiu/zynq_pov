## 🔴 固件版本判定法 (免猜, 上板必用)

写新寄存器位再回读, 比看时间戳/文件名硬:

| 判定 | 方法 | 结果 |
|---|---|---|
| 新旧对称版 | 写 `0x10[5]`(mirror_a) → 读 `0x00[14]` | 旧版无此位, 恒 0; 新版能读回 |
| 对称 vs 偏心 | 读 **`0x24`** | 对称版 = status 别名(与 0x00 相同); 偏心版 = POV_CTRL 影子(`0x0168xxxx`) |

## v3.1 六层交付 (细节见 commit bac5e41 的 message, 写得很全)

**RTL** `0x28 slice_base_b`(=0 回落老行为) / `0x10[6] fold_a_en` / **`R 0x24` POV_CTRL 影子回读**
(解决 0x10 只写导致软件无法安全 RMW)。镜像置换 52/51/53 三个常量**一个字没动** ——
已独立验证 486 格双射+对合, 且严格等于观察者域 `X→159-X`。综合 WNS **+6.888ns**, LUT +99/FF +66。

**协议** 帧长去常量化(`n_slices` 权威, ≤720) / `DUAL_FACE`(bit3) / `FOLD_A`(bit4) /
DELTA 必须按**布局**匹配而非仅长度。

**板端** 变长帧 + 双流并行解压(pthread+CPU 亲和, 与串行逐字节相同) + 三缓冲 +
DDR 重规划(bank A/B/C @0x10/0x11/0x12000000, FRAME_MAP_LEN 40.4MB)。

**Host** `--face-off-mm` / `--dual-face` / `--fold-a` / `--window` + 几何变化先排空窗口再强制关键帧。
不给新参数时**逐字节等价旧行为**(30+ 套 frames_* 不作废)。

**内核** `povmem.ko` 窗口 16MB→41MB。**脚本** boot×2 + `bench_s0` 危险偏移(会往正在显示的帧写垃圾)。

## 🔴 三个被修正的关键数字 (我最初都算错了)

1. **540 片双面并行解码 = 64ms, 不是 48ms。** `FOLD_A` 后面A 180 片/面B 360 片,
   **分割是 1:2 不是 1:1**, 双核由大的那面封顶 ⇒ 上限 **1.5×**(实测 1.42×), 只有对称的
   720 片才吃满 2×。⇒ 540 双面 window=2 后是 **15.6 fps** 不是 17.9。
   要 48ms 得把大的那面也拆开做负载均衡(3 流), **等 iperf 实测链路后再定值不值**。
2. **拆两条流的压缩代价 ≈ 0**(实测 −0.12%~+0.04%), 不是我估的 0.3%。原因: zlib 窗口
   仅 32KB 而两面在载荷里相距 2.2–4.4MB, **本就不存在可丢的跨面后向引用**。
3. **A9 解码实测 `dec_avg=108ms`/帧**(4.42MB → 约 41 MB/s), 比记忆里长期用的 69 MB/s 慢。
   ⇒ 单面 26fps 目标本身就撑不住, 之前"fps 掉到 4"有一部分是这个原因, 不是网络。

## 板上固件沿革 (⚠ 2026-08-03 起已换成**偏心版**, 下面这段是历史)

(2026-08-01) 纯对称固件曾烧并验证: **`mirror_a` 首次真正可用** —— 板上原来那版(7/28 16:58 打包)早于
`eb4854c`(17:16 加 mirror_a) 18 分钟, 所以两屏之前只能**同时**镜像。现在两面可独立镜像,
这对偏心后的手性重测是关键(偏心后两面手性关系不再对称)。对称版综合 WNS **+7.968ns**。

烧录: `stream/boot/build_boot.bat`(FSBL from XSA + bootgen) → BOOT.BIN → pscp → SD FAT
`/dev/mmcblk0p1` 替换 `BOOT.bin`(小写) → **冷启动**(reboot 不重载 PL)。
⚠ FAT 上若存在 `system.bit.bin`, u-boot 的 `fpga_loadbit` 会**覆盖 FSBL 已加载的 PL** —— 烧前必查。

## ARM 交叉编译: 本机不用装工具链

**Vitis 2024.2 自带 `arm-linux-gnueabihf`**:
`C:\Xilinx\Vitis\2024.2\gnu\aarch32\nt\gcc-arm-linux-gnueabi\bin`(走 cmd.exe 调用)。
配合仓库里现成的 `stream/board/deps/arm/libz.a` 可直接出 `pov_rxd`/`bench_s0` 静态 ARM 二进制。
⚠ 静态链接 pthread 要自检: `nm` 里 `pthread_create`/`pthread_setaffinity_np` 是 **`W` 弱符号但指向
真实地址**(glibc 2.34+ 把 libpthread 并进 libc) —— 只 grep `T` 会误判成"没链进去"。

## 换安路 FPGA 的时机判断 (2026-08-04 复审)

RTL 依赖**重新审过仍是 14 处 ODDR**, v3.1 新增的 `slice_base_b`/`fold_a_en`/`R 0x24`
全是纯逻辑, 无新增厂商原语。在用 RTL 1949 行。PL 只占 **LUT 5.1% / WNS +6.888ns**。

⇒ **Zynq 侧一点都不紧张, 换平台解决不了上面任何一个瓶颈**。正当理由只能是
供货/成本/国产化。用户 2026-08-04 决定**先不换, 优先解决现有瓶颈**。

真要提前验证的话, **最高性价比的一步是"在 TD 里综合一遍"—— 不需要板子**, 就能暴露
oDDRx1 替换、时序收敛、BRAM(ERAM) 推断、AXI 对接四件事。前提是先装 TD+FD+license。
