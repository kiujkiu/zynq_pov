# 安路全系真差分对 / DDR / LVDS 速率清点 (2026-08-31)

起因: 用户问"有没有更适合的芯片方案, 比如纯 FPGA, 安路有没有更适合的"。
判据来自 [[project_pov3d_final_target_chip_verdict]] 与 [[reference_icnd2260_spec]]:
**605 片/圈双面全速需 192 真差分对**(下界 108) · LVDS 线速率 **340 Mbps** ·
DDR **3.77 / 2.64 / 1.13 GB/s**(三档架构口径) · 渲染 2 个 IP。

## 🔴 头号陷阱: 安路选型表里的 "用户 IO 数" 不等于真差分对数

选型表写法是 `335/(41+126)` = **用户 IO 数 /(真 LVDS 对 + 仿真 LVDS 对)**。
**Emulated LVDS = LVCMOS + 板级 3R 电阻网络, 上限只有 300 Mbps**(PH1A 表 3-2-x),
达不到屏要的 340, 而且 141 对 = 423 个电阻要上转子 ⇒ **仿真对在本项目里等于零**。

⇒ **EF3LA0CG642B 的 "475 用户 IO" 是假高**: 真差分只有 **47 对**, 比 7020 的 96 还少一半。
EF3 全系无 DDR 控制器、LUT 只有 4.8K~11.8K ⇒ **整个 EF3 系列出局**, 连"转子侧串化桥"
都当不了(桥要 ISERDES 类资源 + 真差分)。

## 逐型号对照 (DS900 表 1-1/1-2 原文抄, 括号内为真差分对)

| 器件 | 真差分对 | 用户 IO | DDR | SERDES | LUT4 | 硬核 CPU | 对 192 对 |
|---|---|---|---|---|---|---|---|
| XC7Z020 CLG484 (现役) | **96** | 200 | 芯片 x32 / 板 x16 | 无 | 53,200 | A9×2 | ❌ 0.5× |
| DR1V90GEG484 | **96** | 201 | 芯片 x32 / 板 x16 | 无 | 94,464 ⚠ | RV 单核 800M | ❌ 0.5× |
| PH1A90SBG484 | 81+43+10 = **134** | 280 | x40 @1066 = 5.3 GB/s | 4×10.3G | 115,776 | **无** | ❌ 0.70× |
| PH1A180SFG676 | 108+72 = **180** | 396 | x72 @1866 = 16.8 GB/s | 8×12.5G | 210,240 | **无** | ❌ 0.94×(差 12 对) |
| PH1A400SFG676 | 120+72 = **192** | 400 | x72 @1866 | 8×12.5G | 417,024 | **无** | ⚠ 1.00×(一对不剩) |
| **PH1A400SFG900** | 168+72 = **240** | 500 | x72 @1866 | **16×12.5G** | 417,024 | **无** | ✅ **1.25×** |
| EF3LA0CG642B | **47**(+141 仿真) | 475 | **无控制器** | 无 | 11,776 | 无 | ❌ 0.24× |

- HR bank LVDS25 输出 **1250 Mbps**, HP bank LVDS18 输出 **1500 Mbps**(表 3-2-x)
  ⇒ 对 340 Mbps 余量 3.7~4.4×, **屏侧线速率在安路这边从来不是问题**。
- PH1A180/400 有 **2 个 DDR 硬核控制器, 最大 x72 @1866**(DDR3 与 DDR4 都是)
  ⇒ 即便只贴 x64 也有 14.9 GB/s, **DDR 那堵墙(最坏 3.77)在这一档彻底消失**。
- PH1A400 的 417K LUT ≈ 7020 的 **7.8 倍** ⇒ 渲染 IP 想放几个放几个,
  "切片不落 DDR 的硬死线架构"不再是被迫选择。

## 🔴 结论一: "要 IO" 和 "要硬核 CPU" 在安路目录里**互斥**

安路唯一的 SoC 线就是 DR1, 而 DR1 **全家只有 BGA400/484 两种封装, 201 IO 封顶**
(DR1M90 与 DR1V90 逻辑资源完全一样, 只差 ARM A35×2 / RISC-V×1)。
⇒ **在安路catalog 里, "换到够 IO 的型号" 与 "变成纯 FPGA" 是同一件事**, 没有中间选项。

代价 = 整个 PS 侧要重做: 收包/TCP/lz4 送料/寄存器控制现在都在 Linux 上。可行的补法:
- ❌ **ESP32-C5 顶不住**: 实测 TCP 只有 **39.5 Mbps**(HT40 上限) 且 SDIO 通道
  **100 KB/s 天花板**([[feedback_esp32c5_singlecore_ceiling]] / [[project_esp32c5_wifi_throughput]]),
  而传体素表架构要 **108 Mbps** ⇒ 换上去等于把墙从 IO 搬到链路。
- 外挂一颗跑 Linux 的小 SoC(SDIO/USB/**PCIe Gen3**, PH1A400 有 PCIe 硬核), 或软核 RISC-V。
  两条都**没做过任何评估**。

## 🔴 结论二: VOCM 那条**换型号不解决**, 它是安路家族数

PH1A 表 3-1-13(HR): LVDS25 输出共模 **VOCM 0.9 / 1.25 / 1.4 V** ——
与 DS1200 V1.0 给 DR1 的数**逐格相同**; HP bank(LVDS18) 是 0.9/1.2/1.5, min 更低。
而 ICND2260 要 **VIC 1.1~1.3 V** ⇒ **典型值正中、min/max 两端都超窗**, 与
[[reference_dr1_datasheet_draft_vs_v10]] 记的那条完全一样。
⇒ **这不是 DR1 的缺陷, 是安路 IO 库的共性**; 换 PH1A 也得问同一个电气问题。

## 结论三: 排序没变 —— 器件仍排最后

[[project_pov3d_final_target_chip_verdict]] 的"架构 → 自制板 → 器件档次"顺序**依然成立**,
本次清点只是把最后那一格填上了名字:
1. 问供应商 `VHEAD[23:20]` 有没有 **8-bit 线上格式** —— 若有, 需求对数减半到 96,
   **现役 7020/DR1 的 96 对就够, 一颗芯片都不用换**;
2. "切片不落 DDR" 架构 ⇒ DDR 需求降到 1.13 GB/s, **16-bit 板都过**;
3. 只有在 1 失败 **且** 坚持 605 片双面全速时, 器件才成为问题, 那时唯一答案是
   **PH1A400SFG900**(安路对标 [[reference_icnd2260_spec]] 里点名的 K7-325T FFG900 那一档,
   且纸面更好: 240 对 vs 250 对但 DDR 是 x72 硬核、SERDES 12.5G vs 6.6G)。

## 选 PH1A400SFG900 的已知代价 (未量化, 别当成"就它了")

- **无 PS** ⇒ 见结论一, 软件栈重做。
- **FCBGA900 / 31×31mm / 1.0mm pitch** 装在 **900 RPM、68-136 g 离心加速度的转子上**,
  PCB 层数与滑环供电功率都要重算。
- **价格与货期零调研**(官网不公开; DR1M90 就是因为"贵很多"被否掉的, 见 [[project_dr1_sku_decision]])。
- **TD 对 PH1A 的支持与 license 未验证** —— 现有 license 是按 DR1 拿的
  ([[reference_anlogic_td_toolchain_setup]])。
- 零经验: 光 DR1 的 bring-up 就花了整个 8 月。

⚠ **待核**: 官网选型页给 DR1V90 的 LUT 是 **94,464**, 而
[[project_pov3d_final_target_chip_verdict]] 里记的是 **52,480**(与 7020 打平)。
两个数差 1.8×, 大概率是"LUT4 总数 vs 等效逻辑单元"口径不同, **引用前回查 DS1200 V1.0**。

## 🔴 2026-08-31 二次收窄 (查 EF2/EF3 手册 + 重算链路台阶) —— 上面的结论要改两处

### ① 安路**全家族**单端都只有 300 Mbps ⇒ 「单端 + 外置 LVDS 驱动器」这条路在安路上**整个不存在**

| 家族 | 真 LVDS 输出 | **单端 LVCMOS** | 仿真 LVDS |
|---|---|---|---|
| PH1A (表 3-2-8) | HR 1250 / HP 1500 Mbps | **300 Mbps** | LVDS25_E/33_E **300 Mbps** |
| DR1 (DS1200 V1.0) | 1250 Mbps | **300 Mbps** | — |
| EF3 (表 3-2-5) | **400 MHz**(≈800 Mbps DDR) | **166 MHz**(≈332 Mbps DDR) | LVDS25E/33E **166 MHz** |

而 ICND2260 要 **333-340 Mbps/对**。
⇒ 🔴 **安路全系单端/仿真 LVDS 全部擦线不过**(300 差 11%; 332 差 0.3% 零余量)。
而 [[reference_icnd2260_spec]] 记着 **Xilinx 单端 340 Mbps 能出**(且 SSN 已实跑 `Passed`)。
⇒ **「FPGA 出 165 单端 → 外置 LVDS 驱动器 → 差分进屏」这条已验证的路是 Xilinx 专属的,
换到安路就必须改成真差分直出** —— 这是换厂商时"一半变好一半变坏"的又一例。
⇒ **在安路上, 真差分对数就是全部的游戏。**

### ② 🔴 真差分对是**阶梯函数**, 中间档买不到任何东西

[[reference_icnd2260_spec]] 的链长表(48 颗双面, 每链 3 数据对 + 1 时钟对):

| FPGA 对数 | 链数 | 颗/链 | **最大片/圈** |
|---|---|---|---|
| 48 | 12 | 4 | 157 |
| 64 | 16 | 3 | 210 |
| **96**(7020/DR1 现有) | 24 | 2 | **315** |
| **192** | 48 | **1** | **629** |

🔴 **链长是整数 ⇒ 96 对与 192 对之间的任何对数, 上限仍然是 315 片/圈。**
⇒ **PH1A90SBG484(124 输出对) 和 PH1A180SFG676(180 对) 在这个口径下比现有 96 对多不了一片。
花钱买不到东西。**(⚠ 上表里 PH1A90 我原写 134, 那是把 **10 对 MIPI DPHY-RX** 算进去了 ——
**MIPI 那 10 对是输入**, 出屏用不上 ⇒ 可输出真差分对是 **81 HR + 43 HP = 124**。
PH1A180 的 180 = 108+72 不含 MIPI, 不受影响。)

### 🎯 但**外置 LVDS 时钟扇出**把台阶从 192 降到 **145**, 结论随之改写

一颗外置 LVDS 时钟缓冲/中继把 1 路时钟扇成 48 路 ⇒ FPGA 只出 **48链 × 3 数据对 = 144 对**
+ 1 对喂缓冲 = **145 对**(链长表里"96(时钟外扇出则 73)"那个括号就是这条规则)。

| 器件 | 可输出真差分对 | 过 145? | 片/圈 |
|---|---|---|---|
| XC7Z020 / DR1V90 | 96 | ❌ | 315 |
| PH1A90SBG484 | **124** | ❌ 差 21 对 | 315 |
| **PH1A180SFG676** | **180** | ✅ **余量 1.24×** | **629** |
| PH1A400SFG676 | 192 | ✅ | 629 |
| PH1A400SFG900 | 240 | ✅ 余量 1.66× | 629 |

⇒ 🎯 **改判: 能跑 605 片/圈全速的最低档安路器件是 `PH1A180SFG676`(180 对) + 一颗外置 LVDS
时钟扇出**, 不是 PH1A400SFG900。PH1A400 的 240 对只在"连时钟也自己出"(192 对)时才必需。

### 其余家族的清点结果: 全部出局

| 家族 | 最大真差分对 | 出局原因 |
|---|---|---|
| EF2 (DS400 表 1-2) | **31** (206 IO = 31 真 + 65 仿真) | 太小; 最大 4,480 LUT |
| EF3 (DS600) | **47** (EF3LA0, 475 IO) | 真对太少; 无 DDR 控制器 |
| EG4/SALEAGLE | 最大 **196 用户 IO** | 老工艺, 规模小 |
| SF1/SALSWIFT | **6K LUT** | 定位 MIPI 小芯片 |
| PH1P100S | 301 IO / **约 120 对**⚠ | 不如 PH1A180; ⚠ 对数来自官网页面, **未见手册原文** |
| **EF5** (2496-16224 LUT, 383 IO) | **未知** | 🔴 **手册未公开下载, 真差分对数要问代理** |

🔴 **2026-08-31 当天稍后作废(限定作用域)**: 上面整节是按「**主控芯片自己直出全部 192/145 对**」
算的。用户确认 **WiFi 必须留 ⇒ Zynq/DR1 这颗 SoC 不能省** ⇒ 走
[[project_pov3d_bridge_architecture]] 的**串化桥**架构后, **主控只需要 36-46 对**,
现役 96 对绰绰有余。
⇒ **PH1A 不再是「主控候选」, 只剩「桥片候选」**, 而桥片只要 91-114 对 ⇒ 该看的是
**PH1A60GEG324(100 对) / PH1A90SBG484(124) / PH1P100SBG484(137)** 这一档,
**PH1A180SFG676 与 PH1A400 整个用不上了**。本节保留是因为「单端 300 Mbps 全家族擦线不过」
与「对数是阶梯函数」这两条**仍然成立且仍在用**。

⚠ **价格仍然零调研** —— 全表按对数排, 不是按价排。PH1A180SFG676 是 27×27 FCBGA676 1.0mm,
比 PH1A400SFG900 的 31×31/900 球好, 但仍是 FCBGA, 转子板层数要重算。
