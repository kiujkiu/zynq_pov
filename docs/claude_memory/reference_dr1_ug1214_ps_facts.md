# UG1214 一手事实 (2026-08-27 拿到并挖完)

《UG1214_安路科技DR1系列FPSoC产品说明书》v1.4(2026.05) —— 安路 UG12xx 里**唯一讲 PS 的一本**。
之前没有它, 我们对 PS 侧的结论**全是从 IP 包 json / demo 的 C / 厂商口头答复反推的二手出处**。
归档在 `dr1v90/docs/vendor/anlogic/UG1214_ProductSpec.pdf`。

## 🎯 推翻: "低 4G 走 M2 / 高 4G 走 M3"

厂商口头答复说过"两路分别走 M2/M3 就不竞争公共缓存, 划分按低 4G / 高 4G 地址空间"。
**手册推翻了这个划分方式**: 图 14-1 (`:7275-7280`) 四个 XPI 是**按 master 固定分配**的:

| XPI0 | XPI1 | **XPI2** | **XPI3** |
|---|---|---|---|
| APU/ACP (DR1M) 或 RPU (DR1V) | NPU and Other Masters | **HP0** | **HP1** |

⇒ **与访问地址无关。** 全文搜"映射/重映射/remap/路由"无任何按地址分派 DDRC 端口的描述。
⇒ 🎯 **对我们是好消息**: 板子 512MB DDR 全在低 4G, 但 HP0/HP1 **依然分别落在 XPI2/XPI3
两个独立端口**, 不会在 XPI 层竞争。真正的共享点在其后的 **PA(端口仲裁器)、DDRC 的 CAM
和唯一那颗 DRAM 颗粒**。
(`:7107-7111` 也证实了厂商那句"4 个 128-bit AXI 接口, 其中两个直连 HP0/HP1"。)

## 🔴 新硬约束: HP 在 PL 边界远比想象的窄

| 项 | 值 | 出处 |
|---|---|---|
| PL 边界数据位宽 | **32 或 64 bit**(不是 128) | `:3511` |
| `A*Len` 位宽 | **4 bit** ⇒ 单笔最长 **16 拍** | `:3519` |
| Slave ID 位宽 | 6 bit | `:3521` |
| **Outstanding** | **8 reads / 8 writes** | `:3523` |

⚠ 那个 **128-bit 只在 DDRC 那一侧**, 中间由 XPI 做位宽转换(`:7318-7319`)。
🔴 **对 `axi_hp_arb` 的直接影响**: 现在每主 `MAX_OUTST=2`, 3 个引擎就 6, **逼近 8 的上限**。
   这条之前完全不知道 —— 加引擎数时必须一起算这个账。
(GP 口同为 8/8; ACP 更低 4/4。)

## QoS 的真实语义: **是分类器, 不是"谁大谁优先"**

`arqos/awqos` 只是把事务分类。16 个 QoS 级别按阈值切成 **2 个读区 / 3 个写区**,
真正决定优先级的是**每个区被配成什么事务类型**(`:7491-7516`):

| 类型 | 语义 | 出处 |
|---|---|---|
| **VPR** 可变优先级读 | **"最大延迟绑定流量"**; 初始与 LPR 同级、低于 HPR, **一旦超时在 DDRC 里升为最高优先级**; 手册**点名用于视频/音频等实时应用** | `:7465-7467` |
| HPR 高优先级读 | **独占专用 CAM 空间**; 面向**延迟敏感(如 CPU)而非实时** | `:7471-7472` |
| LPR 低优先级读 | 恒低, 靠超时防饿死 | `:7457-` |
| NPW 正常写 / VPW 可变优先级写 | 写侧的 LPR / VPR | `:7474-7481` |

🎯 **我们的面板取片(硬实时纯读)正好是 VPR 的教科书用例** —— 不是原先设想的"把 arqos 拉到 0xF"。
⚠ `:7480-7481` 的 VPW 段落有明显复制粘贴错误(正文写成"可变优先级读 VPR"), 别被带偏。

寄存器: `PCFGQOS0_n` / `PCFGWQOS0_n` / `PCFGR_n` / `PCFGW_n`, **n=0-3 对应四个端口
⇒ n=2 是 HP0, n=3 是 HP1**(由 `:7495` + `:7275-7280` 拼出的推论, 手册没并排写成表)。
基址 `DMC_CFG = 0xF8420000`(128KB, `:2766/:2893`)。
端口超时防饥饿: `PCFGR_n.rd_port_priority` / `rd_port_aging_en`(`:7519-7533`)。

## 🔴 两条可能让我们白忙的

### ① XMON 会覆盖 PL 侧的 arqos
每个 AXI 端口(含 HP0/HP1)上挂一个 **XMON**(`:3581-3582`, 图 8-1)。
`QOS_CONFIG` 有**静态 / 动态 / 透传**三种模式(`:3656-3659`):
- **动态**: XMON 监控 Resptime 和 Bandwidth **自己动态调 qos**
- **静态**: 输出 = `qos_config_value` 寄存器的值
- **透传**: 输出 = PL 传进来的 qos
⇒ 🔴 **非透传模式下, `axi_hp_arb` 里那套 QoS 参数化根本不生效。**
   上电默认是哪种模式 **手册没说** ⇒ 必须实测或问原厂。

### ② HP 口各挂一个 MPU, 而 DDR 侧默认是开保护的
`MPU Slave AXI_HP0 @ 0xF8412000` / `AXI_HP1 @ 0xF8413000`(各 4KB, `:3078-3130`)。
`:15465` **"DDR 访问默认打开保护, 若需关闭, 将 0xF840E004 及 0xF840F004 设置为 0"**。
**HP 侧 MPU 的默认状态手册没说** —— 若同样默认开, 未配置的 PL master 走 HP 会
**吃 SLVERR**(`:15537` "对违反保护的访问, 返回 slv err")。
⇒ **这可能就是上板第一次调不通的原因**, 上板前先查这两个寄存器。

## 🎯 意外收获: HP 带宽可以**实测**, 不用估

**XMON 自带硬件带宽计数器**, 基址 `XMON = 0xF8440000`(32KB, `:2769/:2902`):
- `BANDWIDTH_RD/WR` + `BANDWIDTH_TMWD` 时间窗 ⇒ `平均读带宽 = BANDWIDTH_RD / (Tcpu_2x × TMWD)`(`:3601-3607`)
- **响应时间** `A*RESPTIME_MAX` / `A*RESPTIME_ACC_H/L`(`:3616-3618`)
- 按 burst_length/size/type 分类统计(`:3626-3628`)
- 总线超时 `DEBUG_TIMEOUT_THD` / `DEBUG_TIMEOUT_FLAG` bit[2]写 bit[0]读(`:3644-3651`)
- 中断 `intr_xmon` = SPI 142(`:4793`)

⇒ 🎯 **"DR1 的 HP 口带宽零实测"这条可以直接消掉** —— 读芯片自带计数器即可,
   不必只靠我们自己那个 `measure/01_hpbw` 的估算。
⇒ 而且 `A*RESPTIME_MAX` 正好能回答**"硬实时读会不会被反压卡住"**。

## 其它

- **HP 口地址空间受限**(`:2935-2965` 表 5-3): 只能看到 **DDR 和 OCM**,
  没有 GP、没有外设、没有 RPU TCM。OCM 在 `0x61000000`/256KB。
  ⚠ `DDR 0x00000000/1024KB` 那段"不能被 BSU 访问, 建议保留"。
- **PL 加载前必须先关闭 PS-PL 的 AXI 接口**(`:4412-4414`) ——
  "以防止加载过程中的接口数据波动导致 PS 部分进入未知状态"。**我们的流程没做这件事。**
  这与 [[feedback_dr1_pl_probe_must_be_hang_proof]] 是同一件事的两面。
- `CRP_CFG_STAGE(0xF8801454) Bit0` = PL 初始化完成判据(`:4417-4424`)。
- `0xF8806330` 正式名 **`TOP_S_GLOBAL_SRST_N`**(TOP_CFG_S 基址 0xF8806000 + 0x330)。
  UG1214 只定义 **Bit[0]**(系统软复位) / **Bit[8]**(单独软复位 PL, 清除已下载逻辑) /
  **Bit[9]**(PS_SRST_N 时是否复位 PL 逻辑)。
  🔴 **全文没有出现 [7:4]** ⇒ 我们那条"[7:4] 是四路 p2f_rst_n 闸门"**没有背书**
  (注意是"无背书"不是"被证伪" —— UG1214 不是位级寄存器手册)。

## 🔴 仍缺的文档与手册自身的矛盾

1. **《UG1215_DR1M90_Registers》** —— UG1214 三处指向它要位级定义(`:14748-14749`)。
   我们在用的 `0xF8800080` / `0xF8801078` / `0xF8800084` 在 UG1214 **一次都没出现**;
   手册只给行为级要求("关闭 AXI 接口")却不给寄存器位。**这是下一本要要的。**
2. **UG1214 自相矛盾**: `GLOBAL_RESETN` Bit8 的写序 —— `:4416` 说 **0→1**,
   而 `:4438`/`:4459` 说 **1→0**。按寄存器名 `SRST_N`(低有效)与 `:14719-14720`
   对 Bit[0] 的"写入值 0 即复位"推断 **0→1 才自洽**, 但**这是推断, 未在硬件上验证**。
