# EG4X20BG256 → EG4A20BG256I7 可移植性 (2026-09-07 六维度核查)

用户问"我们在 EG4X 上的代码后续可以挪到 EG4A 对吧"。跑了 6 个维度的一手来源核查
(器件参数/球位/工具链/E104 板级/本仓代码/电气), 结论分四层:

| 层 | 判决 |
|---|---|
| **RTL / 原语 / 时序模型** | ✅ **整体可搬**。TD 里两颗是**同一个 die**: 同 `eagle_20.db`、同 `eagle_macro.v`、同一套时序库、`speed` 只有 NA ⇒ **资源占用与 Fmax 可直接当预测值** |
| **工具链 / tcl / SDC / Device_Settings** | ✅ 原样可用。器件串已抽象成 `DEVICE=... ./build.sh` |
| **引脚约束 `.adc`** | ❌ **零兼容, 不是"改几行"是整张表作废** |
| **电气结论** | ❌ 机理不同且风险方向相反 |

## 🔴 引脚层为什么是零兼容 (D2 逐球实算)

- **256 个球里没有一个信号名相同**; 连电源/地都对不上(只有 G7/G9/H7/H9/J8 五个球轨道类别碰巧一致)
- **晶粒在封装里方向翻转**: A20 的 L 边在第 2.8 列, X20 的 L 边在第 14.1 列;
  A20 的 TE 边行均值 1.9, X20 是 12.6 ⇒ **两颗都是差分 IO 的 148 个球里, 没有一个留在同一条边**
- A20 的 90 対里只有 **18 対(20%)** 在 X20 上仍是"同两球 + 同极性 + 同真伪属性"
- 把本项目真实的 `bridge_pin.adc` 套到 X20: **105 行里 73 行致命**, 其中 **29 行落在电源/地球上**
- **bank 数不同**: A20 = 8 个 VCCIO, X20 = 4 个 ⇒ per-bank 的 VCM/VOD/IOSTANDARD 分组整套重做
- **真/仿真対配比反过来**: A20 = 39 真 + 51 仿; X20 = 53 真 + 36 仿。
  🔴 **本设计要 51 対仿真対, 而 X20 全片只有 36 対 ⇒ 按原样在 X20 上排不下**

⇒ **承认这是两条独立的硬件路线**: E104 只能跑 X20, 自制桥片板只能跑 A20, 不要做"兼容焊盘"。
⇒ 换器件的真实工作量 = 改 2 个可覆盖变量 + 重写 `mkadc_bridge.py` 里约 60 行引脚表
  + 换 `PINLIST.tsv` 数据文件 + 重测三项电气/相位。**解析层与 emit 框架不动。**

## 🔴 E104 的五条硬边界 (最终板最贵的部分一条都验不了)

1. **引脚规模不够**: 模块只引出 **47 対 LVDS / 97 个独立 IO**, 而设计要 87 対 + 17 单端 = 191 根。
   板上还焊了 W9812G6KH 128Mb SDRAM, **硬占掉 bank0 的 29 根**(含全部 8 根 GCLKIOB 时钟输入脚)与 bank3 的 8 根。
2. **只有 VCCIO1 可调**(拆 R23 焊 R22), 而 X20 的**仿真対全在焊死 3.3V 的 bank0/bank2**
   ⇒ **最终板下行 73 対里那 51 対的原生配置(LVDS25_E + 3R + VCCIO 2.5V)在 E104 上物理上做不出来**。
3. **"释放 JTAG 换 2 対"不存在**: X20 的 TCK(C14)/TDI(C12)/TMS(A15)/TDO(E14) 是**纯单端 dedicate 脚,
   不成対**, 而且只连 JTAG 座 J2、不上 J3/J4。A20 的收益来自 `H3+H4 = L8_1` 恰好成一対真差分。
4. **上行 13 対 @800M 没法自环全量**: 只有 bank1 能给 2.5V(21 対), 放不下 14 収 + 14 发。
   现实上限: 全 2.5V 双向都有背书 ≈ **10 対/方向**。
5. **SI 结论一条都不能搬**: 出了排针就是 2.54mm 双排针飞线, J4 的 60 脚里只有 8 根地
   ⇒ 平均 7 根信号配 1 根地, 800 Mbps 眼图量的是治具不是芯片。

## 🔴 两个只有 X20 才有的坑

1. **改 VCCIO1 到 2.5V 可能让 JTAG 下不进去** —— X20 的 JTAG 四脚**跨两个 bank**
   (TCK/TDI 在 bank0, TDO/TMS 在 bank1), 而 DS300 表 3-1-5 对 X20 的 **VCCIO0 与 VCCIO1 都**
   要求"≥ 下载器供电电压、与下载器一致"。E104 只能改 VCCIO1 ⇒ 改完两个 JTAG bank 电压不一致。
   **动烙铁前先查下载方式与下载器 VREF, 备好焊回 R23 的退路。A20 上不存在这条。**
2. **TD 的 bank DRC 在 X20 上会静默放过** —— TD 内部仍按 **8 个 bank** 做 DRC, 而封装只有 4 条 VCCIO
   (1:2 映射: 封装 _1 → TD bank 1/2, _0 → 3/4, _3 → 5/6, _2 → 7/8)
   ⇒ **同一条 VCCIO 上混不同电平 TD 一声不吭直接出 bit**。写 .adc 必须自己按 PINLIST 的
   `_0/_1/_2/_3` 后缀做一遍电平一致性断言。
   ⚠ 且 TD 日志里的 `PHY-3001 : BANK n` 在 X20 上指的是内部 8 bank, 与原理图上的 VCCIO0-3 对不上号。
3. (顺带) bitgen 可能有 X20 专属开关 **`-entdo`**: td.exe 的命令拼装串表里只有
   `EG4X20BG256`/`EG4X20BG256ID7` 紧挨着它; 实测加了会改变位流内容(CRC 变、USER CODE 不变)。
   本仓 build.sh 直接 bitgen 不带这个开关 ⇒ 第一次下载前建议与 GUI 生成的命令行比对。

## 🔴 电气: 5R@3.3V 与 3R@2.5V 风险方向相反

| | 共模 | 余量 | 风险方向 |
|---|---|---|---|
| E104 · 5R @3.3V (RS150/RP140/Rpd430) | ≈1.19 V | 离 VIC 上限 1.3V 有 110 mV | **下沿** |
| 最终板 · 3R @2.5V | VCCIO/2 = **1.25 V** | 离 1.3V **只剩 50 mV** | **上沿** |

🔴 **VCCIO 2.5V + 5% = 2.625V ⇒ 共模 1.3125V 已出窗** ⇒ 最终板把 2.5V 轨按 **≤2.600V** 当硬约束。
还要再扣驱动器 P/N 导通电阻失配(环流 6.2~6.6 mA, 失配 5Ω = 16 mV, 20Ω = 62 mV),
而 **DS300 从未规定上下臂对称度** ⇒ 上板必须示波器实测 `(VP+VN)/2`, 别只信 VCCIO/2。

**幅值也变小**: E104 5R 到接收端 ≈**457 mV**, 最终板 3R@2.5V 只有 **365 mV**(差 20%)。
⚠ 本仓 `E104_2260_接线方案.md` 原写 432 mV, 偏低约 5%(已更正)。

⇒ **"5R 驱通了"证明的是 2260 认电阻网络驱动, 不证明最终板共模有余量。**
实验 ④ 的判据必须写窄成"2260 是否接受电阻网络驱动 @150MHz"—— 它同时压着**两个**无背书的东西
(`LVDS33_E` 能否跑 150MHz / 2260 认不认电阻网络), 成功**不得**写成 `LVDS25_E` 的背书。

## 🔴 又一处 X20 与 A20 不同: `HSWAPEN` 是**引脚**还是**寄存器位** (2026-09-08 查证)

决定「**配置期普通 IO 是 High-Z 还是被上拉**」, 而这条直接决定**外部下拉要多强** ——
是要落到焊台上的数。

| | `HSWAPEN` 形态 | 默认值 | ⇒ 配置期 `Others` |
|---|---|---|---|
| **EG4A20BG256** | **控制寄存器 `CTRL[31]`**(只能由位流改写) | **1** | High-Z |
| **EG4X20BG256** | **一个 I/O 引脚**(`C4 = IO_BE1P_HSWAPEN_0`), 默认弱上拉 | **1** | High-Z |

DS300 表 2-8-8 有**两列**, 极易读错:
```
Pin      HSWAPEN=0(enable)    HSWAPEN=1(disable)   Post-configuration
Others   Pull-up to Vccio     High-Z               User I/O
```
⚠ **我 2026-09-08 就读错过一次** —— 只看了 `HSWAPEN=0` 那一列, 断言"配置期普通 IO 被上拉到
Vccio", 据此要求外部下拉必须压过 250 µA 内部上拉(⇒ 1 kΩ)。**默认是 `=1` 那一列, 是 High-Z。**

### E104 板上的实际接法(更要紧)

`C4` 在 E104 上**接到了 SDRAM 的 `DQ2`**(原理图网名 `NLSDRAM0DQ2`), **不是接成 strap**。
⇒ 配置期 SDRAM 未初始化、DQ 无人驱动 ⇒ `HSWAPEN` **浮空** ⇒ 内部弱上拉赢 ⇒ **=1 = disable**
⇒ **E104 上普通 IO 在配置期确实是 High-Z。**

### ⇒ 对"用普通 IO 做电源使能"的两条结论

1. **High-Z 下外部下拉不必压过内部上拉** —— 10 k~100 kΩ 都够, **不需要 1 kΩ**。
   (1 kΩ 那个值是 MSEL 那条的: MSEL 在两列里**都是 Pull-up to Vccio**, 必须压过 250 µA,
    `10k×250µA = 2.5 V` / `4.7k×250µA = 1.175 V` 都高于 `VIL max 0.7 V` ⇒ 上限 2.8 kΩ。
    **两件事别混。**)
2. 🔴 **但 High-Z 意味着脚是真浮空的, 全靠那只外部下拉** ⇒ **下拉必须真的存在且接地良好**,
   这条比阻值重要。⚠ 且 E104 上 `HSWAPEN` 挂在 SDRAM DQ2 上,
   **若配置期有人把 DQ2 拉低, `HSWAPEN` 就变 0, 全部 IO 转为上拉** —— 概率低但不是零。

### 顺带: 配置期**不受控制**的引脚(会输出高/低脉冲)

DS300 表 2-8-8 后附的列表, 设成 output/inout 时会在加载期输出脉冲:
```
EG4X20BG256   M15,M16,L12,K15,P16,L13,K1,L14,T13,R15,L16,L1,T6,P11,L10,M10,N9,P9
EG4A20BG256   L7,M6,P1,P2,C14,G5,A5,A13,C6,F7,A7,A3,B4,A4,D5,D6
```
⇒ **电源使能、屏复位、I2C 这类"配置期必须确定"的信号, 绝不能落在这些球上。**
(`eg4_2260_e104` 用的 `M12` 不在列表内 ✅; 输出脚 `H4/F15/E16/E15/C16/D11/B12/C13/B14` 也都不在。
 `K15` 在列表里但本工程用作**输入**(相位跳线), 不受影响。)
