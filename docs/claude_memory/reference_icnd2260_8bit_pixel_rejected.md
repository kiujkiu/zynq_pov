# 8 位像素模式: 芯片拒绝 (2026-09-02 实测)

## 假设与依据

【手册明确·docs/pg.txt:1096,1207】`VHEAD[23:20]: 0x3 = 像素位宽 16 位`。
那是个**4 位字段而手册只定义了这一个值**。若编码为 `(n+1)×4`, 则 `0x1 = 8 位`,
帧数据从 14,400 拍减半到 7,200 拍, 单颗上限从 11,133 翻到约 23,600 fps。

## 结果: 🔴 不成立

实现: `icnd2260_lvds_tx.v` 加 `parameter PIX_BW8`, `vh_hi` 用 `4'h1`,
S_VID 终止计数 7→3, **`pl_next` 预取时机 6→1**(漏改这个会让预取永不触发 ⇒
取不到下一像素 ⇒ 发送器卡死 ⇒ `frame_cnt` 恒 0, 实测踩过)。
构建关键字 `pix8`。

判据链完整, 结论无歧义:
```
✅ fps = 363          发送端每字确实 4 拍 (16位时 357) —— 帧内容真的减半
✅ frame_cnt 稳定递增  发送侧健康
✅ status = 0xf870    正常
🔴 屏全黑            ⇒ 失败百分之百在接收端
```
⇒ **芯片不接受 VHEAD[23:20]=0x1。16 位是唯一已知合法值。**
⇒ **单颗天花板 11,133 fps @ 12.5 位 成立**(见 [[project_icnd2260_9404fps_measured]])。

## 顺带的收获(值得保留)

修这个实验时顺手把一条**咬了三次**的关键路径修掉了:
`mot_frame0`/`mot_adv` —— 原本 `fb_addr==0` 和 `fb_addr!=fb_addr_d` 两个 12 位比较
直接喂 mode-7 计数器的同步复位, 形成 4 条进位链 + 11 级逻辑, 148MHz(6.747ns)下放不下。
今天因此三次把 WNS 从基线 -0.471 推到 **-0.740 / -0.972 / -0.801**。
各寄存一级后回到 **-0.469**(=基线), 代价只是图案平移 1 像素。
**任何往高时钟走的改动都会被这条路径绊住, 已修。**
