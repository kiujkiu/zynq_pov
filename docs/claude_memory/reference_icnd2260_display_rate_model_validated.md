# 显示帧率的模型, 已上板验证 (2026-09-02)

## 公式

```
显示帧率 = GCLK / (扫描行数 × 刷新分组 × Line_len)
GCLK     = DCLK × (P/M) × N

扫描行数 45           Line_len = 0x03 = 0x0034 = 52
刷新分组 = 0x00[15:8] + 1      (出厂 0x493C ⇒ 0x49=73 ⇒ 74 组)
N        = 2^0x00[5:4]         (出厂 0x3C ⇒ [5:4]=3 ⇒ N=8)
P        = 0x06[4:0]           M = 0x06[8:5] × 4 (mini-LVDS)
                               【手册明确·docs/pg.txt:1575-1582, :2067】F_GCLK = DCLK × P/M
```

## 实测验证

| | 0x00 | 0x06 | GCLK | 预测 fps | 实测 |
|---|---|---|---|---|---|
| 出厂 | 493C (74组, N=8) | AA44 (P/M=0.5) | 250 MHz | **1,444** | **~1,470** (差 2%) |
| 改后 | **0F3C** (16组, N=8) | **AA48** (P/M=1.0) | 500 MHz | **13,355** | 吃下发送的全部 4,000 fps |

⚠ GCLK 上限【手册明确·docs/ds.txt】**600 MHz**, 500 未超。

## 量法(唯一可行的)

图案 `dbg_pat_mode=7`(帧相位条纹, 40 列切 8 条, 第 k 帧只亮第 k mod 8 条)
+ **短曝光拍照**。亮起的条数 = 曝光窗口内芯片显示的不同帧数。
🔴 **必须 A/B 对比且发送帧率相同**, 这样未知的曝光时间在比值里被约掉。
实测 A(2.5 相位) vs B(6 相位), 而且 **A 的曝光更长却捕获更少** —— 方向与混淆项相反,
所以定性结论不受曝光不一致影响(定量则需要同一套相机设置)。

## 结论: 瓶颈从显示移交给链路

```
显示侧  16 分组 + P/M=1.0            → 13,355 fps  ✅ 够 10k
链路侧  62.5 MHz 单颗 (15,270 拍/帧) →  4,093 fps  🔴 现在卡这
        喂满 10k 需 DCLK ≈ 152.7 MHz, 而 155.36 MHz 实测芯片收不了(屏全黑, FPGA 侧完好)
```

⇒ 下一步是**二分链路上限**(142.9 / 125 / 100 / 83.3 MHz 的 cas2 bit 均已编好),
  且 **WNS 一律忽略** —— 见 [[feedback_wns_was_a_mirror_of_my_own_margin_knob]]。

## 🔴 最有用的一条推论: 扫描率是常数, 帧率和分组数在分它

```
帧率 × 刷新分组 = GCLK / (扫描行数 × Line_len) = 扫描率
                = GCLK / (45 × 52) = GCLK / 2340
```
验证: GCLK 250MHz / 74 组 = 1,444 fps ✓(实测 ~1,470); GCLK 571MHz / 16 组 = 15,251 fps ✓

⇒ **GCLK 顶到手册上限 600 MHz 时, 扫描率上限 = 256,410 次/秒。这一个数决定所有组合:**

| 帧率 | 最多分组 | 灰度级(=分组×32×8) | 位深 |
|---|---|---|---|
| 1,000 | 256 | 65,536 | 16.0 |
| 5,000 | 51 | 13,056 | 13.7 |
| **10,000** | **25** | **6,400** | **12.6** |
| 16,000 | 16 | 4,096 | 12.0 |

⚠ 灰度级公式是【推断】, 未验证。但**结论是: 10k fps 下还能保住约 12.6 位灰度,
色深不是墙, GCLK 的 600MHz 才是。**

## 链路上限 (2026-09-02 实测)

| DCLK | 结果 |
|---|---|
| 155.36 MHz | 🔴 **屏全黑**(FPGA 侧 fps=361 精确命中, 一帧不丢 ⇒ 失败在接收端) |
| **142.86 MHz** | ✅ **通过**。单颗实测 **SENT = 9,310 fps** 画面正常 |
| 62.5 MHz | ✅ 上限 4,032 fps |

⇒ 真实上限在 142.9~155.4 MHz 之间, **148 MHz 可用 `VCO_MULT_X8=166` 取到**, 待二分。
⇒ 单颗最大帧率 = DCLK / 15,270。

## 关掉读探针 (2026-09-02)

`READ_PROBE_FR=16` + `QUIET_CYCLES=8000` ⇒ 每 16 帧**停 DCLK 56 µs**(142.9MHz 下),
4,800 fps 时**每秒 300 次**。而【手册明确·docs/pg.txt:923】「如果 DCLK 作为内部 PLL
参考时钟, 则不能暂停」—— mini-LVDS 下参考就来自链路 ⇒ 每停一次全链 PLL 失锁一次,
下游芯片趁机误同步到噪声上偶尔闪。**本样板 ACK 根本没接线, 探针零收益。**
已把这两个参数透传到顶层并加 `noprobe` 构建关键字, 顺带省 3.3% 帧时间。

## 🔴 修正 (2026-09-02 17:53): 155.36 MHz **是通的**, 之前那条"全黑"作废

早先记的「155.36 MHz 屏全黑 ⇒ 链路上限在 142.9~155.4 之间」**是错的**, 错在没排除两个自造干扰:

| | 那次失败的配置 | 修正后 |
|---|---|---|
| 读探针 | **开着** —— 每 3.3ms 停 56µs DCLK, 每秒 300 次 ⇒ 全链 PLL 反复失锁 | `noprobe` 关掉 |
| `0x06` | `AA44` ⇒ GCLK = 155.36×0.5×8 = **621 MHz, 超 600 上限 3.5%** | **`AA43`**(P=3) ⇒ GCLK 466 MHz ✅ |

【实测】改正后 155.36 MHz **画面正常**, `SENT = 10,344 fps`。数字自洽:
`noprobe` 去掉探针后帧内容 15,270 → **14,755 拍**, `155.357e6/(14,755+265) = 10,343` ✓

⇒ **首次跨过 10,000 fps。** 155.36 MHz 下链路上限 = `155.357e6/14,755` = **10,529 fps**。
⇒ 手册 DCLK 上限 170 MHz ⇒ 理论 **11,522 fps**。

**教训: 拿"失败"当结论之前, 先排掉自己造成的干扰。** 那次失败同时叠了两个我自己引入的问题,
而我据此推出了一个错误的上限区间, 并基于它做了后续决策。
