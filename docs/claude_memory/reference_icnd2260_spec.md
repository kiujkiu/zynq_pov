## 🔴 三条决定可行性的硬关系

### 1. 单颗输入带宽 —— 🔴 手册自相矛盾, 必须按 166.7MHz 保守取

`datasheet V1.7` 开关特性表:
```
时钟周期 tLVCP   最小 6.00 ns    → 166.7 MHz
时钟频率 1/tLVCP 最大 170.00 MHz → 5.88 ns     ← 两者差 2%, 对不上
```
| | 按 170MHz(乐观) | **按 166.7MHz(取这个)** |
|---|---|---|
| 单差分对 (双沿) | 340 Mbps | **333 Mbps** |
| **单颗 3 通道** | 1,020 | **1,000 Mbps** |

TTL 模式: 25MHz DDR ⇒ 50 Mbps/线; 6 通道 = **300 Mbps/颗**。
⇒ **POV 必须走 mini-LVDS, TTL 差 3.3×。**

🔴 **注意 TTL 与 mini-LVDS 共用同一组球** (D1/D2/E1/E2/F1/F2 = SDI_R1/R2/G1/G2/B1/B2
= L_D2IP/IN, L_D1IP/IN, L_D0IP/IN), 由 **LVDS_EN(G3)** 切换。
⇒ **一样是 6 根线, LVDS 给 3.4 倍带宽。走单端毫无好处**, 要补带宽得堆 3.4 倍芯片,
IO 反而更多 (480 根/面 vs 144)。

### 2. 线上像素位宽**固定 16-bit**, 没有 8-bit 选项
`VHEAD[23:20] = 0x3: 像素位宽 16 位` (手册四处一致, 显示数据每通道 16-bit,
校正数据每通道 8-bit)。⇒ **"降色深省带宽"这条路不存在**, 带宽账一律按 16-bit 算。

### 3. 帧频公式 (由手册"亮度有效率"公式反推, 这是最有用的一条)
```
帧频 = GCLK / (灰度等级 × 扫描数)
灰度等级 G = (reg00[14:8]+1) × (reg01[12:0] × N)     N=reg0x00[5:4] ∈ {1,2,4,8}
             └─ 刷新分组数, 手册要求 reg00[14:8] ≥ 15 ⇒ 分组 ≥ 16
             刷新倍率 1/2/4/8 ⇒ reg01[12:0] = 128/64/32/16
```
⇒ **G 最小 = 16 × 16 = 256 (8-bit), 降不下去。**
⇒ 一帧时间 ≥ (Width_X + exp_time) × Tgclk × 扫描数 × 刷新分组数 (`Line_len` 逐行计, 见 §6)

⚠ 手册里的 **"视觉刷新率 = 刷新分组数 × 帧频" 对 POV 无意义** —— 跟
[[reference_pov_chip_selection]] 里 S-PWM 那条警告同源: POV 视角下 sub-field
和物理 slice 是同一回事。**只看帧频。**

## POV-3D 目标核算 (192×216, 30Hz 体帧率, 双面)

🔴 **先定口径 —— 我一度算错过**: 体帧率 = **2 ×** 转速 (穿轴屏半圈扫完一个体),
所以 30 Hz 只需 **900 RPM**; 且每面片/圈是 **360 (1°)** 还是 720 (0.5°) 是设计选择。
完整三档对照见 [[project_pov3d_final_target]] 的 2026-08-04 修正节。

| 口径 | slice/s/面 | **单颗需求** | vs 1,000 Mbps 能力 |
|---|---|---|---|
| 30Hz + **1°** (v3.1 现行) | **5,400** | **498 Mbps** | ✅ **余量 101%** |
| 30Hz + 0.5° | 10,800 | 995 Mbps | 🔴 余量 0.5%, 打不住 |
| 60Hz + 0.5° | 21,600 | 1,991 Mbps | ❌ 差 2× |

⇒ **按 v3.1 现行的 1° 口径, 整套方案余量翻倍, 且可只用 2 通道 mini-LVDS**
(2×333=666 ≥ 498) ⇒ FPGA 单端脚 48×2+时钟 ≈ **100**; 甚至 FPGA 直出差分
48×2 = 96 对正好用满 96 (但要改 bank 2.5V 且一对不剩, 仍建议留外置驱动器)。

### ✅ 定案口径 (2026-08-04): 603 片/圈 / 900 RPM / 偏心双面

切片数由最外圈像素间距定: `N = 2π × 96px = 603` (推导与 503 的交叉验证见
[[project_pov3d_final_target]])。每面 **9,045 slice/s**。

| 项 | 需求 | 能力 | 余量 |
|---|---|---|---|
| **单颗 mini-LVDS** | 92,160 bit × 9,045 = **833.5 Mbps** | **3 通道** = 1,000 | ✅ **20%** |
| | | 2 通道 = 666 | ❌ 不够 |
| **FPGA 单端脚** | 48颗 × 3 + 时钟 ≈ **148** | 200 | ✅ |
| FPGA 直出差分 | 144 对 | 96 | ❌ ⇒ 外置 LVDS 驱动器必需 ⚠ **仅在「不级联」前提下成立, 见文末 08-17 更正** |
| 芯片 PWM 色深 | 9,045 Hz @48扫 | G ≤ 600M/(9045×48) = **1,382** | ✅ **10-bit**, 余量 35% |
| **切片 DDR** (存16bit) | 3.38 写 + 3.38 读 = **6.76 GB/s** | 峰值 4.26 | 🔴 差 1.59× |
| **切片 DDR** (存 **8-bit**) | **3.38 GB/s** | 4.26 | ✅ **过** |
| 渲染 IP | 905 片/圈 × 15rps = 13,575 slice/s ⇒ **73.7 µs/片** | 实测 355 µs | 🔴 差 **4.8×** |

🔴 **DDR 的便宜解法**: 芯片显示只到 10-bit, 但**线上格式固定 16-bit**。
⇒ **DDR 里按 8-bit 存, PL 出口左移对齐到 16-bit** (几十个 LUT), DDR 卡点消失。
代价: 色深 10→8 bit (相对现在 1-bit 仍是 256 倍)。

### 偏心结构下的两个关键区分
- **体帧率 = 2 × 转速仍成立**, 但**由穿心的面A 保证** (面A 整屏跨方位 180.0°);
  面B 偏心 13.4mm 跨方位仅 **159.6°**, 每点每圈被扫 2 次但间隔 `2·arccos(off/r)`
  —— 外沿 159°、盲柱边只有 19°, **半圈内既不完整也不均匀**。面B 只是环带上的
  过采样填充, 不破坏正确性。
- **`fold-a` 只省链路/DDR/解码, 不省面板带宽** —— 镜像补齐是 PL 干的,
  芯片拿到的是全速流。⇒ 两面 mini-LVDS 需求相同。

### 色深天花板 = 10-bit, 不是 16-bit
```
G ≤ GCLK / (帧频 × 扫描数) = 600e6 / (10800 × 48) = 1157  ⇒ 10-bit
真 16-bit(65536) 需 GCLK 34 GHz  ❌ 物理不可能
```
⇒ **花 16-bit 的带宽, 拿 10-bit 的色深。** 这个结论跟 [[project_pov3d_led_chip_decision]]
当年否决 16-bit 的理由一致(内置 PWM 周期慢), 只是数字宽松了很多。

## 🔴 新瓶颈: 差分对数, 不再是带宽

[[reference_anlogic_dr1_fs03_eval]] 逐球核对过: **7020 CLG484 = 96P+96N (96 对) + 8 单端**,
**DR1V90 完全相同**。

| 方案 | 单颗需求 | 通道/颗 | 双面总对数 | 96 对够吗 |
|---|---|---|---|---|
| 双面 30Hz 720片 10-bit | 995 Mbps | 3 | **146** | ❌ 超 1.5× |
| **单面** 30Hz 720片 | 995 Mbps | 3 | 73 | ✅ 宽松 |
| 双面 **20Hz** 720片 | 663 Mbps | 2 (680M) | **96** | ✅ 贴边 (CLK 走单端) |
| 双面 30Hz **360片/圈**(1°) | 498 Mbps | 2 | **96** | ✅ 贴边 |

⇒ **这是第一次出现"换 FPGA"的技术理由。** [[project_pov3d_v31_delivery]] 里
"Zynq 侧一点都不紧张, 换平台解决不了任何瓶颈" 的结论**在 ICND2260 方案下失效**。
但 DR1V90 pin2pin 同样 96 对**也救不了**, 要双面全速得上 7z035/7z045 (FFG676/900) 这一档。

⚠ 另: 现在整屏走**一根 50pin 线**(CEP2)。146 对 = 292 根导线, 连接器/线束/接口板全要重做。
⚠ mLVDS 要 LVDS_25 输出 ⇒ VCCO 需 2.5V, 而现设计 bank 是 3.3V LVCMOS33 —— **整个 bank 电压要改**,
会牵动同 bank 的其他信号。

## 🔴 是 mini-LVDS, 不是 M-LVDS (这条卡过整套方案)

`编程指导 V2.8` 特性页写 "支持 TTL 或 **m-LVDS**", §3.2 标题却写 "**Mini-LVDS** 模式"。
两者不是一回事: **M-LVDS**(TIA/EIA-899) 是多点总线, 一对时钟可挂 32 个节点;
**mini-LVDS** 是 TI 的显示屏点对点接口。差别直接决定时钟要几对。

✅ **datasheet V1.7 版本历史给了权威答案**:
```
0.6  2022/09  添加 m-LVDS 特性
1.1  2023/01  修改 m-LVDS 为 mini-LVDS      ← 厂家自己纠正
```
⇒ **是 mini-LVDS, 点对点。编程指导 V2.8 特性页那句 "m-LVDS" 是没清干净的旧文案。**
⇒ **时钟不能总线广播, 每颗要独立时钟对。**

## mini-LVDS 电气参数 (datasheet V1.7, VDD=3.8V)

| 特性 | 符号 | 值 |
|---|---|---|
| 差分输入电压 | VID | **±100 ~ ±600 mV** |
| **共模输入电压** | VIC | **1.1 ~ 1.3 V** ← 窄 |
| 差分阈值 | VTH/VTL | ±100 mV |
| 输入电流 | IIN | 10 µA ⇒ **高阻, 无内部终端** |
| Module chain 匹配电阻 | RBD | **100 Ω** (80~120) |
| Data chain 匹配电阻 | RDC | **200 Ω** (160~240) ← 注意不是 100 |
| 建立/保持 | tSTU/tHLD | **1/4 tLVCP = 1.5 ns @166.7MHz** |
| 采样相位可调 | — | 1/8, 1/4, 3/8 tLVCP (±0.7ns 调整余地) |

### ⇒ 标准 LVDS 驱动器能用, 但共模必须卡
```
标准 LVDS driver: |Vod| 247~454 mV  ✅ 落在 VID 窗内
                  Voc  1.125~1.375V ⚠ 上端超出 VIC(1.3V) 75 mV
```
**必须选 Voc 典型 1.2V 且上限 ≤1.3V 的器件**, 不能随便抓一颗 LVDS driver。
外部终端要自己放: 48 颗 × 4 对 = **192 个精密电阻**上转子。

## ✅ 落地方案: FPGA 出单端 → 外置 LVDS 驱动器 → 差分进芯片

**这是唯一"不降规格、不换 FPGA"的路** (2026-08-04 用户提出, 已核算成立):
```
FPGA 直出差分:  48颗 × 3对 × 2脚 = 288 脚      ❌ 超 7020 的 200
外置驱动器:     48颗 × 3根单端 + 时钟~4 = 148 脚 ✅
驱动器通道:     144 数据对 + 48 时钟对 = 192 对
```
**选型: 用 4 通道驱动器, 一颗管一个 ICND2260 的「3 数据 + 1 时钟」** (48 颗),
或 8 通道塞 2 组 (24 颗)。🔴 **别把时钟单独放一颗** —— 跨器件 skew 会吃掉 1.5ns 预算;
同片内通道间 skew 通常 <200 ps。

附带好处: FPGA bank 可保持 LVCMOS(甚至降 1.8V 减 SSO), **不用为 LVDS_25 把整个 bank 改 2.5V**。

### Zynq 单端 340 Mbps 能不能出? ✅ 能
🔴 **Xilinx 不公布 LVCMOS 每脚速率上限** (DS187/DS181/UG471 全查过, 没有这张表)。
- 之前记忆里"LVCMOS33 上限 300 Mbps"是**安路 DR1V90 手册的数**, 套到 Xilinx 上是引用错对象。
- DS187 Table 48: **DDR LVDS transmitter (OSERDES) 950 Mb/s(-1) / 1250(-2)** ⇒ IOB 通路余量 2.8×。
- 真限制是 **SSO/SSN**, UG471 让用 **Vivado SSN Predictor** 按实际 pin plan 实算。
  本例负载极轻(驱动器输入 ~5pF + 板上短线) ⇒ 可用最低驱动 4mA + FAST, SSO 可控。
  **148 根同时切换, SSN Predictor 这一步不能省。**

## 🔴 2026-08-17 重大更正: 2260 **自带 mLVDS 输出, 可级联** ⇒ FPGA 只驱动链头

上面"外置 LVDS 驱动器是必需项"的前提是**每颗都要 FPGA 单独驱动**, 这条**错了**。
编程指导 V2.8 引脚表 (第 5-6 页) 逐球核对:

| 球号 | 名字 | 作用 |
|---|---|---|
| D1/D2, E1/E2, F1/F2 | L_D2IP/IN, L_D1IP/IN, L_D0IP/IN | 3 对数据**入** |
| G1/G2 | L_CKIP/IN | 时钟**入** |
| I15/I14, J15/J14, K15/K14 | L_D2OP/ON, L_D1OP/ON, L_D0OP/ON | 3 对数据**出**(转发下一颗) |
| L15/L14 | L_CKOP/ON | 时钟**出** |

`VHEAD[19:16]=级联芯片数(n+1)` + `DEVICE[3:0]` ⇒ **一条链最多 16 颗**;
§5 "按照级联顺序进行图像数据发送, 先发第一级芯片的图像数据" ⇒ **链内共享同一条链路带宽**。

### ⇒ 链长由「片/圈」决定 (这是新的主设计旋钮)
```
链路能力 = 3 对 × 333 Mbps = 1,000 Mbps
单颗每片 = 40px × 3 × 16bit × 48扫 = 92,160 bit   ← pixel#0..#39 固定 40 个, 不可截断(§5 图)
单颗需求 = 1.3824 × N(片/圈) Mbps  @900RPM
```
| 颗/链 | 最大 片/圈 (留 15% 余量) | 链数(双面48颗) | FPGA 差分对 | 总 PL IO |
|---|---|---|---|---|
| 1 | **629** (603 口径 ✅ 余量 20%) | 48 | 192 | 439 ❌ |
| 2 | 315 | 24 | 96 (时钟外扇出则 73) | 223 ❌ / **177 ✅** |
| 3 | 210 | 16 | 64 | **151 ✅** |
| 4 | 157 | 12 | 48 | 115 ✅ |

⚠ 别贪整数: 360 片/圈挂 2 颗 = 995 Mbps, **余量 0.5%**, 与 0.5° 口径同一个坑, 不算数。

⇒ **保 603 双面全速 ⇒ 192 对 ⇒ 外置驱动器仍是唯一路 (下节仍成立)。
   愿意降到 ~315 片/圈 ⇒ 2 颗/链, 驱动器一颗都不要, 177 脚直出。**
⇒ 换 FPGA 也救不了 603 双面: 7z045 FFG900 只有 **181 对 < 192**, 要 K7-325T FFG900(250 对) 那一档。

### 单端方案精确 pin 账 (2026-08-17 重算, 取代上面的 148)
144 数据 + 6 时钟(每 8 颗驱动器一根, 板上再短距扇出) + 7 控制
(I_SYNC/RSTN/SCL/SDA/光电/UART×2) + 6 (48 路 ACK 经 8:1 mux) = **163 / 200** ✅ 余 37。
ACK 链内是菊花链 (ACK_I←下一颗 ACK_O, 只有链头回 FPGA), 首期不做回读则再省 6。

**这条路能不能成, 卡在四关, 顺序照做**:
1. ✅ **SSN — 2026-08-17 实测已过, 不是瓶颈**。150 根摊 4 个 HR bank, `report_ssn`
   6 组配置全 `Passed 0/150`; 天花板 **196 根 @DRIVE 4 仍过 (+56.6%)** ⇒ 真限制只是 200 根 PL IO。
   **定案 LVCMOS33 / DRIVE 4 / SLEW FAST (+66.4%)**, DRIVE 8 是退路 (+30.9%)。
   🔴 三条反直觉: ① **LVCMOS18 比 LVCMOS33 差** (46.5% vs 66.4%, 预算按 VCCO 缩放)
   ⇒ 上文"降 1.8V 减 SSO"作废; ② **7 系列 report_ssn 与数据率无关** (25MHz 与 166.7MHz
   报告逐字节相同), 它是 UG471 静态 SSO 预算, **不等于 333 Mbps 板上能跑**, 仍需板级 SI;
   ③ DRIVE ≥12 时 Vivado 偷换负载模型为 `FP_VTT_50`, 看报告必须连 `Off-Chip Termination` 列一起看。
   ⚠ `help report_ssn` 的器件列表没列 Zynq, 但实际支持 (`SSN_REPORT`=1, Production 数据), 别被吓退。
   证据: `pov3d/ssn_2260/` (CONCLUSION.md + 19 组报告 + placed dcp); 详见
   `mlkpai_fs03/docs/design_icnd2260/00_scheme_and_pin_budget.md` §4 关 1。
2. 🔴 **驱动器 Voc** — 见下节, 通用件纸面超窗 75mV。**直接向映己鸿鹄要 2260 参考设计用的型号**。
3. **时钟-数据 skew** — 1.5ns 预算, 3 数据+时钟必须同封装; 时钟若多经一级扇出要等长补偿或用芯片采样相位调整(±0.7ns)。
4. **线束** — 192 对 = 384 根导线 + 192 个终端电阻上转子, 现在只有一根 50pin。BOM/机械最贵项。
