# KR7.3 修正: 16 位计数回绕 (2026-10-16, dr1v90 分支 task/kr73-wrap)

## 问题
10-15 实转 1 h 判通过时留了一条"16 位计数回绕要补"。PL 的"写完片"计数 (0x8000483C, 低 16 位 = A 面, 高 16 位 = B 面) 是自由回绕的 16 位计数。
583 rpm 下每 10 s 约写 5.9 万片, 60 s 窗口约 35 万片, 已经会回绕 (甚至整圈整圈地丢)。差值若直接相减 / 变负当 0, 完成率会被算得极低; 只做 `& 0xFFFF` 在增量 >= 65536 时又会少算整圈。

## 改了什么
- `board/voxrx/wrap16.h` (新): `wrap16_d` 模 65536 差值; `wrap16_u` 用 32 位触发计数增量做参照, 补回整圈回绕。voxslice PLSTAT 的"写完 A/B"和完成率改用它。
- `soak8h/wrap16.py` (新): 同算法的 Python 版 + `plmon` 子命令, 把板上 `pl_mon.log` 按小时重算完成率 (`--old` 给旧算法对照)。
- `soak8h/soak_judge.py`: 新增 S3b, 取回了 pl_mon.log 时用 wrap16 独立复算每小时未完成率 (<= 0.1 %), 与 PLSTAT 窗口算法互相印证。
- 卡死监测 (`wr & 0xFFFF` 比较, soak_board.sh 第 89 行, v4_board.sh / d15b_board.sh 同写法): 只比"相等", 1 s 内不可能恰好差整圈, 回绕安全, 逻辑不变 (仅 soak_board.sh 加了注释)。
- 未改: `povstat_ext.c` 的 D16 与 miss/late/drop —— 那是**饱和**计数 (到 0xFFFF 停住不回绕), 差值为负只表示复位, 取 0 是对的。
- 验收: `kr73_wrap/verify.sh` (单测含跨回绕 / 恰好 65535->0 / 1000 步长跑 / 1 h 合成日志 / 重判读), 5 项全 PASS。
