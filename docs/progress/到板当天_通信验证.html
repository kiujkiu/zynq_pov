0.1 先讲结论

  • V1 上行线速定 600M (用户 10-27 拍板)。DR1 的 oDDRx2 实测: 400M、600M 逐位正确; 700M 边缘, 开始丢位; 750M、800M 只发偶数位 (每位发两次)。原 800M 作废, 下文凡写 800M 的地方都按 600M 读。600M 时每片上行 146 µs, 占 V1 片率 (357 片 × 12 rps = 4284 片/s) 的 63%, 够用。桥位流不用为线速改: 桥上行 PLL 跟转发时钟 (线速/8, 600M 时 75 MHz) 走。
  • 面 A 链路已通: 电平、握手、训练对齐、PRBS (600 s 和 1 h 都 0 误码)、边带双向、真实帧格式出片 10 min 都过了, 数字见 0.2。
  • 桥 flash 已烧正式版: 面 A e60cp (md5 e19f344a, USERCODE E405, BUILD 26102760), 面 B e60cb (md5 d6de18bc, USERCODE FA0B, BUILD 26102740)。上电就是它们, 通信验证不用再灌桥 (脚本加 --skip-bridge)。
  • 灌桥不再用 PC: 两块桥都插上后 JTAG 菊花链闭合 (TDO 经面 B 转接板回主控), 主控用 gw5a_sram --tdo-pulldown --chain 2 --pos N 带回读校验地灌 SRAM, 也能让桥 reload flash (D80, 命令见 5.2)。只有改 flash 还要 PC 下载器; D81 在做主控远程烧 flash。
  • 转发时钟不用再手动切: D78 新主控位流复位就是 fwd=2 (线速/8)。10-26 版里的几样东西都作废: COMM_UL_FWD=2 / ul fwd 2 手动步骤、"桥位流更新暂用 PC 下载器" (--bridge-load pc)、_work/d65c_out 桥位流 (A 版片用的)、D72 的 800M 主控三档。
  • 硬件一次定型, 不改板 (10-26 已定, 不变): SoC 底板 H1/H2 与 FS03 J11/J12 对调, 主控位流一律 POV_HSWAP=1 (面 A 进 bank11, 面 B 进 bank33), 这就是 V1 的正式做法; J1 与 J2 都 2.5 V。桥转接板 R221–R223 (TDI/TMS/TCK) 和 R219 (TDO) 是 10k 下拉, 由 gw5a_sram 的开关吸收, 不用改。

# 在主控板上 (root)。目录里放 gw5a_sram (= d33_jtag/gw5a_sram_aarch64, D80 版, task/d80-jtag2chain) 和 bridge.gws

# 先确认两块桥都上电、都有状态帧 (sbd info / sbd --face b info): 下拉开关放开后, 预检已分不出"桥没上电"

$J --pos 0 status                               # 面 A 现状: flash 正式版 USERCODE 0000E405
