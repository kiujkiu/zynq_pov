§1 起因：要做一台体显示器

目标是做一台能显示真 3D 影像的体显示器（Volumetric Display）。原理是一块 LED 板高速旋转，在不同角度上点亮不同图像，视觉暂留（POV）把所有角度合成成「漂浮在空中的 3D 物体」——没有眼镜、多角度可看，整个装置像透明球体里的全息影像。

🔴 第一性约束：数据量。所有架构决策都从这一条推出来

最容易被忽略、但决定了一切的一节。先算 3D 体的数据量，再看哪条路可行：

方案 A · 把完整体素送上去 体积 = 160 × 160 × 180 = 4,608,000 voxel × 3 byte = 13.8 MB/帧 @30 Hz = 414 MB/s = 3.3 Gbps ← 任何 WiFi 都做不到 ❌ 方案 B · 主机端算好成品切片直接送 360 片 × 160 × 180 × 3 byte = 31 MB/圈 @30 Hz = 930 MB/s = 7.4 Gbps ← 比体素还糟 ❌ ⇒ 「主机把图算好直接送过去」这条最简单的路根本走不通。 ⇒ 必须把渲染工作分给旋转端 —— 传压缩的 3D 描述，板端实时切片。

🎯 这一条是整个项目架构的根。转子上之所以要放一颗带 CPU 又带可编程逻辑的芯片，不是因为「这样比较好」，而是因为把渲染放在固定侧、只传结果，链路差两到三个数量级。后面所有的选型——FPSoC、桥接 FPGA、板端渲染 IP——都是这一条的推论。

§2 怎么走到今天：四次转折

四个月里指标翻了几倍，但每次变化都是被实测数据推着走的，不是纸面优化。

转折一：WiFi 从 2 Mbps 到 172 Mbps —— 换板 + 自编内核
ESP32 的 ~2 Mbps 完全喂不饱。而鹿小班没有 USB host ⇒ 换米联客 FS03（同 XC7Z020，带 USB3320 真 USB Host + 出厂 Linux）。自编 linux-xlnx 6.6 内核 + mt7921u 无线栈，插 MT7921AU dongle → 连 AP → 端到端打通。提升约 80×。
同期定下一条至今有效的架构原则：timing-critical 代码全部搬到 PL，DDR 帧 buffer 成为 Linux ↔ PL 的唯一契约。
07-13
ICND2047 共阳双屏方案（四份子文档）
13 rps · 360 片/圈 · 26 fps 体帧率 · 3-bit BCM。原文自评「预算 213.7 µs/片，余量 <1%，零浪费设计」。这套方案后来被 2260 取代——不是因为慢，是因为没有余量。
08-27
转折二：判决 —— 瓶颈在连接器，不在芯片
逐脚回查 CLG484 球号发现：FS03 通过 CEP1+CEP2 只引出 96 个信号 / 48 対差分，而方案需要 165 根单端。反推片/圈上限只有 210，不是 603。
⇒ 换 FPGA 一根线都不多给你。由此定下投入顺序：架构决策 → 自制板 → 器件档次，器件排最后。

§3 现在卡在哪

🔴 一句话：全部工作卡在一个还没做的决定上 —— 灯板宽度。

邮票孔 168 焊盘 @1.0 mm = 168 mm 长的一排，而灯板只有 160 mm 宽，单边放不下。外形不定 ⇒ 原理图能画、PCB 画不了 ⇒ M1 一天都动不了 ⇒ M2 动不了 ⇒ 后面全部。

推荐方案 (d)：延长区做成 ≥175 mm 的凸台，LED 区仍 160 mm。延长区没有 LED 可以比本体宽，且它在旋转内径侧、加宽对转动惯量影响小。四个方案里代价最小。

除此之外的现状可以一句话概括：九堵墙倒了 4 堵（实测）、纸面过了 4 堵、剩 1 堵（亮度）从头到尾没碰过；接口已冻结、排布已定案、选型两级开放、layout 外发。

§4 六个闭环任务 下发给硬件

「闭环」= 把一个还没有答案的问题变成有答案，并且答案能被别人复核。每个任务给出：入口条件（什么时候能开始）· 动作 · 判据（怎么算闭上了）· 产出物。
🟢 标记的三个不占 PCB 设计的手，可以立刻并行开始——它们不在关键路径上，但决定的是整机指标本身。

D🟢 亮度闭环（墙⑨）可立刻开始 · 不占 PCB 的手
入口无。现有单颗 2260 台架就能做，不需要整机、不需要转起来
背景满白规格上限 145 W（已含扫描：2260 只有 120 个恒流通道，任一时刻只有一个行管导通），而转子供电只有 48 W。出路是调低电流设定（寄存器 0x2d/0x3d/0x4d 的 IREF 0.1~0.4 mA × igain+1，R 0.15~9.6 mA / G-B 0.1~6.4 mA，最低档只有最高档的 1.6%）+ 内容不是满白。电容解决的是行切换与 PWM 的 di/dt 尖峰，救不了持续功率。
动作把 IREF 从最低扫到最高，测实际亮度与电流的曲线。已知红色能从 0x2d 拉 5.3×，G/B 从没试过（2260 的 G/B 电流只有现役 ICND1069 的 0.356×）
判据给出一张「电流设定 → 实测亮度」曲线，并回答：在 48 W 能供的电流下（约规格上限的 24%，R≈2.3 mA / G-B≈1.5 mA per 通道），亮度够不够看
为什么它同时决定无线供电的规格，而且是九堵墙里唯一一条从项目开始到现在一次都没碰过的

F🟢 屏体路线闭环尽早 · 周期最长
入口无
背景采购 09-10 回复：COB 打样周期 3 个月。而屏体规格要等 C 闭合才能定 ⇒ 最早 11 月中下单 ⇒ 2027-02 中到货，撞进春节停工窗。整机排期里所有其它环节的机动空间加起来都不到 3 个月
动作① 自制方案的单位成本与良率估算 ② P0.78 间距下自制的工艺可行性（0.78 mm 很密，要跟工艺方确认）③ 与 COB 做一次完整对照（成本 / 周期 / 迭代次数 / 良率）
判据出一份自制 vs COB 的对照表，四个维度都有数字，并给出选定路线
为什么整机最大一笔开销（82,944 px）。而且 3 个月周期意味着一次改版就吃掉一个季度——验证板阶段大概率不止做一版

🟢 D、E、F 三条为什么要现在就排：它们都不占 PCB 设计的手（一个是台架电测、一个是机械、一个是询价与工艺调研），可以和 A/B/C 完全并行。而它们决定的是整机指标能不能达成——亮度不够、转速上不去、屏体来不及，这三件里任何一件都能让前面所有 PCB 工作白做。

反过来说：它们不在关键路径上，所以最容易被一直往后拖。墙⑨从五月拖到现在就是这么来的。
