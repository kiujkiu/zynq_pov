# POV3D 软件 / FPGA 20 日计划

- 日期：2026-10-09
- 口径：只算 FPGA + 板端软件 + 上位机，**不算硬件改板 / 转子 / 采购等待**
- 工期：20 个工作日（用户口径）
- 主验收：DR1M90 追上 Zynq-7020 现役 **ICND2047 160×180 偏心双面体像**；后半把 **GW5A 桥 + 2260 软件路径**做完，回板后只剩接线联调
- 记忆索引：`zynq_pov/docs/claude_memory/project_pov3d_sw_plan_20d_2026_10_09.md`

---

## 0. 这 20 天解决什么

现役 **Zynq-7020 + ICND2047 160×180 双面** 已经端到端跑通体像。DR1M90 在 2026-09-22 只做到 GP0 探针 + WiFi，**从没接过 2047，也没有显示位流**。

```
已跑通 (7020):  PC 渲染 → WiFi/直写 → DDR → PL 取片 → 双面 2047 → 电机转 → 体像
DR1M90 现状:    出厂 Linux + WiFi 159 Mbps + configfs 加载 + GP0 读写  (停在这里)
本计划终点:     同一套 2047 上 M90 功能对齐 7020；GW5A/2260 固件两模式齐，硬件回来可接
```

M2 是对内「7020 已跑通」的对齐。M4 是阶段①软件封板。2260 整板转起来、新灯板回板，不进这 20 天。

## 1. 现行产品口径（09-22，别用旧数）

| 项 | 验证板（阶段①） | 量产目标板（阶段②，本计划不验收） |
|---|---|---|
| 灯板 | 0.9375 mm / 160×180 | 0.78 mm / 192×216 |
| 片/圈 | 503 | 603 |
| 转速 | 1050 RPM | 同左 |
| 体帧率 | 35 Hz（= 2 × 17.5 rev/s） | 同左 |
| 色深 | RGB565，每像素 16 bit | 同左 |
| 驱动 | ICND2260（已锁） | 24 颗/面 @48 扫 |
| 刷新需求 | 8,802 slice/s/面 | 10,552 slice/s/面 |
| 对 2260 实测 11,000 fps | 余量 ~25% | 余量 ~4%，偏紧 |

硬约束（本计划当边界，不展开做）：

- 转子供电 = 无线电力 48 W，不是滑环。跨界全非接触：WPT + WiFi + 光电索引。
- WiFi 算在链路里。内容传**体素表**，不传全切片。
- 芯片只锁 2260。验证板主控 = **DR1M90**，桥片 = **GW5A**。
- 主控和桥都在转子上。解码 + 帧缓冲必须和驱屏绑在同一颗芯片。

旧口径作废：1800 RPM = 30 Hz、只能 900 RPM、滑环过 43 A、只传切片。

## 2. 开工基线（2026-10-09）

### 已经有、不用重做

- 7020：2047 偏心双面体像、3-bit BCM、`fold_a`、PL 三引擎 lz4、推流 10–12 fps
- DR1V90：08-28 点亮过同一套 2047（可抄寄存器，**位流不能直接灌 M90**）
- DR1M90：出厂 Linux aarch64 / 6.1.111-rt42；WiFi TCP **159 Mbps**（外推 ~210）；eth0 941；`bootgen -arch dr1m90`；configfs 加载；GP0 MAGIC 正确；ATF 加载后 `SRST_CTRL2` `0x1100 → 0x1133`（GP0 复位风险已排除）；现有 RISC-V PS 封装改器件串即可，不必重做 ARM IP
- 用户态：`iperf3` / `ksink` / `pov_rxd_aarch64` **能编**（Makefile 写明：没有 povmem + 显示 PL **跑不全**）
- GW5A：全功能桥 BIT:OK，dclk Fmax 152 MHz；ACG525 冒烟 PASS；4 lane @400M 环回 PASS

### 还缺（本计划要补）

| 项 | 状态 |
|---|---|
| 2047 显示位流 `DR1M90GEG484` | 没有（`td_panel` 仍是 V90 / 08 月） |
| `povmem_dr1.ko` aarch64 | 没有（Makefile 写死 `ARCH=riscv`） |
| `povctl` aarch64 / CMA 96MB dtb / `povboot.sh` 架构适配 | 没有 |
| 接 2047 双面 / 推流体像 | 没做过 |
| GW5A 86 对全功能桥上机 | 只做过 smoke，没接 DR1M90 / 2260 |
| JTAG 加载线 aarch64 | 未移植 |

机制假设（D3 必须验，不是已实测）：V90 的 `cpy` 162 ms 和 PL 解码 37 帧卡死都是 RISC-V 专属。A35 上 `pgprot_writecombine` 应生效，判据是 **`cpy` 落 20–26 ms 档**。

## 4. 逐日

现成台架假设：DR1M90 开发板、现役 2047 双面、ACG525、PC 推流。屏和电机只在 **D4–D5、D9** 两段占用。D1–D3 可与占屏工作错开。

### 第 1 周 · M1（D1–D5）

| 天 | 做什么 | 完成标准 |
|---|---|---|
| **D1** | 显示工程改 `DR1M90GEG484`，`bootgen -arch dr1m90`，加载脚本补 `mount configfs` | 出 `pov_m90.bin`；overlay 后 `fpga0=operating`；GP0 是显示 MAGIC，不是 `B2B` |
| **D2** | 时序 / HP 使能 / 寄存器块对账。加载失败只修加载，不接屏 | `SRST_CTRL2` 仍是 `0x1133`；未映射地址不挂死 |
| **D3** | `povmem` 对 M90 内核重编；CMA 96MB dtb；量 `cpy` | insmod 成功；**`cpy` 20–26 ms**（落到 162 ms 则当天改策略，不能假装没看见） |
| **D4** | `povctl` aarch64 + `povboot.sh` 去掉 `_riscv64` 写死 | `povctl fb solid` 单面全白 |
| **D5** | 双面、`dual_en`、`PHASE_B`、`0x28` 面 B 基址 | 两面同时亮、无花屏。对照 7020：`POV_CTRL=0x01680005`，`mirror_a=0` `mirror_b=0` `PHASE_B=180` |

D1 与 D3 不占屏，可并行。凡从 Linux 加载的位流必须挂 GP0 从机（没挂会单核挂死）。

### 第 2 周 · M2（D6–D10）

| 天 | 做什么 | 完成标准 |
|---|---|---|
| **D6** | `pov_rxd_aarch64` 接上 `povmem` + 显示 PL | 本机 lz4 帧能翻页，不经 WiFi |
| **D7** | WiFi 推流（现成 PVS1 / `povsh`） | 静止台架 `flip` 稳定，空闲动画让位 |
| **D8** | 3-bit BCM、`n_slices`、`half_scan` 从 7020 抄寄存器 | 棋盘格 / 斜坡和 7020 同图 |
| **D9** | 偏心几何：`gap_mm` 沿用 13.8（2047 现役） | **电机转起来体像方向对**。静止比两面没有意义 |
| **D10** | PL lz4：能上就上；`cpy` 已快则 CPU lz4 可先顶 | 内容帧率到 **10–12 fps 档**（对齐 7020 现役，不设 15） |

D10 退路：PL 引擎移植卡壳就 CPU 解码收口，不挡 M2。连推 ≥200 帧才算过（V90 上 37 帧才卡）。

### 第 3 周 · M3（D11–D15）

不依赖新 PCB。环回和现有 2260 单板就够把固件闭环。

| 天 | 做什么 | 完成标准 |
|---|---|---|
| **D11** | `gw5a_bridge` 全功能 bit 与 ACG525 可下载脚位分开 | 再出一版可联调 bit（不是 smoke） |
| **D12** | DR1M90 `uplink_tx` 改器件串（09-18 的 800M RTL 已有） | 主控侧综合过；GP0 能开/停发送、读误码计数 |
| **D13** | 主控↔桥环回（接得齐几对算几对；接不齐先 4～6 lane） | ≥1 时钟 + 若干数据 lane **零误码** 连坐 ≥3 min（400M 已在 `gw5a_loop` 上过） |
| **D14** | JTAG 加载线 aarch64（`bridge_load` / 文件名 / ELF 机型断言） | DR1M90 能给 GW5A 灌 SRAM，不必手开 Programmer。判据必须断言 `ARM aarch64`，数 `R_RISCV` 会空过 |
| **D15** | 2260 序列：显示 60 扫 / 压测 48 扫，同一 DCLK 166.67 | 现有 2260 样板出已知图案；配对 1 串 2 配置能写入 |

### 第 4 周 · M4（D16–D20）

| 天 | 做什么 | 完成标准 |
|---|---|---|
| **D16** | 上位机：160×180 / 503 片口径；体素表推流 | 同一套 host 能打 2047（回归）和 2260（新口径）。不要传全切片 |
| **D17** | 压测模式软件：假 24 链、18+1 lane、603 片数据量 | 不接满屏也能把主控/桥负载跑满，误码计数可见 |
| **D18** | 开机：`povboot` AUTOBOOT、configfs、加载显示 bit、起 `pov_rxd`/`povsh` | 冷启动一次到可推流；热重启不丢，或脚本 15 分钟恢复 |
| **D19** | 远程：转动后没串口，状态/误码走 WiFi；加载失败不碰 GP0 | 只连 WiFi 能看 fps / miss / 桥状态 |
| **D20** | 缓冲：M1–M3 剩缺陷 + 7020 vs M90 对照表 | 书面：这 20 天交付了什么、硬件回来接哪几个口 |

紧的三天：D5 点屏、D9 转起来看体像、D13 环回。第 4 周整周是缓冲。

## 5. 验证板固件两模式（M3–M4 写入，M4 验收）

同一 DCLK **166.67 MHz**：

| 模式 | 用途 | 参数 |
|---|---|---|
| 显示 | 看图、调驱动 | 60 扫，n_slices=503，7,545 slice/s/面 |
| 压测 | 按目标板时序打满 | 48 扫（49–60 行不亮），n_slices=603，9,045 slice/s/面；上行按 24 链 + 18 数据 + 1 校验，多出的链走假数据进误码计数 |

产品仍是 24 颗 / 48 扫目标板。验证板 60 扫能转、能压测，不等于量产刷新余量已过。
