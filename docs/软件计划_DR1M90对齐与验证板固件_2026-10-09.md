## 0. 这 20 天解决什么

现役 **Zynq-7020 + ICND2047 160×180 双面** 已经端到端跑通体像。DR1M90 在 2026-09-22 只做到 GP0 探针 + WiFi，**从没接过 2047，也没有显示位流**。

```
已跑通 (7020):  PC 渲染 → WiFi/直写 → DDR → PL 取片 → 双面 2047 → 电机转 → 体像
DR1M90 现状:    出厂 Linux + WiFi 159 Mbps + configfs 加载 + GP0 读写  (停在这里)
本计划终点:     同一套 2047 上 M90 功能对齐 7020；GW5A/2260 固件两模式齐，硬件回来可接
```

M2 是对内「7020 已跑通」的对齐。M4 是阶段①软件封板。2260 整板转起来、新灯板回板，不进这 20 天。

- 转子供电 = 无线电力 48 W，不是滑环。跨界全非接触：WPT + WiFi + 光电索引。

## 2. 开工基线（2026-10-09）

### 已经有、不用重做

- 7020：2047 偏心双面体像、3-bit BCM、`fold_a`、PL 三引擎 lz4、推流 10–12 fps
- DR1V90：08-28 点亮过同一套 2047（可抄寄存器，**位流不能直接灌 M90**）
- DR1M90：出厂 Linux aarch64 / 6.1.111-rt42；WiFi TCP **159 Mbps**（外推 ~210）；eth0 941；`bootgen -arch dr1m90`；configfs 加载；GP0 MAGIC 正确；ATF 加载后 `SRST_CTRL2` `0x1100 → 0x1133`（GP0 复位风险已排除）；现有 RISC-V PS 封装改器件串即可，不必重做 ARM IP
- 用户态：`iperf3` / `ksink` / `pov_rxd_aarch64` **能编**（Makefile 写明：没有 povmem + 显示 PL **跑不全**）
- GW5A：全功能桥 BIT:OK，dclk Fmax 152 MHz；ACG525 冒烟 PASS；4 lane @400M 环回 PASS

### 还缺（本计划要补）

| 项 | 状态 |
|---|---|
| 2047 显示位流 `DR1M90GEG484` | 没有（`td_panel` 仍是 V90 / 08 月） |
| `povmem_dr1.ko` aarch64 | 没有（Makefile 写死 `ARCH=riscv`） |
| `povctl` aarch64 / CMA 96MB dtb / `povboot.sh` 架构适配 | 没有 |
| 接 2047 双面 / 推流体像 | 没做过 |
| GW5A 86 对全功能桥上机 | 只做过 smoke，没接 DR1M90 / 2260 |
| JTAG 加载线 aarch64 | 未移植 |

机制假设（D3 必须验，不是已实测）：V90 的 `cpy` 162 ms 和 PL 解码 37 帧卡死都是 RISC-V 专属。A35 上 `pgprot_writecombine` 应生效，判据是 **`cpy` 落 20–26 ms 档**。

## 8. 插入项（2026-10-10 用户定：插进计划，先做 X1）

起因：梳理"DR1M90 开发板够不够驱目标灯板"。结论：直驱不够（目标板双面 146–192 对，FS03 只引出 48 对）；
经 GW5A 桥对数够（26–32/48 对），但目标口径（192×216 / 603 片 / 1050 RPM ⇒ 每片 94.8 µs）下有两条要实测：

| 项 | 做什么 | 判据 | 工期 | 位置 |
|---|---|---|---|---|
| **X1 DDR 并发读效率（M90）** | 基于现成的 `dr1v90/measure/01_hpbw`（08-27 双口综合通过、从未上板）：移植 M90，HP 时钟从 50 MHz 提到 100/200 MHz（64 位 HP 在 50 MHz 单口只有 400 MB/s），加切片模式（每列 432 B = 4 笔 AXI3 突发、列地址散布、提前 2 列），两路各占 HP0/HP1；对照 7020 量具 `zynq_pov/eta_test`（η=0.950） | 两路同时跑，每片 ≤ **94.8 µs**（1050 RPM），留 20% 则 ≤ **75.8 µs**；附 η = 两路合计 MB/s ÷ 2,133 | 2 天 | **现在做**（不占屏，与 D1/D3 并行） |
| **X2 上行 1.0G 经 FS03 排针** | DR1M90 发上行真帧 → FS03 CEP → 跳线 → ACG525 收（gw5a_bench 的 rx 侧），扫眼 + 误码 | 每对 1.0 Gbps，≥ 4 lane 零误码连坐 ≥ 3 min；拆 33 Ω 排阻 | 2 天 | 并入 D12–D13（原 800M 环回改成 800M + 1.0G 两档） |

为什么不能直接用 7020 的数：DR1 只有 2 个 HP 口（每口手册 1600 MB/s），DDRC 端口按 master 还是按地址分仍未决；
7020 的 81.9 µs/片在 1050 RPM（94.8 µs）下只剩 14% 余量，不到 20%。

**X1 结果（2026-10-10 实测，`dr1v90/measure/07_eta_m90/README.md`）**：hclk 200 MHz，双口切片 ot=8 合计 **1786 MB/s，η = 0.837**
（7020 0.950）；每片**均 92.9 µs ≤ 94.8 裸过、余量仅 2%**，最慢一片 95–98 µs（长跑 133 µs）逐片不过，留 20%（75.8）**不过**。
单口 1556 MB/s（口峰 97%）；双口连续读也只 1789 ⇒ 天花板在 DDRC：PSTAT 只亮端口 2，HP0/HP1 同进一个 DDRC 口。ot ≥ 4 饱和。
⇒ 1050 RPM 只够"平均刚好"，需片间 FIFO + 压 CPU DDR 流量；要 20% 余量须降到 ≈ 890 RPM 或减每片字节。

工期影响：X1 + X2 共约 4 天；D11 已于 10-09 提前完成（gw5a_bench），净增约 3 天 ⇒ **总 ≈ 23 个工作日**。

## 10. 远程升级 (X4, 2026-10-10 用户定按此方案)

**原则: 转子上所有可升级的东西都集中在 DR1M90 的 SD 卡上, 远程升级 = 经 WiFi 安全地换卡上的一组文件。**

| 对象 | 存放 | 加载方式 | 远程升级 |
|---|---|---|---|
| 板端程序 (pov_rxd / povsh / 脚本) | SD 卡槽位 | 进程重启 | ✅ |
| DR1M90 PL 显示位流 | SD 卡槽位 | configfs 运行时加载, 不重启 | ✅ |
| GW5A 桥位流 (含 2260 寄存器表) | SD 卡槽位 | **每次上电由 DR1 经 JTAG 灌 SRAM** (任务 1.1.8) | ✅ (不写 GW5A Flash) |
| GW5A Flash | 只放出厂"保底"位流 | 上电自加载, 随后被 DR1 覆盖 | ❌ 永不远程写 |
| 内核 / 启动镜像 / dtb | SD 卡启动分区 | 重启 | ❌ 第一期不做 (要现场); 第二期 u-boot bootcount A/B |

**机制**
- 卡上 `/pov/slotA`、`/pov/slotB` 两份完整组件 + `MANIFEST` (版本、每文件 sha256); `/pov/current` 指向在用槽位, `/pov/trial` 标记试运行。
- PC `povota push <包>` 经 WiFi 只写**非当前**槽位 → 板上逐文件校验 sha256 → 置 trial。
- 热切换: 停 pov_rxd → configfs 装新 PL → JTAG 灌新 GW5A → 起服务 → **自检窗口** (GP0 MAGIC、上行 link_up、vid 好帧计数在涨、PC 心跳) 全过才写 current 并清 trial; 任一不过或超时 ⇒ 自动装回旧槽位。
- 掉电保护: 开机脚本 (S95pov / up.sh) 看到 trial 未清 ⇒ 直接起旧槽位。升级中途断电最坏回到旧版本, 不会变砖。
- 转子在转时允许升级: 切换期间屏黑约 1~2 s, 电机不受影响。
- 安全: 第一期 sha256 + 预共享密钥校验包; 签名 (ed25519) 放第二期。

**排期 (约 2.5 天, 放在 D18–D19 之后, 依赖 1.1.5 WiFi / 1.1.7 远程状态 / 1.1.8 JTAG 灌 GW5A / 1.1.6 开机脚本)**
- X4a 槽位布局 + MANIFEST + PC 推送工具 (0.5 天)
- X4b 热切换 + 自检窗口 + 自动回滚 (1 天)
- X4c 开机时 trial 回退 (0.5 天)
- X4d 故障注入: 坏包 / 自检失败 / 切换中掉电 各 ≥5 次 (0.5 天)
⇒ 计划总工期 ≈ 25.5 个工作日 (原 20 + X1/X2 + X4)。

## 11. 10-10 实测带来的计划调整

- **D10 反过来**: DR1M90 (A35) 上 CPU lz4 解码 9.9 ms + 写合并拷贝 14.5 ms ≈ 25 ms/帧, PL 三引擎 71.7 ms/帧 ⇒ **CPU 路径是快路径**, PL 只用来省 CPU。原文"PL lz4 能上就上, CPU 先顶"对 M90 作废 (那条是 V90 的 cpy 162 ms 墙推出来的, M90 上墙不存在)。
- D4 单面通过 (三色循环 + 数字棋盘格); D6/D7 通过 (无人值守, 计数器判据); D5 双面与 D8 3-bit 画面待目视; D9 要电机。
