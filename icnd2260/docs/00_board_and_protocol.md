| 屏侧 J1 | 网名 | FPGA site | PACKAGE_PIN | 串/并元件 |
|---|---|---|---|---|

| J1.25 / J1.26 | CLK_P / CLK_N | IO_L8P/L8N_T1_33 | **AA21 / AB21** | R7 100Ω 跨接 |

| J1.22 | ACK (输入) | IO_L24N_T3_33 | **AB15** | R11 100Ω 串联 |
| — | EN_3V8 | IO_L19P_T3_33 | **V14** | R2 1k → U1.EN，R14 100k 下拉 |
| — | EN_2V8 | IO_L19N_T3_VREF_33 | **V15** | R13 1k → U2.EN，R15 100k 下拉 |

电源：两路 **BL8032** DCDC（3.3µH + 10µF×2），
`R1 39k / R3 10k → VCC_3V8`（0.8V×(1+3.9)=3.92V），
`R4 27k / R6 10k → VCC_2V8`（0.8V×(1+2.7)=2.96V）。
J1.1-5 = VCC_3V8，J1.16-20 = VCC_2V8，J1.7-14/41/42 = GND，P1.39/40 = +5V 输入。

**两个设计意图值得记下**：
1. **两路电源的 EN 都由 FPGA 控制，且带 100k 下拉** ⇒ 复位态电源是关的，
   固件必须主动开。顺带得到一个能力：**FPGA 可以给 2260 断电重启**
   （RSTN 没有引到连接器上，这是唯一的复位手段）。
2. **板子同时准备了 TTL 与 mini-LVDS 两条路**：差分对的 P 侧正好是芯片的
   `SDI_R1/G1/B1`（球 D1/E1/F1），N 侧是 `SDI_R2/G2/B2`；另有独立的单端 DCLK。
   ⇒ 同一块板既能跑 TTL（1/3/6 通道）也能跑 mini-LVDS（3 对 + CLK 对）。

## 3. 本版代码选 TTL 3 通道的理由

- 鹿小班 BANK 33 的 VCCO 是 **3.3V**，7 系列 HR bank 在 3.3V 下**出不了 LVDS_25**；
  板上又没有 LVDS 驱动器和共模网络 ⇒ mini-LVDS 这条路在这块板上走不通。
- 手册 §11 的寄存器默认表**本身就是 TTL-3 通道配置**（`0xb4[5:4]=10`、
  `0x06[9]=0`、`0x1a[9]=0`，已在 `tools/gen_reg_defaults.py` 里做成自检断言），
  首次点亮改动最小。
- TTL-3 通道要用的四根线 —— DCLK / I_SYNC / SDI_R1·G1·B1 —— 板上**全部接通**。
- 带宽够用：3 通道 × 25MHz × 双沿 = 150 Mbps，单颗一帧 92,160 bit ⇒ **1,628 fps**。

**⚠ 100Ω 跨接电阻的处理**：TTL 3 通道下 N 侧（SDI_R2/G2/B2）被芯片忽略，
但 R7~R10 把 P/N 跨接在一起。RTL 把 **N 侧驱动成与 P 侧同电平**，两端等电位 ⇒ 零电流。
若误驱动成反相，每根线 3.3V/100Ω = **33 mA**，远超 LVCMOS33 DRIVE 4。
CLK_P/CLK_N 同理，静态一起拉低。

## 4. 协议要点（TTL，编程指导 §3.1 / §5 / §12）

```
指令 = I_SYNC 拉低 → (≥16 DCLK 全 0) → 头部 → 载荷 → IDLE[127:0] 全 0 → I_SYNC 拉高 (≥8 DCLK)
DCLK 双沿, 1 个沿 = 1 bit, 最小单位 16 bit, 先发 MSB
SDI_R1 走命令/寄存器/图像; SDI_G1/B1 只走图像 (头部期间必须是 0)
```

| 指令 | 头部 | 载荷 |
|---|---|---|
| VSYNC | `RSYNC[23:0]=0x000d55` + `CMD=0011` + `DEVICE=0xF` | 无 |
| 写寄存器 | `RSYNC` + `CMD=0101(全部)/0110(指定)` + `DEVICE` + `OFFSET[7:0]` + `LENGTH[7:0]` | LENGTH+1 个 16bit |
| 读寄存器 | `RSYNC` + `CMD=1010` + `DEVICE` + `OFFSET` + `LENGTH` | 无，结果走 ACK |
| 显示数据 | `VHEAD[47:0]` = `0xA5A5` + 扫描行数-1 + `0x3`(16bit) + 级联数-1 + 前两项重复 | 逐颗 → 逐行 → 逐像素 |
| 校正数据 | `CHEAD` = `0xC3C3` + 同上 | 每通道 8bit |

3 通道数据排布：`SDI_R1: R#0 R#1 R#2 …` / `SDI_G1: G#0 G#1 …` / `SDI_B1: B#0 B#1 …`
（1/2/6 通道排布不同，见手册 §5 那张图）。

**上电流程（§12）**，已实现在 `icnd2260_seq.v`：
1. 整表（0x00..0xED，238 个）连发两次，其中 `0x00[3]=0`、`0x15[5]=0`
2. 64 帧全 0 显示数据，寄存器恢复常规值
3. 正常显示

## 5. 🔴 待确认项（会改设计的，按优先级）

**Q1 · 芯片 VDDD 从哪一路取？** J1 上只有 3.8V / 2.8V / GND，没有单独的数字电源。
LED 板（40×48）的图纸不在这个工程里。这决定两路电源的上电**顺序**
（现在按 2.8V 先、3.8V 后，`POWER_2V8_FIRST` 一个参数就能改）。
也决定 LVDS_EN / RSTN / SCL / SDA 在 LED 板上是怎么接的 —— 尤其
**LVDS_EN 必须为低**，否则芯片跑在 mini-LVDS 模式，TTL 数据全丢。

**Q2 · TTL 模式的 tSU / tHLD 是多少？** datasheet V1.7 只给了 mini-LVDS 的
`tSTU/tHLD = 1/4 tLVCP`。本设计按手册 §3.1 的字面描述做成**边沿对齐**
（一个位横跨「上升沿 → 下降沿」，芯片自己在位中间采样）。
若上板发现芯片是在 DCLK 沿上采样，把顶层 `DCLK_Q90` 置 1（DCLK 走 90° 相移）。
XDC 里的 ±1ns 是**偏斜约束不是芯片时序**，理由写在文件里。

**Q3 · 默认寄存器表下的帧频只有 ~763 fps。**
`0x00=0x3f3c` ⇒ 刷新分组数 64、倍率档 N=8；`0x01=0x0020` ⇒ Width_X=32
⇒ 灰度等级 G = 64 × 32 × 8 = **16,384**，
帧频 = GCLK/(G × 扫描数) ≤ 600M/(16384×48) = **763 fps**。
台面点亮够用，但离 POV 需要的 9,045 fps 差一个数量级 ⇒
**正式跑 POV 前必须重算 0x00/0x01 这组参数**（这正是发给厂家那份需求书 §7 Q5~Q6 问的事）。

**Q4 · ACK 回读没实现。** RTL 只把 ACK 的跳变点了个灯（LED[1]）。
读寄存器指令 (`CMD=1010`) 的解码器还没写 —— 手册 ACK 协议是脉宽编码
（w1>w2 = 1，w1<w2 = 0，5µs > w1+w2 > 1µs），要单独做一个解调器。
上板第一步「芯片到底有没有活」用回读寄存器验证是最硬的判据，值得早做。
