# mini-LVDS 上板清单（板子到之前先做完前两项）

分支 `feature/icnd2260-lvds`。目标：鹿小班 → 转接板 `zynq-lxb_2260_V0.1` → ICND2260，
走 **mini-LVDS 3 通道**。

---

## 0. 先做：把鹿小班 BANK 33 改成 2.5V（焊接活，等板子的时间正好够）

**为什么必须改**：7 系列 HR bank 在 VCCO=3.3V 下**没有** LVDS_25 输出，
板上也没有 LVDS 驱动器和共模网络。不改就出不了 LVDS。

**为什么改得动**：鹿小班上 **BANK 33 是唯一挂在 `VCCIO_ADJ` 上的 bank**——
逐脚核过原理图 P1 的 FPGA 电源引脚矩阵：

| bank | 供电网络 |
|---|---|
| VCCO_35 / VCCO_34 / VCCO_13 / VCCO_0 | `VCC3V3`（固定） |
| **VCCO_33**（= GPIO1 那 34 根 IO） | **`VCCIO_ADJ`** ✅ |

`VCCIO_ADJ` 由 **U6**（TPS563210 类，Vref 0.768V）产生，反馈分压 **R13(上) / R14(下)**：

```
现状: R13 = 33K, R14 = 10K  →  0.768 × (1 + 33/10) = 3.302 V   (网络名 PG_3V3 ✓ 对得上)
目标: R13 = 22.6K(1%), R14 = 10K 不动 → 0.768 × (1 + 2.26) = 2.503 V ✅
退路: R13 = 22K(5%) → 2.458 V, 仍在 LVDS_25 要求的 2.5V±5% (2.375~2.625) 内
```

⇒ **只换 R13 一颗电阻。** 改完先用万用表量 VCCIO_ADJ = 2.5V±0.1 再插板。

**改了以后的连带影响（XDC 里已经处理）**：同 bank 的单端信号全部变 **LVCMOS25**——
`I_SYNC` / `DCLK` / `ACK` / `EN_3V8` / `EN_2V8`。BANK 34/35 不受影响（LED、50M 晶振还是 3.3V）。

### 🔴 改之前要确认的两件事（我查不到，得看 LED 板）

1. **2260 的 VDDD 是多少？** datasheet 写 `VDDD: 2.8~3.8V`。
   - FPGA 用 2.5V 驱动 `I_SYNC`：若 VDDD=2.8V，VIH≈0.7×2.8=**1.96V** ⇒ 2.5V 有余量 ✅
     若 VDDD=3.8V，VIH≈**2.66V** ⇒ 2.5V **打不进去** ❌
   - `ACK_O` 是芯片输出、方向朝 FPGA：VDDD=3.8V 时 3.8V 灌进 2.5V 的 bank，
     串了 100Ω（R11）也会让钳位二极管吃 ~8mA ⇒ **不能直接接**。VDDD=2.8V 则无此问题。
   ⇒ **先量一下 LED 板上 2260 的 VDDD 接到哪一路**。若是 3.8V，`ACK` 那根先别接
     （代码里 ACK 只驱动 LED2，不接也能跑），`I_SYNC` 要加电平转换。

2. **LED 板上有没有自己的 100Ω 端接？** 转接板在连接器处已经跨接了 4 个 100Ω
   （R7~R10）。若 LED 板在 BGA 边上**也**有一组（我们自己那块 KiCad 面板
   `icnd2260_panel_v1` 就有 RT1~RT4，并注明「Zynq 侧不要再并端接电阻」），
   两组并联 = 50Ω，Vod 减半。⇒ **二选一，拆掉其中一组。**
   另注：datasheet 写数据链匹配是 **200Ω**(RDC)、模块链才是 100Ω(RBD)，
   转接板四对都用了 100Ω，这点也要一并问厂家。

```bash
# 综合到布线 + 时序 + DRC

```

顶层 `icnd2260_lxb_lvds_top` + 约束 `xdc/lxb_icnd2260_lvds_pins.xdc`。

### 首光前把这三个参数摆对

| 参数 | 首光值 | 说明 |
|---|---|---|
| `CLK_DIV` | **24** = 41.7MHz 位时钟（83 Mbps/对） | 通了再依次试 12（83MHz）、6（166.7MHz，手册上限）。**改了要同步改 XDC 里的 `BITCLK_NS`**（24.0 / 12.0 / 6.0） |
| 测试图 | `--mode single` | `python3 tools/gen_test_pattern.py --iface lvds --mode single` 只点一个像素，限流。通了换 `cross` 看方向、再 `gradient` |
| `VID_CRC` | 1 | 若怀疑 CRC 推断错了，置 0 二分排查（见下） |

### LVDS 版与 TTL 版的四个实质差别（每条都能单独把屏搞黑）

1. **VCCO 2.5V**（上面第 0 节）
2. **转发时钟 90° 移相**：mini-LVDS 的 `tSTU/tHLD = 1/4 tLVCP` ⇒ 芯片在**位中间**采样。
   TTL 版是边沿对齐，**要求正好相反**，两份 XDC 别混用。
   打不出来的备选：芯片自带采样相位调整（1/8、1/4、3/8 tLVCP，±0.7ns）。
3. **第一通道是 B 不是 R**：手册 §3 传输模式表「寄存器配置」列，TTL 走 `SDI_R1`，
   mini-LVDS 一律走 `D0IP/N`，而 D0 = `SDI_B1`（球 F1/F2）= **B 对**。
   第一通道除了发配置还独家发 VHEAD ⇒ 它必须是 tx 的 lane0。
   ⇒ 帧缓存字序换成 `{R,G,B}`（低 16 位 = B），用 `--iface lvds` 生成。
   **搞反了不报错，只是红蓝对调。**
4. **寄存器表要用 LVDS 版**：`icnd2260_regs_lvds.mem`（`0x06[9]=1`、`0x1a[9]=1`）。

## 2. 上电顺序与判据

复位后固件自己做：`EN_2V8` → 等 → `EN_3V8` → 等稳 → 开输出 → 位时钟空跑 →
整表×2（屏蔽 `0x00[3]`/`0x15[5]`）→ 64 帧全 0 → 正常显示。（手册 §12）

| 板载 LED | 含义 |
|---|---|
| LED1 (P20) 常亮 | 卡在上电/配置阶段，没进正常显示 |
| LED1 ~1.5Hz 闪 | 帧循环在跑 |
| LED2 (P21) 亮 | ACK 脚上出现过跳变 = **芯片有回话** |

**如果全黑，按这个顺序二分**（每次只动一个变量）：

1. 量 `VCCIO_ADJ` = 2.5V？量 J1 上的 3.8V / 2.8V 有没有上来（EN 是 FPGA 拉的，
   固件没跑起来电源就是关的）
2. 示波器/逻辑分析仪看 `CLK_P/N` 有没有波形、幅度多大（差分探头；
   Vod 应在 ±100~600mV 内、共模 1.1~1.3V）
3. `LVDS_EN` 脚在 LED 板上是不是拉高的（TTL/LVDS 靠这根切换，拉低就全丢）
4. 把 `CLK_DIV` 调到 24 甚至更慢
5. 翻转时钟相位（MMCM 的 `CLKOUT1_PHASE` 改 270°）
6. `VID_CRC=0` 关掉图像 CRC —— 若这样就亮了，说明 CRC 推断错了

## 3. 🔴 仿真过 ≠ 芯片认：三条推断项

代码里 TTL 与 LVDS 两套自校验测试台都过了（含独立重算 CRC 对拍），
但下面三条是**从手册图形/文字反推的，没有厂家书面确认**：

| # | 推断 | 依据 | 错了会怎样 |
|---|---|---|---|
| A | CHKSUM = CRC-16/CCITT，poly 0x1021，init 0xFFFF，高位先入，不反射不取反 | 手册 P13 的 LFSR 图（x^0 / x^5 / x^12 / x^15 标注） | 芯片丢包，全黑 |
| B | 图像数据每颗芯片末尾各追加一个 CHKSUM；多通道时每 lane 各算各的 | 「mLVDS 模式下每颗芯片接收的图像或校正数据最后需计算 CHECKSUM」 | 同上；`VID_CRC=0` 可二分 |
| C | 「第一组差分对」= D0 | §3 传输模式表的「寄存器配置」列 1/2/3 通道都写 D0IP/N | 配置发不进去 |

**上板第一件事**：发一条读寄存器指令（`CMD=1010`），拿 ACK 回包对一次 CRC。
对上了 A 和 B 就基本坐实。⚠ ACK 解调器**还没写**（手册 ACK 是脉宽编码：
`w1>w2` 为 1、`w1<w2` 为 0，`5µs > w1+w2 > 1µs`）——这是当前最该补的一块。
