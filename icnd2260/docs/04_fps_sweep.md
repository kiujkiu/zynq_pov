# 用鹿小班测 ICND2260 的帧率上限

这块板的立项目的（`hardware/pcb/icnd2260_panel_v1/docs/DESIGN_BASELINE.md`）是
**实测这颗芯片真实的帧率上限，目标 ≥9,000 fps**。本文说清楚要测什么、怎么测、
以及现有代码在哪一档就顶不住了。

---

## 0. 先分清两个"帧率"，它们的上限来自完全不同的地方

| | 谁决定 | 怎么算 | 谁来测 |
|---|---|---|---|
| **链路可发帧率** | FPGA 侧位时钟 | 位时钟 ÷ 每帧拍数 | 我们自己（VIO 读 `probe_in7`，片内 1 秒窗口数出来的） |
| **芯片显示帧率** | 2260 内部寄存器 | 帧频 = GCLK ÷ (灰度等级 × 扫描数) | 光电探头 / 相机，读不出来 |

**两者都要够 9,000 fps 才算达标**，任何一个不够就是瓶颈。下面分开算。

---

## 1. 链路侧：CLK_DIV 决定能发多快

每帧在位时钟域占多少拍（按当前 RTL 的实际结构算）：

```
显示指令 = IDLE(64) + VHEAD(48bit÷2) + 图像(40×48×16bit÷2) + CHKSUM(16÷2) + IDLE(64)
         = 64 + 24 + 15360 + 8 + 64                      = 15,520 拍
VSYNC 指令                                                =      64 拍
整表写 (每 64 帧一次, 4 沿/位)                             =   7,936 拍 → 摊 124 拍/帧
读探针 (每 16 帧一次)                                      =     320 拍 → 摊  20 拍/帧
────────────────────────────────────────────────────────────────────────
平均每帧                                                  ≈ 15,728 拍
```

| `CLK_DIV` | 位时钟 | 每对速率 | **可发帧率** | 用途 |
|---|---|---|---|---|
| 48 | 20.8 MHz | 41.7 Mbps | 1,325 fps | 最保守，`-slow` 变体 |
| **24** | 41.7 MHz | 83.3 Mbps | **2,649 fps** | **首光默认** |
| 12 | 83.3 MHz | 166.7 Mbps | 5,298 fps | 中间档 |
| 8 | 125.0 MHz | 250.0 Mbps | 7,948 fps | 还差一点 |
| **6** | 166.7 MHz | 333.3 Mbps | **10,597 fps** | 手册上限，**唯一能过 9,045 的档** |

⇒ **要验证 9,045 fps，最终必须跑到 `CLK_DIV=6`（手册标称的 mLVDS 上限）。**
24 和 12 只是上板阶梯，别拿它们的结果下结论。

（这个数跟 LED 板基线里的"每 lane 276.5 / 340 Mbps = 81%"是一致的口径。）

### 🔴 高速档的时序约束要跟着改

XDC 里的窗口是 `1/4 周期 − MARGIN`，而位时钟周期正好等于 `CLK_DIV` 纳秒：

| `CLK_DIV` | 周期 | tSTU/tHLD = 1/4 周期 | 减 1ns 余量后剩 |
|---|---|---|---|
| 24 | 24 ns | 6.00 ns | 5.00 ns |
| 12 | 12 ns | 3.00 ns | 2.00 ns |
| 8 | 8 ns | 2.00 ns | 1.00 ns |
| **6** | **6 ns** | **1.50 ns** | **0.50 ns** ⚠ |

⇒ 到 `CLK_DIV=8` 以上时，XDC 里的 `set MARGIN 1.0` 要往下调（0.3~0.5），
否则约束本身就把设计判死了 —— 那是约束太紧，不是设计不行。
**改 `CLK_DIV` 时永远要同步改 `BITCLK_NS`，高速档还要再看 `MARGIN`。**

## 2. 芯片侧：默认寄存器只有 763 fps，必须改

```
帧频 = GCLK / (灰度等级 G × 扫描数)
G    = (reg0x00[14:8]+1) × (reg0x01[12:0] × N),  N = 2^reg0x00[5:4] ∈ {1,2,4,8}
```

手册 §11 那份默认表算出来：

```
reg0x00 = 0x3f3c → 分组数 = 0x3f+1 = 64,  N = 8
reg0x01 = 0x0020 → Width_X = 32
G = 64 × 32 × 8 = 16,384
帧频 ≤ 600MHz / (16384 × 48) = 763 fps          ← 差一个数量级
```

LED 板基线用的工作点是 **分组数 16 × Width_X 55 = G 880（≈9.8 bit 灰度）+ GCLK 595MHz
→ 10,330 fps**。所以要测上限，**必须把 `0x00` / `0x01` 改掉**。

⚠ 手册要求 `reg0x00[14:8] ≥ 15`（分组数 ≥ 16），别往下压过头。
⚠ 灰度和帧率是直接对换的：`G` 减半，帧率翻倍，色深少一位。

## 3. 怎么扫（不用重出 bit）

用调试分支 `feature/icnd2260-lvds-debug` 的 bit：

```bash
cmd.exe /c "cd /d D:\claude_workspace\pov3d\zynq_pov\icnd2260 && \
  call C:\Xilinx\Vivado\2024.2\settings64.bat && \
  vivado -mode batch -source tools\build_bit_dbg.tcl"
# 产物 build_dbg/icnd2260_lvds_dbg.bit + .ltx
```

Vivado Hardware Manager 里烧 bit（**要同时指定 .ltx**，否则看不到探针），打开 `hw_vio_1`：

**读**
| 探针 | 含义 |
|---|---|
| **`probe_in7`** | **`fps` —— 片内 1 秒窗口直接数出来的实际发帧率，读到几就是几** |
| `probe_in0` | `frame_cnt` 累计帧数（要看长期有没有卡住用这个） |
| `probe_in1` | 状态位 `{locked, running, out_en, en3v8, en2v8, ack_ok_sticky, crc_ok, err, ph[3:0], sub[1:0]}` |
| `probe_in2` | ACK 回包里的 `Data0` —— **芯片真实返回的寄存器值** |
| `probe_in3` | ACK 回包头 `{ACK, DEVICE, OFFSET, LENGTH}` |
| `probe_in4` / `probe_in5` | 收到的 ACK 帧数 / 出错帧数 |

**写**
| 探针 | 含义 |
|---|---|
| `probe_out0` / `probe_out1` | 要改的寄存器地址 / 值 |
| `probe_out2` | 翻一下这一位 = 写一次（用的是"变化沿"，不是电平） |
| `probe_out3` / `probe_out4` | 读探针地址 / 使能（默认探 `0x00`） |
| `probe_out5` | 软复位，重跑整个上电流程（含电源 EN 关再开） |

⚠ **poke 完不会立刻生效**：寄存器表是在下一条整表写时才整体送进芯片的
（每 `REG_REFRESH_FR` 帧一次，默认 64 帧）。等一下再看。

### 建议的扫法

1. 先确认回读通了：`probe_out3 = 0x00` → `probe_in2` 应该等于 `0x3f3c`（或你刚 poke 的值）。
   **这一步过了，才说明后面读到的都算数。**
2. poke `0x00` 把分组数从 64 降到 16（`[14:8] = 15`），poke `0x01` 调 Width_X。
3. 每个点：读一次 `probe_in2` 确认芯片确实收到了（写进去 ≠ 生效），
   再用光电探头量屏侧的真实帧频。
4. 链路侧到顶了（`probe_in7` 的 fps 不再随寄存器变，且贴着第 1 节表里那一档的理论值）
   就往上抬 `CLK_DIV`，回到第 1 节的表。

⚠ `probe_in7` 量的是**我们发得多快**，不是屏亮得多快。两者要分别确认：
发得够快 + 芯片寄存器配得对，屏才可能到 9,000 fps。

---

## 4. 这套平台**测不了**的

- **芯片显示帧率本身**：读不出来，只能光学测量。FPGA 这边只能保证"喂得够快"。
- **多颗级联**：VHEAD 的级联字段做了，但数据量/时序没算过，也没验证过。
- **校正数据（CHEAD）对亮度均匀性的影响**：通路没接。
- **偏心双面 / 转速相关的一切**：这块是台面验证板，不转。
